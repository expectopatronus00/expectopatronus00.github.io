Loop Engineer 定义

Loop Engineer 到底是什么？是造新词吗

从 Prompt Engineer 到 Agent Engineer，再到今天的 Loop Engineer——AI 工程师的角色正在经历第三次范式跃迁。Loop Engineer 不再写提示词，而是设计反馈环、目标函数和评估指标，让系统在无人值守下自迭代。

01 · 从热词到工种

Loop Engineer 是新瓶装旧酒吗

2026 年 6 月，一条来自硅谷工程师的推文在中文 AI 圈刷屏：不要再亲自给 Coding Agent 写提示词了。随之而来的是 Loop Engineering（循环工程）这个新词。很多人第一反应是：这不就是换个说法的 Prompt Engineering？

答案是，也不是。它继承了 AI 工程化的核心逻辑，但对工程师的能力模型提出了完全不同的要求。这篇文章试图回答一个朴素的问题：Loop Engineer 到底是什么，以及为什么它在 2026 年这个节点突然变得重要。

Loop Engineer 不写提示词——他们设计让提示词自动流转、自动修正、自动达标的系统。

02 · 三阶段演进

从 Prompt 到 Agent 再到 Loop

AI 工程师的角色不是凭空冒出来的，它是沿着一条清晰的路线演进的。理解这条路线，才能看清 Loop Engineer 的位置。

2023—2024
Prompt Engineer 时代：人的角色是「提示词艺术家」。核心工作是写一条让模型输出准确结果的 Prompt，反复试错，直到结果可用。生产力上限 = 人的响应速度。
2025
Agent Engineer 时代：人退一步，只给目标，让 Agent 自己拆分步骤、调用工具、多步执行。核心工作从「写提示词」变成「设计工作流」。
2026—
Loop Engineer 时代：人再退一步，站在循环之外。核心工作是设计规则、设定目标函数、布置评估指标，让 Agent 在无人值守下自迭代、自反馈、自修正。

这不是一条线性替代路径，而是层叠关系：好的 Loop Engineer 必须懂 Prompt，也必须懂 Agent——只是他们把这些能力打包进了一个可自运转的系统。

03 · 核心职责

Loop Engineer 一天在做什么

如果说 Prompt Engineer 的产出物是一串文本，Agent Engineer 的产出物是一个工作流，那么 Loop Engineer 的产出物就是一条「闭合回路」。具体来说，他们的日常工作围绕三件事展开：

设计反馈环：谁（maker Agent）做决策，谁（checker Agent）做校验，校验不通过时如何回传错误信息，触发下一次迭代。这是 Loop 中最核心的结构。

定义目标函数：「完成任务」这句话太模糊。Loop Engineer 需要把目标翻译成机器可读的指标——代码是否通过测试、文档是否包含指定章节、输出是否符合预设格式。没有可量化的目标，就没有可运转的 Loop。

布置评估指标：Loop 不能无限跑。工程师需要设置停止条件、成本预算、迭代上限。这是避免「Agent 越跑越偏、Token 越烧越多」的关键护栏。

Loop 公式：定时器 + 决策器 + 反馈系统 + 安全护栏。四者缺一不可。

04 · 为什么是现在

2026 年是一个拐点

一个概念走红，从来不是因为它被发明了，而是因为它突然好用了。Loop Engineering 之所以在 2026 年中爆发，背后有几个可以被验证的前提。

第一，模型输出速度已经超过人类处理速度。当 Claude Code 或 Codex 可以在几秒钟内写完上百行代码、跑完测试、生成 PR 时，人反而成了瓶颈——你盯着屏幕等它输出，不如设置规则让它自己跑。

第二，长时域工作能力成熟。部分 Agent 支持无人值守运行数小时，这让「运行→检查→反馈→再运行」的闭环从理论上可行变成了实操上可落地。

第三，工具链生态已就绪。MCP 协议把真实世界（数据库、CI、工单、日志）与 Agent 连接起来，Loop 不再是在沙盒里打转，而是可以触碰真实生产环境。

05 · 不是人人都需要

谁应该成为 Loop Engineer

Loop Engineer 不是 AI 工程师的唯一正确答案，它更像一张「进阶门票」。如果你每天的工作仍然是：一次性需求、手工校验、小体量项目——那么 Prompt Engineering 对你来说可能仍然够用。

真正需要向 Loop 跃迁的场景，通常有三个特征：重复性高（每周都有同类需求）、可量化（能写出客观的通过/不通过规则）、体量足够大（人力参与的成本高于自动化投入的成本）。

换句话说，Loop Engineer 不替代任何人，它只是给某些 AI 工程师提供了一条把「自己的双手」换成「自己设计的系统」的路。这条路更寂寞，也更有杠杆效应。

06 · 写在最后

它不只是一个新词

回到最初的问题：Loop Engineer 是新瓶装旧酒吗？我的答案是——它装的酒，和 Prompt Engineering 用的是同一桶，但瓶子的形状完全不同了。

Prompt Engineer 用「手」做事，Agent Engineer 用「流程」做事，Loop Engineer 用「规则」做事。这三者不是替代关系，而是同一个人在不同阶段、处理不同体量问题时，会自然切换的三种工作模式。

如果你想在 AI 工程这条路上继续走下去，Loop 不是一个可选项，而是接下来半年你大概率会被要求理解并使用的一种基本能力。它不需要你推翻过去学到的一切，但它要求你多问自己一句：这件事，我能不能让它自己跑？

AI 工程师的下一个护城河，不是「我会写更好的 Prompt」，而是「我能设计一套让 Prompt 自我优化的规则」。
