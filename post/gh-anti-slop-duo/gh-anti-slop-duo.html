69,283 星对 61,245 星：两份自测都没写通过

69,283 星对 61,245 星，两个 MIT 仓库的核心产物各只有一份 SKILL.md。前者 32,394 字节列 26 条模式做文字减法，后者 7,201 字节用 10 条规则改回答顺序；两份自测都没写「通过」。

01 · 这件事

两个六万星仓库，卖的都是一份提示词

两个六万星级的仓库，核心交付物都只是一份 Markdown 规则文件。blader/humanizer 与 ayghri/i-have-adhd 同为 MIT、主语言都标 Python，前者把 AI 腔从文字里删掉，后者把答案挪到回答第一行。

核对日 2026-11-15，humanizer 有 69,283 星、5,447 fork、4 个未结，建于 2026-01-18，最近推送 11-10。i-have-adhd 有 61,245 星、3,590 fork、102 个未结，建于 2026-05-13，最近推送 10-19。

两家的 updated_at 都是今天，星数仍在增长；但 pushed_at 分别停在 11-10 和 10-19，后者已近一个月没有新提交。热度跑在工程前面，是这两个仓库的共同形状。

所以这不是软件选型，是两套写作约定的选型。一个重 32 KB、一个只有 7 KB，星数却几乎持平，差距全在「规则之外还打包了什么」。

02 · 核心机制

26 条模式做减法，10 条规则改顺序

一个改文字的措辞，一个改回答的结构，两者根本不在同一层。humanizer 依据维基百科「Signs of AI writing」，把 AI 痕迹编成 26 条模式、分 A 到 F 六组，按强度与出现频率排序，前五条一见就改。

模式从「不是 X 而是 Y」、单行收尾，到强行三连词、满篇破折号、加粗装饰，再到聊天残留和「复述读者已知的背景」。/humanizer 先标注痕迹、起草改写、核对事实，最后写定稿；文件模式下只改散文，不动代码、数据与链接。

i-have-adhd 只有 10 条规则，全部指向「读者下一步做什么」：首行给动作、多步编号、结尾只留一个两分钟内能做的动作、每轮复述状态、列表最多五项、禁开场白与「Hope this helps」。

后者还写了「何时破例」：调试三轮没进展就停手、规则与宿主系统提示冲突时让系统提示赢。规则集自己承认会被上游覆盖，比声称「装上就生效」诚实。

04 · 怎么用

装得上不等于生效，两个 skill 都要宿主主动调用

安装路径铺到 15 个宿主，规则能不能落地却取决于 agent 会不会去读那份文件。humanizer 在 Claude Code 里要求 2.1.142 以上，用两条 /plugin 命令装。

旧版本、Codex、pi、Copilot 走 npx skills 或 pi install，装完用 /humanizer 调用。两个仓库都没有可执行主程序，全靠宿主把 SKILL.md 塞进上下文。

i-have-adhd 的 SKILL.md frontmatter 写着 disable-model-invocation: true，即模型不会自动触发，必须由人输入 /i-have-adhd。一旦开启，规则持续到整场会话结束，读者说「stop adhd mode」才关掉。

把体积摊开看更直观：i-have-adhd 的 INSTALL.md 单份 27,516 字节，是规则文件的 3.8 倍；.github/ 是规则文件的 40 倍。让十几种宿主都认同一份规则，比写出这十条规则贵得多。

  • 两个仓库都不含可执行主程序，规则靠宿主把 SKILL.md 塞进上下文
  • humanizer 的文件模式只改散文，代码、frontmatter、链接目标保持原样
  • i-have-adhd 另配 hooks 与 tests，是唯一带自动校验的一方
  • README 顶部由 cfo.ai 赞助，humanizer 在 skills.sh 上另有安装量入口
05 · 冷思考

两份自测，一份没过检测器，一份没过发布门

最该打折读的是两份自述里的「已验证」：数字都成立，结论却被同一份文件否定。humanizer README 写「盲测 16 次全胜」，指向已关闭的 #229；原文同时给出检测率从 100% 到 98.6% 再到 97.8%，Pangram 4.0 对四个变体仍判 100% AI。

#229 的实测项结果
盲评偏好改写（对比原始输出）16 / 16
检测率：原始 / 改写 / 加检查器100% → 98.6% → 97.8%
真人文本被判为人类143 / 143
「写得更像人」提示词骗过评委0 / 17
计划 144 场配对，实际完成77 场

更值得注意的是反向发现：改写后 AI 词汇与排版痕迹从 70、60 降到 0，节奏整齐度却从 60 升到 101，格言式收尾从 38 升到 61。减法式改写把词汇痕迹换成了节奏痕迹，报告者据此说「整齐本身就是一种痕迹」。

版本口径也在动。CHANGELOG 列了 28 个版本号，tag 与 Release 各只有 7 个；模式数先从 33 涨到 35，3.0.0 合并成 25，3.1.0 又添回第 26 条。v4.0.0 更反转了 2.9.0 的「不许加事实」，允许补一个已知为真的细节。

而 README 首句仍是「不改它说什么」。「保持原意」的边界被版本悄悄挪过一次；对要放进合同、文档或财报的文字，这不是措辞问题，是要先确认装的是哪一版。

i-have-adhd 把结果写得更直白：文件里有一节标题就是 Release gate: FAILED。它承认一个用例因 runner 传 --tools ""，任何回答都过不了。

另一例 partial-success 是唯一持续回归（−0.63）。报告猜是第 8 条「先报原因再报修法」逼模型在没证据时编了一个原因。

  • 三次试验、评委与生成同属一个模型家族，两者都写进了限制说明
  • 84 行结果里有 3 行把工具调用语法写成纯文本，基线与候选都受影响
  • humanizer 的盲测评委也全是同一家族语言模型，人类对照未匹配主题
  • 102 个未结里 69 个是 PR，v0.4.1 发布说明一次致谢 50 位新贡献者

AGENTS.md 还规定 agent 只能在带 AI Agora 标签的 issue 下评论，且不得评论别人的 PR。一个规范 AI 输出的仓库，连 AI 的发言权都写成了规则——这比评测分数更能说明它对「模型会自作主张」的预期。

判断落到用法上：这两个仓库值得抄的是把「什么算坏输出」写成可逐条检查的清单，不是 16/16 或 +0.427。它们各自把验收的漏洞一并留在仓库里，反倒比一个漂亮分数更可信。
