24,497 星、219 个技能：16 个插件指向别家仓库

Google 官方 skills 仓 24,497 星、219 个技能，三处清单完全对齐。但 17 个插件里只有 1 个在本仓，另 16 个是指向外部仓库的指针；README 说欢迎贡献，贡献指南却拒收外部 PR。

01 这件事

Google 把自家产品的操作知识做成了 Agent Skills 开源仓：技能本体全在这个仓库，插件却另走一条线。README 的定位只有一句——面向 Google 产品与技术的 Agent Skills，包括 Google Cloud。

截至 2026-11-21，google/skills 有 24,497 星、2,030 fork，2026-03-31 创建，主语言 Python，Apache-2.0。仓库的 releases/latest 接口返回 404：它一次 Release 都没发过。

一眼看去，这是一份技能目录：README 用一张长清单列出从云认证到广告的全部产品线。但仓库里躺着两套东西——skills/ 下是 219 份技能文本，plugins/ 下是 16 个 git submodule，指向 GoogleCloudPlatform 组织下各自独立的仓库。两者用不同命令安装，也不在同一层维护。

README 顶部挂了 skills.sh 的一键安装徽章，技能格式遵循 agentskills.io 的社区规范。换句话说，它产出的是可被多种 agent harness 读取的 SKILL.md 文件，不是绑死在某个 IDE 上的插件。这也是它能同时被 Claude Code、Codex 与 Antigravity CLI 安装的底层原因。

入池时雷达给它 83 分，归入 official-skills 族。九天后星标仍在涨，推送日期就是今天。这是一个持续维护的官方索引仓，不是一阵风的榜单项目。

02 核心机制

219 这个数字在三个地方完全一致：README 清单、index.json、skills/ 目录下的 SKILL.md。说明它是脚本统一生成和校验的，不是手数出来的宣传数。

README 把 219 个技能分成 13 类，覆盖从云认证、基础设施到广告与分析的全部产品面。

13 类里，Infrastructure 一类就占 54 个，大多是 GKE 集群、TPU 故障排查、Cloud Storage 桶配置这类具体运维场景；Advertising 有 15 个，对应 Google Ads 与广告投放；Security and identity 有 24 个。它们不是产品宣传页，而是写给 agent 执行的操作步骤。

index.json 顶部只有一句 "This file is generated. Do not edit it by hand."，219 条记录每条带 name 与 description。描述写明了触发条件，决定技能会不会被正确唤起。

以 agent-platform-access-audit 为例：要求 agent 通过 BigQuery 查 Cloud Audit Logs，审计它访问了哪些资源、以什么身份操作，用在排查 PERMISSION_DENIED 或判断 VPC Service Controls 边界时。

这类描述决定了技能会不会被正确唤起。磁盘上 skills/ 分 ads、analytics、cloud、developers、identity、platform-devices 六个领域目录，219 份 SKILL.md 与清单逐一对齐。六个目录是物理结构，13 个分类是给人读的展示层，同一批技能按两套维度切分。

技能用 skills CLI 安装：npx skills add google/skills 一次装完，按提示选具体技能或全部、目标 agent、项目或全局作用域；更新走 npx skills update，附带选项可移除已废弃的技能。环境里没有 npx，README 让先装 Node.js。

03 关键细节与数据

17 个插件里，只有 1 个本体在这个仓库，另外 16 个都是指向 GoogleCloudPlatform 名下独立仓库的指针。插件是「Skills + MCP servers」组合，和纯 Markdown 技能不是一种东西。

.gitmodules 正好 16 条，每条把外部仓钉到一个分支或 tag。google-cloud-storage 是 3.0.1，firestore-native 是 0.3.4，oracledb 是 0.2.7，looker 是 0.3.11，knowledge-catalog 是 0.5.4。本仓存的是地址与版本号，不是插件内容。

唯一例外是 db-context-engineering：它用 git-subdir 类型，指向外部仓的 plugin 子目录而不是仓库根，ref 是 v0.7.2。这也是 17 个插件里唯一不走标准 github 顶层引用的外部条目。

marketplace.json 的 metadata.version 停在 0.0.1，metadata 把仓库描述成「官方技能与规范化插件的中心仓库」。完整 git tree 里共 225 份 SKILL.md：219 份在 skills/，只有 6 份落在 plugins/。真正的技能文本仍在各自的产品插件仓里。

16 个外部插件的产品分布也偏数据侧：alloydb、bigquery、bigtable、cloud-sql 三款、dataproc、firestore、spanner、looker、oracledb 都是数据库与分析产品，其余是存储、知识目录与数据 agent kit。这份插件清单解决的是「怎么把数据产品接进 agent」，不是通用编程辅助。

04 怎么用

技能和插件走两套命令，混用会拿不到对应的东西。前者用 skills CLI，后者要走各 harness 的 marketplace；演示里的 <plugin> 要换成实际插件名。

  1. npx skills add google/skills 安装技能，按提示选技能、目标 agent 与作用域
  2. npx skills update 更新，附带选项可移除已废弃的技能
  3. 插件另装：先加 marketplace，再从列表里挑具体插件
  4. 需要单独安装时，用 harness 对应的插件路径或仓库链接
Harness安装路径
Claude Codeclaude plugin marketplace add google/skills，再 claude plugin install <plugin>@google-plugins
Codexcodex plugin marketplace add google/skills，再从 /plugins 浏览器安装
Antigravity CLIagy plugin install https://github.com/google/skills/<plugin-path>

三套命令的差别在入口：Claude Code 与 Codex 都先把 google/skills 注册成 marketplace，再按名字挑插件；Antigravity CLI 直接吃仓库路径，跳过 marketplace 这一步。装技能时选 project 或 global 作用域，决定它是跟着当前项目走，还是对所有项目生效。

README 还列了 7 个「Additional Google skills」外部仓：Android、Dart、Flutter、Google Maps Platform、ADK、Firestore 与 Cloud Storage。这些连指针都不是，只给一个链接，需要自己进对方仓库安装。

附加仓与插件的区别值得说清：7 个附加仓没有被 .gitmodules 收进本仓，也没有固定版本，更新与否取决于各自仓库。插件则钉住了 ref，装下来的内容可复现。想要稳定版本，走 marketplace；想追最新，才去附加仓。

05 冷思考

README 正文写着「欢迎贡献」，CONTRIBUTING.md 却明确「不接受外部 PR 和代码贡献」——这不是笔误，是两处并存的口径。前者让读者报 bug、提新技能、fork 去 remix；后者把口子收紧到只收 issue。

贡献指南给的理由是保证技术准确、安全与架构对齐，所有技能必须经过 Google 团队内部审核。README 正文同时写了一版贡献说明，两处措辞方向相反。只读 README 的人会以为可以提 PR，点开贡献指南才发现口子只留了 issue。

对一个官方文档型的仓，这个姿态可以理解：它能保证口径统一，代价是社区修不了一个写错的 SDK 例子。贡献者能做的只是开 issue 提醒，等内部团队排期改；fork 出去自己改，则脱离了官方更新链。

未结条目的构成也印证了这个姿态：42 个未结里，41 个是 issue，只有 1 个是 PR。拒收外部代码，issue 就成了唯一的反馈通道。想贡献的人被引导去开 issue 或 fork，官方则用内部审核换口径一致，这是一个明确的取舍，不是疏漏。

插件全钉在 0.x，marketplace 版本 0.0.1，一次 Release 没发。dataproc 是 0.1.0，alloydb 是 0.2.0，oracledb 是 0.2.7。0.x 意味着上游接口随时可能变，本仓的 pin 既是稳定器，也是滞后器：16 个子模块任一上游改了 tag，这里都得同步更新。

覆盖面上，219 个技能里 Infrastructure 54、AI/ML 32、Databases 26、Security 24，四项合计 136 个，约六成是 Google Cloud 的运维与架构知识。要学通用编码或前端，这里能给的不多；它更像一份按产品切分的操作手册索引。

我的判断是：把它当 Google 产品的操作手册索引，按领域查；别当通用技能集市，也别指望发现错误能提 PR 修——那个入口从设计上就没开。
