1.5 万星、11 个 agent：审批权交回浏览器

agent 交出计划，浏览器开给你批；批准放行，驳回把意见送回。Plannotator 把人放回审批环，15,216 星、36 个发布资产。但 Release 停在 v0.29.4、源码已到 0.29.5，边界得自己守。

01 这件事

Plannotator 把「批准还是驳回」做成本地浏览器里的一层审批面，但它接得进多少 agent，和安装器能配好多少，是两件事。

截至 2026-11-27，backnotprop/plannotator 有 15,216 星、1,456 fork，2025-12-28 建库，11-26 仍有推送，TypeScript。未结条目 230 个，用分项检索拆成 138 个 issue 与 92 个 PR。它挂在编码 agent 的钩子上，把计划和 diff 拦到浏览器里给你看。

02 核心机制

整个机制的开关只有一处：agent 调用 ExitPlanMode，PermissionRequest 钩子触发，本地服务接手。

计划审查不需要命令。agent 一提出计划，浏览器就打开标注页；你批准，它继续；你驳回，结构化意见回传给 agent，它改完再出一份 plan diff。这个来回才是它真正的卖点，而不是标注本身。

  1. 触发：agent 调用 ExitPlanMode，钩子截住。
  2. 读取：本地服务从钩子输入里读出计划。
  3. 审查：浏览器开标注页，你批注、批准或驳回。
  4. 回传：批准则放行，驳回则把反馈送回。
  5. 修订：agent 改完，plan diff 显示改了什么。

代码审查是另一条入口。/plannotator-review 抓本地 git diff，或按 URL 拉 GitHub PR、GitLab MR；你在页面上逐行评论、暂存文件，反馈回到原会话。它对接 Git、GitButler、Jujutsu 和 Perforce。

第三个面是 Inbox：plannotator inbox 开一个本地窗口，agent 把问题、文件、引导式审查留在里面；你点一下回答，回复作为下一轮送回原会话，不会占着 agent 等。

03 关键细节与数据

三处数字对不齐：Release 与源码版本、安装表与目录、GitHub 许可字段与 README，各差一层。

Latest Release 是 v0.29.4，11-25 发布、36 个资产，覆盖 macOS、Linux、Windows 的 x64 与 arm64；但 package.json 写的是 0.29.5。安装器从 Releases 拉二进制，源码构建走另一个版本号，升级时要看清装的是哪一层。

04 怎么用

安装器会配置大部分 agent，但每个宿主收尾动作不同，Pi 甚至要求跳过安装器。

一条命令装全套：macOS、Linux、WSL 用 curl -fsSL https://plannotator.ai/install.sh | bash，Windows 用 irm … | iex。它自动探测已装 agent，写钩子、技能和斜杠命令。

只要二进制就加 --minimal，装到 ~/.local/bin，跳过所有技能、钩子和配置。Claude Code 2.1.287 起，审查不再让 agent 干等：它结束回合，你的决定晚点作为消息送达；设 PLANNOTATOR_CLAUDE_MOD=0 可退回旧流程。

远程场景要手动：SSH 会自动切到固定端口 19432，devcontainer 或 Docker 里设 PLANNOTATOR_REMOTE=1 并转发端口。设置存在 cookie 而非 localStorage，因为每次钩子调用端口随机。

05 冷思考

它的设计明确把「别添堵」放在防御前面，这正是边界问题该被单独拿出来的原因。

远程模式下服务监听 0.0.0.0 且无登录：README 原文说，任何能连到端口的人都能用，哪怕你走了 SSH 隧道。安全边界等于「别把端口开给不信任的网络」，工具自己不守这道门。

分享也一样。小内容塞进链接本身，大的加密后上传、7 天过期；拿到完整链接的人都能读。关掉要设 PLANNOTATOR_SHARE=disabled。安装校验同样默认关闭，要加 --verify-attestation 或写进配置才启用。

AGENTS.md 把态度写得更直白：它是开源产品，不是企业关键系统，不要为了防御加确认、警告和门槛。230 个未结里 92 个是 PR，说明还在活跃收补丁；但 0.x 版本号、一天一版的节奏，意味着升级本身就是成本。

它是把人放回审批环里的一层，而不是替你把边界守住的那一层。单人本地用，默认值够顺手；多人、远程或要过合规，就得先把端口、分享和校验这三项自己配好。
