讲透 Loop Engineering，AI 工程的下一层

最近 AI 圈又在集体换口号了。一个叫 Loop Engineering 的新词，被越来越多人挂在嘴边。但它到底是又一次概念炒作，还是 AI 工程真的进入了一个新阶段？本文试图把这件事讲清楚。

01 · 口号的变迁

从 Prompt Engineering 到 Loop Engineering

如果把 AI 工程的演进画成一条线，大概是这样的：早期我们在调参数——调整模型权重、调 batch size、调学习率。然后 Prompt Engineering 登场，大家开始调提示词——把任务描述得越巧妙，模型输出就越好。

现在进入了第三阶段：Loop Engineering —— 不再纠结单次提示词写得好不好，而是关注 Agent 的整个工作流程：它如何循环调用工具、如何自我检查、如何在出错时自动纠错。

三代 AI 工程范式对比：
L1 · Model
调模型参数、fine-tuning。人做的是机器的工作。需要大量数据 + GPU，门槛很高。
L2 · Prompt
调提示词。人做的是翻译官的工作——把人类意图翻译成模型能理解的语言。门槛低，但上限也低。
L3 · Loop
设计循环工作流。人做的是架构师的工作——设定目标、提供工具、定义退出条件。模型自己在循环中完成剩下的。
02 · 定义 Loop Engineering

它到底指什么？

定义越清晰越能避免炒作。我对 Loop Engineering 的理解是：

Loop Engineering 的工程定义：
以目标为输入，以循环为执行单元，以工具调用为操作手段，以条件满足为退出机制的一套 Agent 工作流设计方法。它强调 Agent 的自主运行能力、自我评估能力和自动迭代能力。

Loop Engineering 不是一个具体的库或框架，它是一种思维方式：你在设计 Agent 时，不应该关心"这一次模型说什么"，而是关心"这个循环是否每次都能收敛到正确答案"。

一个好 Loop 的四个特征

可观测
每次循环的输入输出、中间状态都应该可记录、可回溯。不能是黑箱。
可中断
必须有明确的退出条件。无论是成功退出（达到目标）还是失败退出（达到最大尝试次数）。
可修复
循环应该能从自己的错误中恢复。常见模式：失败 → 分析错误 → 调整策略 → 重试。
可收敛
每次循环应该离目标更近。如果循环在原地打转，这是 Loop 设计失败的明确信号。
03 · 炒作 vs. 真实

它是泡沫还是真的进化？

实话实说：目前 70% 自称"Loop Engineering"的内容都是旧酒装新瓶。把以前的"多步提示"改个名字并不能称为 Loop Engineering。

但这不代表整个概念是泡沫。以下几个信号是真实的、不可忽视的：

三个不可忽视的真实信号：
1. HeyGen 等公司内部全面转向 Loop —— 他们不是在博客里写"我用了 Loop"，而是在生产环境用 Loop 模式跑实际业务流程。
2. Cursor / Claude Code 的功能演进 —— 从"代码补全"到"整个项目级重构"，再到"自动跑测试并修复"。工具的演进方向非常一致。
3. Agent 框架的成熟 —— 从 LangGraph 到各种 Workflow 工具，生态在快速补齐，从"玩具级"走向"生产可用级"。
04 · 你的位置

作为个体工程师，这意味着什么

如果你还没接触 Loop Engineering，不必焦虑，但也不能忽视。它短期内不会让你失业，但长期来看，会让不掌握它的人效率显著落后。

给你一个具体的建议：在你每天的工作中，挑一件你反复做的小事 —— 比如"跑测试 → 看报错 → 修复 → 再跑"这个循环 —— 试着让 Agent 帮你做一次。感受一下这个闭环跑通时的震撼。

"Loop Engineering 真正的价值，不是让模型替你写更多代码，而是让模型替你承担那些重复的、需要耐心的流程性工作。"
