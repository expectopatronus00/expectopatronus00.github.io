3115星画地图、19335星逆向、2017星一句话：读懂分三层

19,335 星、3,637 fork——craft-anything 最重；floorplan 3,115 星，stack-diagram 2,017 星。三个 10 月底扎堆建库，却分管读代码库、逆向复刻、一句话出图：按粒度选。

01 · 这件事

三个都在 10 月底扎堆建库，都叫「让 agent 先读懂再动手」

haydenschmitty/floorplan 2026 年 10 月 27 日建库，11 月 7 日核对时 3,115 星、238 fork、7 个订阅者、56 个未关闭 issue，MIT，JavaScript，6,159 KB，最后 push 在 11 月 2 日。description 写：See how your app actually fits together. An interactive, plain-English map of your codebase, drawn by Claude or Codex.——让 Claude 或 Codex 读代码库，画一张能点开、用大白话标注的地图。

storytold/craft-anything 10 月 31 日建库，19,335 星、3,637 fork、92 个订阅者、213 个未关闭 issue，API 的 license 是 Apache-2.0，Rust，9,752 KB，11 月 7 日核对当天还在 push。description 是 Craft Anything: understand how any software works, and craft your own.，README 称它为纯 Rust 的 clean-room 引擎：先研究软件怎么工作，再让 AI 造一个你自己的版本。

caru-ini/stack-diagram 11 月 1 日建库，2,017 星、93 fork、3 个订阅者、0 个未关闭 issue，MIT，TypeScript，3,461 KB，最后 push 在 11 月 3 日。description 更短：Agent skill: describe your stack in a sentence, get an architecture diagram with official logos——一句话描述技术栈，换一张带官方 logo 的架构图，是三者里唯一在 description 里写明自己是 agent skill 的。

三个仓库挤在 10 月 27 日到 11 月 1 日这六天里先后出现，都挂在「让 agent 先读懂代码库再动手」这条线上，同属一族，所以这篇横评三个仓库的数字各自独立核过。但「读懂」在三个仓库里根本不是同一件事：一个读你自己的整个代码库，一个读别人软件的外在行为，一个连代码库都不读、只解析一句话。下面按粒度拆，最后给判断表。

02 · 核心机制

一个读实现，一个读行为并重建，一个只读一句话里的名词

floorplan 读的是你自己的仓库。装成 Claude Code 或 Codex 的 plugin 后，agent 用你已有的账号读文件、跟着 imports 走，把前端每条 web request 匹配到回答它的后端 endpoint，跨 repo 也追，再把每个 part、file、request 换成 plain-English 名字——README 的例子是「Takes card payments at checkout」而不是「Stripe API wrapper」。产物是一张能缩到某个文件、端点的地图，附带 Health check（代码里的密钥、敞开的 Supabase 表、Firebase 规则、可伪造的 Stripe webhook、无登录端点）和 Recent work。它读懂的是「这个 app 此刻实际怎么拼起来」，静态实现级。

README 的 How it works 画得直白：agent 扫完 → build → floorplan/index.html 在浏览器打开。它只写自己的 floorplan/ 文件夹（含 architecture.json、descriptions/，自己改的每次更新都保留），在 Claude Code 里若你同意再往 CLAUDE.local.md 加一小段。关键是那句「Neither is committed」：文件夹不提交，它还明说不改变你的代码、.gitignore 或 CLAUDE.md。作者把产物主动挡在了版本库外面。

craft-anything 读的是「另一个软件」。它把网站、app、游戏或文件交给一套纯 Rust 逆向引擎，README 说有 320 个工具（300 个在引擎里，其余来自 AI 与 setup 层），每个同时是 CLI 子命令和 MCP 工具，研究这步甚至标着「No AI is needed to inspect」。四步 Study → Build → Check → Ready：先研究原作，再让本机已登录的 coding agent 按你点名的语言、框架或引擎 build 一个新项目，Check 拿结果和原作比（网页三档屏宽、游戏自检、app 运行），没对上的继续 refine。它读懂的是「这个软件看起来、跑起来是什么样」，行为级。

Clean room 是默认模式：README 写明「nothing inside the original is read, not its code, files or page source」，工具只从可见的东西工作——截图、可见文本、量出来的布局、颜色、字体、间距、展开的菜单；会往里看的工具直接被拒。Deep 才读代码和 JS、装了 Ghidra 就一起上。它「读懂」得最像逆向，却恰恰被规则禁止读源码——为的是让产出算作你自己的实现。产物落在新项目文件夹：craft.json、capture/、app/（生成的项目）、checks/、inbox/，默认在 Documents/Craft Anything 下。

stack-diagram 连「读」都省了。它吃一句自然语言——示例是 Diagram our stack: Next.js and a Hono API on Vercel. Postgres on Neon, auth with Clerk, payments with Stripe. GitHub Actions deploys.——把话里的技术栈名词拆成节点和连线，按 svgl、devicon、gilbarbara/logos 到品牌自己仓库的次序取官方 logo，AWS、Google Cloud、Azure 用各家图标包，渲染成 light / dark 两套主题。它读懂的不是代码库，是那句话里的名词。产物 README 写得很具体：「one HTML file with its fonts and logos inlined」，断网也能渲染，能发成 artifact、也能「drop it into a repo or wiki」。三者摆成一条轴：A 读实现、B 读行为、C 读名词；进版本库的分别是「不提交的地图」「要提交的新代码」「能提交的一张图」。

19,335 星对 3,115 星对 2,017 星，量出来的不是同一把尺子

把三组硬数字摊平。floorplan：3,115 星、238 fork、56 个未关闭 issue、7 个订阅者、10 月 27 日建库、11 月 2 日最后 push、MIT、JavaScript、size 6,159 KB，README 20,731 字节，根目录带 .claude-plugin/、.codex-plugin/、skills/、docs/、tools/，一份 22,134 字节的 CHANGELOG.md；徽章写 version 0.6.3、Node 18+、zero dependencies。

craft-anything：19,335 星、3,637 fork、213 个未关闭 issue、92 个订阅者、10 月 31 日建库、11 月 7 日核对当天 11:13 还在 push、Rust、size 9,752 KB，README 27,195 字节，另配 8 种语言版本（含 23,620 字节的 README.zh.md），根目录是 Cargo.toml、205,281 字节的 Cargo.lock、crates/、apps/、vendor/ 这一套 Rust 工程，挂在组织账号 storytold 下，产品名 ArtCraft，README 自标 Status: early alpha。

stack-diagram：2,017 星、93 fork、0 个未关闭 issue、3 个订阅者、11 月 1 日建库、11 月 3 日最后 push、MIT、TypeScript、size 3,461 KB，README 8,333 字节，根目录 skills/、site/、docs/ 加一份 1,065 字节的 LICENSE。一个 19,335 星、带 20 万字节锁文件的 Rust 工程，对上一个 2,017 星、README 不到它三分之一的 skill。

许可要单独拎出来：floorplan 和 stack-diagram 是干净 MIT；craft-anything 的 API license 给 Apache-2.0，README 徽章却写 MIT OR Apache-2.0，根目录并存放 10,174 字节的 LICENSE-APACHE、1,106 字节的 LICENSE-MIT 和 1,767 字节的 NOTICE，是双许可不是笔误，引用得注明取自哪个文件。三条在选题池里各带积压评分与榜单数字，但那些都不是 api.github.com 字段，正文里每个数值都只取自 2026-11-07 这次独立核对，星标实时变化，以仓库当前数据为准。

04 · 怎么用

按你手上是有代码库、有产品要复刻，还是只有一句话来选

三者前提不同。floorplan 要 Node.js 18+ 加 Claude Code 或 Codex，装法 claude plugin marketplace add haydenschmitty/floorplan 再 claude plugin install floorplan@floorplan，Codex 侧是 codex plugin marketplace add haydenschmitty/floorplan 与 codex plugin add floorplan@floorplan；开新会话说 Make me a floorplan of this app. 或敲 $floorplan，改完代码用 Update the floorplan. 刷新。它没有 hooks、没有 MCP server、零依赖、不下载也不跑网上的代码，只多出一个本地文件夹。

craft-anything 要 Rust 1.97+：git clone https://github.com/storytold/craft-anything && cd craft-anything、cargo run --release -p craft-anything 起桌面 app，cargo install --path apps/craft-anything-cli 装 CLI，craft-anything-cli doctor 体检；复刻是 craft-anything-cli rebuild https://example.com "Recreate this website"，只给一句话也行：craft-anything-cli rebuild - "A snake game in Rust" --rounds 1。它还得有一个已在本机登录的 coding agent，Claude Code 首选，Codex 适配器 README 明说未在真实安装验证，安装包状态是 alpha。

stack-diagram 最轻，一条 npx skills add caru-ini/stack-diagram，Claude 系应用也可从 Releases 下 stack-diagram.zip 当 skill 上传，支持 Claude Code、Codex、Cursor 等。它不要你交出任何代码库。判断表如下，A 是 floorplan，B 是 craft-anything，C 是 stack-diagram：

  • 要搞懂、交接或体检自己手里的代码库，看清 AI 改了哪几处、哪里有风险——选 A。读 imports、把前端请求对到后端端点、跨 repo 也追，还带 Health check；代价是产物 floorplan/ 被设计成不提交，换机器得重画。
  • 要照着别人的网站 / app / 游戏做出一份自己的可运行实现——选 B。app/ 就是生成的新项目，三者里唯一把代码当产物；代价是 Rust 1.97+、本机登录 agent、early alpha，以及提交前确认你有权检查那个目标。
  • 手边没有代码库，只给文档、汇报或 PR 配一张带官方 logo 的架构图——选 C。一句话一个 npx，出字体与 logo 全内联的单文件 HTML，能直接丢进 repo 或 wiki；代价是它画的是「你声称的栈」，代码一改图就旧。
  • 三件都想要——别按星标从大到小装。先用 C 把栈画成图对外说清，再用 A 摸清自己仓库，最后才轮到 B 重写别人产品的重活；顺序反了成本全压在最后一步。

还有一笔不在安装命令里的账：A 的地图靠每次手动 Update the floorplan. 才跟得上代码，「keep up to date as you work」不是自动的；B 每张 Check 都要跑比对、还得养一个已登录 agent；C 的 logo 来自 svgl、devicon 等第三方包。三者都把「读懂」的一部分成本挪到了安装命令之外。

05 · 冷思考

19,335 星里有多少是「能跑通」，三个「读懂」里又有多少是真读懂

先质疑那个 6.2 倍。19,335 对 3,115，但 craft-anything 是组织账号下的产品：官网 getartcraft.com、Discord、9 语言 README、四平台签名安装包、Releases 里的 SHA256SUMS，一整套分发投入；README 自标 Status: early alpha，还列了「Partly there」——用 API key 构建没跑通 live、app 与游戏行为检查、几个引擎工具只在替身上测过。星标量的是话题和铺量，不是有人跑完一整条流程。

更要紧的是「读懂」被用得太宽。C 连代码库都不碰，只把一句话的名词解析成节点，叫读懂是修辞；A 读 imports 和 request → endpoint 这类静态实现，读不出运行时行为和当初为什么这么设计；B 最像理解，可 Clean room 默认恰恰禁止读源码。三个没谁完整理解了一个软件，各自只切到一片，当同类工具二选一，问题一开始就问错了。

再质疑「产物能不能进版本库」这句干脆话。A 主动不 commit 是克制，也意味着地图绑在本地、换机器就没，「keep up to date」靠你每次敲一句；B 的产物确实是能提交的新代码，可 README 明说 Clean room「is not an operating-system sandbox」，管得住自己那 320 个工具，管不住以你本人权限读写的 coding agent，把「照别人产品生成的代码」提交进公司仓库前，先过的是法务那关，不是 craft-anything-cli doctor。最想进版本库的那个，合规边界也最重。

第四处给那个 0：2,017 星配 0 个未关闭 issue、3 个订阅者，3,115 星配 56 issue、7 订阅者，19,335 星配 213 issue、92 订阅者。两千星的 skill 零 open issue，通常不是没问题，是还没人拿它跑完整条工程流程；C 那张图又全是「你声称的栈」，代码一改图就旧，没有任何工具会替你同步回去。

所以我的判断不落在哪个星多，落在你愿意交出什么、又想把什么留进版本库：A 要你把整个代码库交给 agent 读一遍，换回一张明确不提交的地图；B 要你先接受 clean-room 与许可边界，换回一份能提交却背着合规问题的新实现；C 连代码库都不用交，换回一张能提交、但只对你那句话负责的单文件图。先说清手上是有代码库要读、有产品要复刻、还是只有一句话要画——这一句决定装哪一个，而不是 19,335 比 3,115 大。
