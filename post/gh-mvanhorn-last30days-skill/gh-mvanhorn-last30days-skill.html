67,855 星、30 个来源：免费层只覆盖五分之一

67,855 星的 last30days-skill 把自己定位成「搜人不搜编辑」的 agent 搜索引擎，并行查 30 个来源按 upvotes 和预测市场体量排序。README 说 30+ 来源，表格精确 30 行；SECURITY.md 证实无 telemetry 但补了 Wikidata 自动查公司名且无开关。免费层只有 5 个来源，配齐 11 个付费 key 的时间远超宣称的 30 秒。

01 这件事

67,855 星的 last30days-skill 把自己定位成「搜人，不搜编辑」的 agent 搜索引擎。它并行查 Reddit、X、YouTube、Hacker News、Polymarket 等 30 个来源，按 upvotes、likes 和真金白银的预测市场体量排序，再由 AI 合成带出处的简报。

仓库 2026-01-23 创建，11 月 16 日仍在 push，MIT 许可证，Python 为主（95.8%），附一个 Go 写的 MCP server。79 个 release 跨 271 天，平均 3.4 天一版。

README 头图写着 "Google aggregates editors. /last30days searches people."，GitHub Trending #1 Repository of the Day 徽章挂在页首。口号很漂亮，但 30 个来源里只有 5 个完全免费且无 key——剩下的要 token、要付费 API、要浏览器 cookie，或要第三方爬虫服务。

02 核心机制

它的架构是「skill 指令 + Python 引擎 + Go MCP server」三层。skill 层是一份 31.2 KB 的 SKILL.md 加 17 份 references 文档（最大的一份 research-runbook.md 73.6 KB），告诉宿主 agent 怎么调用。引擎层在 scripts/ 下 142 个 .py 文件，pipeline.py 一个就 335 KB。

工作时 agent 收到查询后调引擎，引擎并行请求各来源，按参与度、相关性和新鲜度打分，合并同一故事跨平台线索，再合成简报。支持话题发现、趋势监控（SQLite 持久化）、本地研究库和结构化 JSON 输出。

03 关键细节与数据

README 自称「30+ 来源」，表格精确 30 行，不多不少。这是第一个口径反差：数字成立，但「+」没有着落。真正的问题不在数量，在成本结构——30 个来源里免费且无 key 的只有 5 个。

第二个口径差在隐私层。README 说 "no tracking, no analytics"——这被 SECURITY.md 证实：引擎无 telemetry、无 update check。但 SECURITY.md 补了 README 没提的细节：

  • 研究主题会发给所有启用的来源和无 key 时的 DuckDuckGo / Startpage
  • 当主题像公司或人名时，自动查 Wikidata 获取股票代码、官网和子公司——无开关可关
  • Yahoo Finance 收到 ticker 符号；专利通道把公司名发给 USPTO（MCP server 默认关掉，CLI 不关）
  • Reranking 是 opt-in：设了 reasoning provider key 后，研究主题和内容片段会发给 OpenAI / xAI / Google 等

第三个差在 "50+ Agent Skills hosts" 这句话。它指 agentskills.io 生态支持的宿主数量，不是本仓库自己的功能。仓库实际支持 Claude Code、Codex、Cursor、Copilot、Gemini CLI、Grok、OpenClaw 和 Claude Desktop 共 8 种安装方式。

04 怎么用

安装方式按宿主分，推荐 Claude Code 的插件市场。在 Claude Code 里两行命令搞定：/plugin marketplace add mvanhorn/last30days-skill 再 /plugin install last30days。其他宿主用 npx skills add mvanhorn/last30days-skill -g。

Claude Desktop 拖入 .mcpb 文件，但 Windows 暂不支持。手动开发安装则是 git clone 后软链到 ~/.claude/skills/last30days。

安装向导宣称 30 秒完成，但前提是已有 Python 3.12+ 且不配 API key。30 个来源里 11 个要 key 或付费服务，配齐至少半小时。

两个已知坑：Claude Code 和 Claude Desktop 的 keys 不互通，需分别配置；原生插件和 npx skills 安装可共存但不去重，/last30days 会显示两个条目。

05 冷思考

67,855 星的背后是 161 个贡献者和 1,489 次提交，top1 占 36.4%。这不是一人项目，但也不是社区共治——mvanhorn 542 次提交，dependabot 和 github-actions 两个 bot 合计 114 次，其余 159 人分 833 次。

79 个 release 跨 271 天、平均 3.4 天一版，节奏极快。SKILL.md 31.2 KB、research-runbook.md 73.6 KB——指令体量比很多完整项目的 README 都大。tests/ 353 个测试文件占全仓 53.9%，说明质量保障投入不低。

但核心问题在 来源可用性的长尾。5 个免费来源覆盖 Reddit、Hacker News、Polymarket、GitHub 和 StockTwits——后两个偏金融，通用话题主要靠前两个。

想查 X 或 YouTube 就要配 token；想查 TikTok 或 Instagram 就要买 ScrapeCreators；想查 LinkedIn 要 Bright Data。30 个来源是理论最大值，不是开箱即用。

README 宣称的「搜人不搜编辑」在免费层基本等于「搜 Reddit 和 HN」。30 个来源是理论最大值，不是开箱即用。

Wikidata 自动查公司名这件事在 README 里没出现，只在 SECURITY.md 写明且无开关。搜一个不想暴露给第三方的人名，引擎会自动拿去查。这不是缺陷，是口径差：README 的隐私承诺管 telemetry，不管数据流向。

对于想拿来就用的人：免费层够了解技术讨论和社区热度，但要覆盖 README 展示的全部场景，配 key 的时间成本远超 30 秒。对于关注隐私的人：SECURITY.md 比 README 诚实得多，装之前先读它。
