01 · 这件事

Anthropic 的官方插件目录

47,427 星、4,927 fork、0 个 Release，但仓库描述只写了一句话：「Official, Anthropic-managed directory of high quality Claude Code Plugins」。

这个仓库存的是 Claude Code 插件市场的官方索引——Anthropic 自己维护的插件放在 /plugins，第三方和渠道插件放在 /external_plugins。README 第一句就划了界限：第三方提交已经搬到 claude.ai/directory/manage，此仓库的 PR 不再监控。

仓库创建于 2025 年 11 月 20 日，到今天正好一年。主语言标记为 Python，但实际内容主要是 JSON 索引和 Markdown 文档。pushed_at 停在今天（2026-11-16），热度没有衰减信号。

02 · 它管理什么

一个 JSON 管着 317 个插件

核心是 .claude-plugin/marketplace.json：192 KB 的 JSON 文件，里面列了 317 个插件条目。不是 43 个，也不是 57 个——README 只提了 /plugins 和 /external_plugins 两个目录，但 marketplace.json 索引的范围远大于目录里的物理文件。

    • 04 · 怎么用

    一条命令装，一个 JSON 管

    安装插件就一条命令：/plugin install {plugin-name}@claude-plugins-official，或者在 Claude Code 里走 /plugin > Discover 浏览。

    每个插件遵循标准结构，以 example-plugin 为参考实现：

    • .claude-plugin/plugin.json — 插件元数据（必需）
    • .mcp.json — MCP server 配置（可选）
    • commands/ — slash 命令（可选）
    • agents/ — agent 定义（可选）
    • skills/ — skill 定义（可选）

    插件名是 不可变 slug：发布后改名会导致用户安装断裂，报 plugin-not-found。要改 UI 显示名，改 displayName 而不是 name；非改不可时，在 marketplace.json 顶层 renames 里加映射，Claude Code 下次同步时自动重写。

    第三方插件不再接受 PR，改到 claude.ai/directory/manage 提交——审核通过后会跨 Claude 产品分发。

    05 · 冷思考

    目录的权限和风险不在一层

    README 用警告框写了一段话：「确保你信任一个插件再安装——Anthropic 不控制插件里包含什么 MCP server、文件或软件，无法验证它们是否按预期工作或是否会改变。」

    这段话的背景是：262 个外部插件的源码不在本仓库，marketplace.json 只锁了一个 SHA。SHA 能保证你拉到的代码和索引时一致，但不能保证代码本身是安全的。CI 有 scan-plugins.yml，但扫描什么、怎么判定的逻辑在那个 27 KB 的 workflow 文件里，README 没提它的结论。

    几个值得注意的口径差：

    • PR 不监控但 issue 照开：close-external-prs.yml 自动关 PR，但 1,097 个 open issue 仍然挂在仓库里——其中最新两条标了 [bug]，是 fakechat 插件的文件覆盖问题。
    • marketplace.json 正在缩减：README 明说它将被缩减为只列 Anthropic 自研插件，第三方索引逐步迁移到 claude.ai/directory/manage。现在 317 个条目是过渡态。
    • bot 主导提交：3,440 次 bot 提交大多来自 bump-plugin-shas.yml 的自动运行——这意味着仓库的活跃度信号（pushed_at、contributors）主要反映自动化程度，而不是人工维护密度。

    判断很简单：这是一个索引仓库，不是代码仓库。它的星标反映的是 Claude Code 生态的热度，不是这个仓库本身的代码质量。装插件之前，去插件自己的源仓库看 README 和 issue，别只看它挂在官方目录里就放心。
