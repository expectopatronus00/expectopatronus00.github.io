01 这件事

它把代码库做成一台本地可查的图数据库，然后把「省了多少 token」写在 README 首页，把「答案质量掉了多少」留在论文里。两个数都公开，只是不在同一页。

11-12 入池时它就已是一个成熟仓库，第 10 天复核星标仍在涨、推送未停，热度够，不需要标 stale。这是存量活跃项目，不是当天冒出来的新库。

项目自己的定位很克制：它是结构分析后端，不生成答案，负责把函数、调用、路由、部署关系存成图；把问题翻译成工具调用、再把结构化结果讲成人话的是你的 MCP 客户端。

打包这件事做得比一般研究型仓库重。README 的 Security 一节列了 SLSA Level 3 构建出处、Sigstore 无密钥签名、每个发布附 SHA-256 校验和，以及 8 个产品共 24 个候选二进制的 VirusTotal 扫描。

02 核心机制

真正发货的不是聊天界面，是 17 个 MCP 工具加一棵 28 类节点的图。图形前端 CBM Lens 还是 v0.0.1 公开测试版，README 明说后端才是核心。

CBM Lens 有架构图、Galaxy 三维图、源码阅读器和本地代码聊天。README 注明录屏拍于 2026-10-20、静态图拍于 10-12 至 10-13，并附每份截图的构建与索引范围说明。它是可选伴侣，不参与后端索引。

索引器把源码、文档、配置、基础设施一起塞进图里，节点 28 类、边 42 类。边不只是 CALLS，还包括 DEPLOYS、CONFIGURES 和跨仓库的 CROSS_*，所以能从服务一路走到容器镜像再到源码。

图元素实测代表项

边类型42 类CALLS / INFRA_MAPS / DEPLOYS / CROSS_*
工具组数量代表工具作用
索引5index_repository建库、删库、查状态、测覆盖
查询12trace_path结构搜索、调用链、Cypher 子集
合计17manage_adr与 README 徽章、架构图三处对齐

语义搜索不是一个独立工具，而是 search_graph 的 semantic_query 参数：Nomic 嵌入被编进二进制，不需要 API key、Ollama 或 Docker。 Hybrid LSP 类型解析另算，只覆盖 12 种语言。

  • full：默认，完整索引加语义分析
  • moderate：过滤后索引，保留语义分析
  • fast：过滤后索引，不做语义分析
  • cross-repo-intelligence：跨仓库连线，可选择目标项目

它能查结构，不负责判断。README 用一段问答示例讲清分工：agent 决定调哪个工具，CBM 返回结构化结果，解释仍由 agent 完成。这不是一个「问了就答」的助手。

04 怎么用

它不需要你装 Python 或 Docker，但安装器会改你的 agent 配置。README 把这点写在首页：这个工具读你的代码，也会写你的 agent 配置文件。

  • 安装脚本：Windows 用 install.ps1，macOS / Linux 用 install.sh
  • 包渠道：npm、PyPI、Homebrew、Scoop、AUR、go install
  • 源码构建：需要 C 工具链，产物在 build/c/codebase-memory-mcp

安装器识别 46 个客户端接入面，其中 40 个自动探测、6 个条件或显式启用。Claude Code、Codex CLI、Cursor 等会额外拿到 Scout / Verify / Auditor 三档 agent 定义。

接入类型代表写入内容
三档 agent + hooksClaude Code / Codex / Gemini CLI技能、规则、会话钩子
仅 MCP 配置Continue / TRAE / Tabnine只写连接，不改提示
显式 opt-inSourcegraph Cody需要已有配置路径

大仓库索引要小心客户端超时。README 建议先 index_repository(async: true)，再用 status: true 轮询，否则取消连接会连带取消索引，重跑永远赶不上 deadline。

团队共享图谱另有笔账。.codebase-memory/graph.db.zst 默认不写，开启后每次索引都会重写；README 举的例子是一个 20 MB 文件在约 350 次提交里滚到约 6 GB 历史。

快照分两档：Best 用 zstd -9、去索引加 VACUUM INTO，Fast 用 zstd -3 做后续刷新，README 给的典型压缩比是 8 到 13 比 1。队友检出时若没装 Git LFS，拿到的是指针文件，导入会被拒，只能全量重建。

Smart CI 的适用范围比宣传窄。它是实验特性，测试收窄目前只支持 C/C++ 系和本仓库自己的测试约定；证据缺失就返回 run_all，建议先跑 shadow 模式再上闸门。

05 冷思考

省十倍 token 的同一篇论文里，答案质量是 83% 对 92%——低了九个百分点。README 的性能段搬走了 10× 和 2.1×，没搬这一行。

指标CBM agent逐文件探索
答案质量0.830.92
每问 token约 1,000约 10,000
每问工具调用2.34.8

论文把话说得比 README 细：质量分由第一作者对照人工检查得出的参考答案打，阈值 0.80 / 0.40 是实用主义选的；只用了 Claude Opus 4.6 一个模型，每种语言只有一个仓库。

评测用 31 个仓库、每种语言一个，覆盖 12 类标准问题，从索引、发现、模式匹配一直到调用链和图查询；两边收到相同问题、同一后端。延迟差更大：图查询远小于 1 毫秒，逐文件探索要 10 到 30 秒。

分差也不是均匀的。图原生问题上，CBM 在 19/31 语言持平或超过对照；需要完整源码或穷举 grep 的问题，对照在 16/31 和 10/31 语言上占优。宏密集的 C 更是 0.58 对 1.00。

作者自己的建议是混合架构：图检索加文件探索回退，而不是用图替掉读文件。这与首页「一次图查询替代几十次 grep」的单句宣传并不完全同一件事。

还有两处边界值得记：图只表示静态结构，不含运行时行为和动态分派；query_graph 默认 10 万行上限，在超大库上可能少算。性能测试只在一台 Apple M3 Pro 上做过。

它适合把跨服务、跨文件的结构问题从几十次读取压成几次查询；不适合当作源码级事实的唯一裁判。要拿它替代探索式阅读，先看你的问题落在 19/31 那一边，还是 16/31 那一边。
