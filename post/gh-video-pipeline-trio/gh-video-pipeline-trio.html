01 · 这件事

三个仓库都让 agent 产出视频，接的却是三段不同的活

Pika-Labs/Pika-H3-Flex 2026 年 10 月 29 日建库，11 月 8 日核对时 1,476 星、45 fork、27 个订阅者、1 个未关闭 issue，Python，837 KB，最后 push 在 11 月 2 日。description 只有一句：Pika H3 Flex: video and audio generation inference——视频与音频生成推理。API 的 license 字段给的是 NOASSERTION，不是某个标准协议。

mromidev/claude-animated-shorts 11 月 1 日建库，2,361 星、513 fork、38 个订阅者、10 个未关闭 issue，MIT，TypeScript，17,948 KB，最后 push 停在 11 月 1 日 05:57，也就是建库当天。description 写得具体：Free Claude skill: viral animated story shorts (2D characters in a 3D world) with three.js + Remotion。根目录只有 5 项，其中 SKILL.md 一份 15,131 字节。

calesthio/OpenMontage 这次核对先撞上一个 301 Moved Permanently：仓库已迁到 OpenMontageInc/OpenMontage，跟随重定向后才拿到数——78,485 星、10,462 fork、394 个订阅者、322 个未关闭 issue，AGPL-3.0，Python，78,486 KB，2026 年 3 月 29 日建库，11 月 8 日 03:50 还在 push。description 自述 12 production pipelines, 100+ tools, 700+ agent skill and production-knowledge files，要把 AI 编码助手变成一整个视频制作棚。

三条同属「让 agent 产出视频」一族，数字各自独立核过。但把 README 翻开会发现，它们分别站在模型推理层、单个 skill 层、全流程编排层：A 只生成片段与音轨，B 交一条成片，C 交的是能反复出片的整条流水线。下面按「接住哪一段、产物是素材还是成片」拆，最后给判断表。

02 · 核心机制

一个出素材，一个出一条片，一个出生产流程

A 是本地推理包，命令与 Python 发行包都叫 pika-h3-pro。README 的章节名就把边界写清楚了：Input and output specifications、Generation modes and reference limits，讲的是一次请求吃进什么参考、吐出多长的视频与音频；Pika API extensions 明说那些可选的托管服务「separate from the downloadable adapters and local inference package」。它接住的是「生成一段像素和声音」，不碰剪辑、不碰时间线——产物是能被别的工具再拿去用的素材。

代价落在硬件和许可上。README 要求 Python 3.12、NVIDIA GPU，代表配置是每请求一张 H100 80GB，H200 与 B300 标着 untested，超出显存加 --cpu-offload；模型组件来自 MiniMax-H3、Diffusers、Transformers，适配器注入用 PEFT。许可也不是一个词：README 的 License 说 adapters 是 MiniMax H3 的 Model Derivatives、按 MiniMax H3 Community License Agreement 分发，Code license 才说推理与加载代码是 Apache-2.0（LICENSE-CODE）——API 那个 NOASSERTION 正是代码与模型双许可的结果，根目录也确实并排躺着 LICENSE 17,604 字节和 LICENSE-CODE 11,357 字节。

B 把一份 SKILL.md 当全部运行时。装进 ~/.claude/skills/cartoon-3d-short/ 后，在 Claude Code 里说一句 Use the cartoon short skill and make a short about …，agent 就照 SKILL.md 走：topic and facts、script、voice、再把分镜写进 story.ts、出 stills、最后 renders，Agents 还会拿 reports 去对帧。它靠 Remotion 与 @remotion/three 把 2D 角色放进 3D 世界，产物是一条能直接发出去的动画短片，不是素材。但它锁定一种画风、一个宿主，README 34 行、2,275 字节就写完了。

C 管的是编排。README 直说「OpenMontage is pipeline-driven」，真活走 pipeline_defs/、阶段导演 skill 放在 skills/pipelines/、工具靠 tools.tool_registry 发现；在 proposal time 先定 render_runtime，在 Remotion 与 HyperFrames 之间选一个，再用 python -m backlot open 打开从项目文件里长出来的动态分镜板。它接住的是从选题、脚本、素材、配音到渲染、发布的整条链，产物是「一套能反复出片的流程」而不是某一个文件。

摆成一条轴：A 在最低层，只把提示词变成像素；B 在中间，把一次创作意图变成一条成片；C 在最上层，把成片这件事本身拆成可调度、可换 provider、可回溯的阶段。越往上，agent 被改写的默认行为越多，能单独搬到你别的项目里的部分反而越少。

03 · 关键细节与数据

78,485 星对 2,361 星对 1,476 星，量出来的不是同一把尺子

把三组硬数字摊平。A：1,476 星、45 fork、27 订阅、1 个未关闭 issue、2026-10-29 建库、11-02 最后 push、license NOASSERTION、Python、837 KB。B：2,361 星、513 fork、38 订阅、10 个未关闭 issue、2026-11-01 建库、11-01 05:57 最后 push、MIT、TypeScript、17,948 KB。C：78,485 星、10,462 fork、394 订阅、322 个未关闭 issue、2026-03-29 建库、11-08 03:50 最后 push、AGPL-3.0、Python、78,486 KB。三者 default_branch 都是 main，星标以本次核对为准。

厚度和星标完全不成正比。A 根目录 20 项，README 17,680 字节，配 Dockerfile、pyproject.toml、requirements.txt、patches/、src/、tools/ 一套推理工程；B 根目录 5 项，README 只有 2,275 字节，全部逻辑压在 15,131 字节的 SKILL.md 里，另有 references/ 与 templates/；C 根目录 47 项，README 44,055 字节，还并排 39,988 字节的 README_zh-CN.md、49,611 字节的 AGENT_GUIDE.md，以及 .claude/、.codex/、.cursor/、.agents/ 一整排宿主适配目录。837 KB 对 78,486 KB，体积差近百倍。

C 那串自述得单独挑明。description 写 12 production pipelines, 100+ tools, 700+ agent skill and production-knowledge files；本文用 /contents/ 实测到的只有：pipeline_defs/ 13 个 yaml（含一个 framework-smoke.yaml）、skills/pipelines/ 12 个导演目录、tools/ 顶层 27 项（14 文件 + 13 子目录）、skills/ 顶层 5 项。「12」勉强对得上 12 个导演目录，但定义文件是 13 个；100+ 工具与 700+ 文件要递归进子目录和 registry 才数得清，本文未逐一复核——按作者自述处理，不当实测。

还有两处口径。一是 Pika 的 license：API 给 NOASSERTION，README 却把模型 adapters 与代码分成两套许可，抄进产品前得分清拿的是哪一份。二是选题池里的积压评分、榜单数字都不是 api.github.com 的字段，本文不采用；正文里每个数值只取自 2026-11-08 这次核对或标明的仓库自述。

04 · 怎么用

先决定要的是素材、一条片，还是一套能反复出片的流程

A 最重。README 的安装是 git clone https://github.com/Pika-Labs/Pika-H3-Flex.git，再 python -m pip install -r requirements.txt、python tools/apply_diffusers_patches.py、python -m pip install --no-deps -e .；Docker 走 docker build -t pika-h3-pro . 与 docker run --rm --gpus 'device=0' pika-h3-pro --help。前提是 Python 3.12、NVIDIA GPU 和一张 H100 80GB 级显卡，需要鉴权时运行时传 HF_TOKEN。它不装 agent，装的是一个要 GPU 供着的推理包。

B 最轻，也最挑宿主。README 只有三步：把整个文件夹拷到 ~/.claude/skills/cartoon-3d-short/（clone 过去或下 ZIP），备好 Remotion、@remotion/three、Node、Python 3 与 ffmpeg，然后在 Claude Code 里说那句触发语。它没有 pip 包、没有插件市场，一份 SKILL.md 就是全部安装量，但少装 Remotion 或 ffmpeg，renders 那一步直接断。

C 是项目模板不是插件：git clone https://github.com/calesthio/OpenMontage.git 后 make setup，前提 Python 3.10+、FFmpeg，以及一个能读文件、能跑代码的编码助手（README 列了 Claude Code、Cursor、Copilot、Windsurf、Codex）；无 make 时手动建 venv，用 python -m backlot open 看板、python scripts/backlot_simulate_run.py 看模拟跑一遍。注意 README 里的 clone 地址还停在迁移前的 calesthio，仓库已迁到 OpenMontageInc，旧地址靠 301 转发才不失效。

判断表如下，A 是 Pika-H3-Flex，B 是 claude-animated-shorts，C 是 OpenMontage：

  • 只要一段能反复取用的视频或音频素材，自己有剪辑与合成链路——选 A。它按输入输出规格出片段，Pika API extensions 也是可选托管服务；代价是 H100 级 GPU、Python 3.12、diffusers 打补丁，以及 adapters 走 MiniMax H3 Community License 而非 Apache-2.0，商用前先读 NOTICE。
  • 要一条能直接发的动画短片，且就认 2D 角色 3D 世界这一种画风——选 B。一份 SKILL.md 把 topic、script、voice、story.ts、stills、renders 串完，还带 agents 对帧；代价是锁死在 Claude Code + Remotion + ffmpeg，换画风得自己改 SKILL.md。
  • 要把「出片」变成可重复、可换 provider、可回溯的生产流程——选 C。pipeline_defs、导演 skills、tool_registry、backlot 分镜板、可选 API key 一起给全，零 key 也能出片；代价是 AGPL-3.0、Python 3.10+ / FFmpeg / 一个 coding assistant，以及 78,486 KB 的工程。
  • 三件都想要——别按星标从大到小装。先想清楚要交出去的是哪一段：只在末端缺素材就补 A，只缺一条成片就用 B，只有把整条链交出去才轮到 C；反过来先上 C，再发现其实只要一段 5 秒素材，成本全压在最重的那一步。

还有一笔不在安装命令里的账：A 的每请求 H100 是硬门槛，H200 / B300 README 明说 untested；B 的 renders 依赖本机 Remotion 与 ffmpeg，且最后 push 停在 11 月 1 日建库当天；C 的零 key 路径和付费 provider 路径能力并不等价，README 自己按 ~$0.15–$1.50、~$1–$3 分了档。三者都把一部分成本挪到了安装命令之外。

05 · 冷思考

78,485 星里有多少是「跑完一整条流程」，三层的「出片」又有多少是真出片

先质疑那个 53 倍。78,485 对 1,476，可 C 是 2026 年 3 月 29 日建的库，比 A、B 早了七个月，有四种语言 README、49,611 字节的 AGENT_GUIDE.md、一整排 .claude / .codex / .cursor / .agents 宿主目录、34,523 字节的 LICENSE 和 322 个未关闭 issue；README 开口就是 World's first open-source, agentic video production system。星标量的是铺量和分发，不是有人把 12 条 pipeline 从头跑到尾。

更要紧的是「让 agent 产出视频」被用得太宽。A 只交像素与音轨，连时间线都不管，叫出片是抬高；B 确实交一条成片，可锁死一种画风；C 交的是流程，最终渲染仍落回 Remotion 或 HyperFrames 和一堆可选 API key，agent 编排得再满，片子不是它自己渲的。当同类工具三选一，问题一开始就问错了。

第三处在数字的可靠性。C 的 description 说 12 条 pipeline，pipeline_defs/ 实测 13 个 yaml 里还夹着一个 framework-smoke；说 100+ 工具、700+ 文件，顶层目录却只有 27 项和 5 项，得递归才数得清，本文没核；README 的安装命令还指向已迁移的 calesthio。A 的 NOASSERTION 也不是笔误，是 adapters 与代码两套许可；B 2,275 字节的 README 里，除了安装和一句触发语，几乎没留下可核对的承诺。把自述当实测排序，等于拿标注当测量。

第四处是「不装配套会怎样」。A 没 H100 级 GPU 就跑不起来，H200 / B300 还标着 untested；B 少 Remotion 或 ffmpeg，renders 直接断，而它最后一次 push 停在 2026-11-01 建库当天，之后没动；C 零 API key 能出片，可 README 自己把「零 key」「~$0.15–$1.50」「~$1–$3」分成三档，能力并不等价，AGPL-3.0 对把它接进商业产品的团队也不是一句 make setup 能带过的。最想进生产流程的那个，合规与运维边界也最重。
