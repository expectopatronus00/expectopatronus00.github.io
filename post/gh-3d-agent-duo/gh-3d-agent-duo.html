1,961 星造几何、1,521 星出画面：别当竞品挑

1,961 星与 1,521 星，两个 11 月初新建的仓库都写着 built for agents。sand3d 把 Blender 包成建模语言，vork 用 Rust 做 GPU 渲染。一个造几何一个出画面，是上下游不是竞品。

expectopatronus 2026-11-14 约 6 分钟阅读 原创 · AI 编程
01 · 这件事

两个都写着 built for agents，交出的却不是同一样东西

这两个项目不是竞品，是同一条流水线的上下游。2026-11-03 建库的 sand3d 有 1,961 星，11-05 建库的 vork 有 1,521 星。两个 description 分别写着 built for LLMs 和 for agents，看上去像同一赛道里的两个备选，实际一个造几何、一个出画面。

先把身份摆齐。下表数字来自 api.github.com 的仓库接口、完整目录树与 search/issues，open 值已拆成 issue 与 PR 两部分，没有把 14 当成 14 个缺陷。

一个交出的是可编辑的几何文件，一个交出的是渲染好的像素。sand3d 的 export 按扩展名吐出 GLB、URDF、IFC 等格式；vork 的场景里有一个 asset 节点，示例正好读 model.glb。前者造零件，后者把零件放进光照和相机里出片。

两条同属 3d-agent 一族，是积压第 7 天与第 6 天的候选，按同族合并一次消耗。下面按机制、数据、用法三条线拆，最后给选 A 还是选 B 的判断表。凡涉及效果的数字，一律按作者自述读，本文没有渲染任何一帧。

02 · 核心机制

都在压缩给模型看的东西，压缩的却是两段不同的上下文

一个把建模词汇压进提示词，一个把渲染接口压进提示词。sand3d 把 Blender 的 bpy 包成一层扁平动词，README 说整个 API 约 3,600 tokens，塞进 system prompt 就能用；vork 说核心 API 约 2,500 tokens，靠 vork help 按需展开 27 篇主题文档。

sand3d 的最小单位是具名零件。程序用 rect、extrude、hole、fillet 一类动词写「一个形状怎么被做出来」，边和面按名字引用，不算坐标；joint 声明部件怎么动，README 的洗衣机示例 38 行、4 个关节。docs/api.md 实测 11,461 字节、70 个函数签名。

扩展名带什么给谁用
GLB网格、材质、节点 extras 里的关节Web、查看器、游戏引擎
URDF每个活动部件一个 link，含限位ROS、MuJoCo、Isaac
USDAOpenUSD 的 UsdGeom 与 UsdPhysicsOmniverse、Isaac Sim
IFCIFC4 项目树、三角面片Revit、ArchiCAD、BIM
OBJ / STL仅网格，当前姿态任意 3D 工具、切片

vork 反过来，场景是一份 JSON。它用 Rust 与 Slang 写，走 Vulkan 和 Metal，agent 写 scene.json、渲染、看图、再改，README 直说没有编辑器可驱动。默认渲染把光栅可见性与硬件光追照明合在一起，另留一个路径追踪档。

  • 四个画质档：std/previs 迭代、std/draft 4 采样、std/final 8 采样、std/path 路径传输。
  • 三处 agent 接口：vork init 起项目、vork help 查字段、skills/vork/SKILL.md 交给编码 agent。
  • SDK 两种：Python 的 vork、TypeScript 的 @voyager-so/vork；npm 上同名的 vork 包与本项目无关。
  • 27 篇 help：docs/help/ 下共 101,884 字节，按主题查，不是一次灌进上下文。

两个 token 数字不好直接比大小。3,600 指整份 API 文档，2,500 指核心 API；前者按文件字节反查是 11,461 字节，后者身后是 27 篇 help。一个是全量塞入，一个是按需检索，口径不同。

03 · 关键细节与数据

对回目录树，两处口径比星标更值得写下来

自述数字没有撒谎，是分母换了地方。这不是给项目挑错，是提醒引用这些数字时别用错口径。

GitHub 把 sand3d 的主语言标成 HTML，源码却在 src/ 下 17 个 py 文件、734 KB。完整目录树给出答案：HTML 只有 6 个、5.28 MB，全在 site/ 里，quickstart.html 一个就 3.94 MB。主语言按字节算，被文档站撑成了 HTML。

vork 最抓眼的数字是「一百万只鸟、192 帧 1080p、单张 L4 用 97 秒」，EEVEE 投影 13 到 18 分钟。但同一份 README 用整节注明：这些是计时，不是等质量加速。

核对项README 自己给的边界
采样不对等vork 8 采样加 OIDN，EEVEE 64 采样无降噪
影片是投影EEVEE 值由 8 帧外推，projections, not measured movies
质量未过线19 个早期对比未通过 FLIP no-worse 条件
未完成作业583 / 585 张图；百万星场景两种档都显存不足
反向结果路径追踪比 Cycles 慢 1.99 到 5.81 倍
冷启动setup 250.792 秒；rack-focus 首帧 82.057 秒

另两处反查也对得上。sand3d 的 README 把动词族标成 16 / 15 / 15，docs/api.md 逐行数正是 profiles 16、solids 15、edits 15。但 assembly 标 8，文件里数出 9 个签名，差在 empty_scene 这类辅助函数没被算作动词。

vork 的 README 列 8 个成片示例，examples/ 下实际有 10 个子目录，多出的 assets 与 programs 是素材和程序片段，不算成片。两处都不是虚报，只是自述按展示口径数、目录按文件口径数。

数据核对：经 api.github.com 仓库接口、完整目录树、search/issues 与 git/blobs 原文读取，文件数与字节数均为完整树计数，两棵树都未截断。

  • 树：sand3d 152 文件 / 12,228,071 字节；vork 1,729 文件 / 54,404,605 字节。

  • 边界：GLB 串联仅指格式可读，两家文档均未提对方；关节 extras 是否被读无说明。本文未安装、未渲染、未复现任何性能数字。

04 · 怎么用

先看显卡，再看要不要把它做成服务

两个项目的门槛不在同一处：一个卡 Python 版本，一个卡硬件光追。装之前先照下表对一遍环境，比读十页 README 省事。

项sand3dvork
安装pip install sand3d平台安装包或 npm create vork；pip 仍写 Coming soon
Python3.11 或 3.13，3.12 无 wheel3.11 及以上，仅 SDK 需要
底层依赖bpy 4.5（3.11）/ 5.2（3.13）Slang、OIDN、Vulkan 或 Metal
GPU不要求Apple Silicon 或带硬件光追的 NVIDIA
明确不支持Intel Mac 从 bpy 5.2 起Intel Mac、A100 / H100 / H200 / B200 / B300
视频输出不涉及Linux 与 Windows 需 ffmpeg

串联路径两边 README 都给了。sand3d 用 s3d.export(machine, "washer.glb") 导出，vork 的 glTF 示例在场景里放 {"type":"asset","file":"model.glb"}。

再跑 vork render model.json 出 PNG，造几何的就把零件交给造画面的，中间不必手写转换器。

但格式对得上，不等于两家联调过。两边文档都没提对方：sand3d 的关节写进 GLB 节点的 extras，vork 读不读没有说明，材质能否保真也要自己验。

单位还得手动对齐，sand3d 默认毫米，vork 用米。这条链路是照着两份 README 推出来的，不是实测结果，别默认无损。

05 · 冷思考

差 440 星不重要，两份许可证划的线才重要

最该先看的不是热度差，是「能不能用」被写在了两种完全不同的条款里。

两个仓库到核对日都不到两周：11-03 与 11-05 建库，1,961 星配 11 个订阅者、7 位贡献者，1,521 星配 8 个订阅者、1 位贡献者 12 次提交。54 MB 源码、1,729 个文件由单人推送，更像一次集中开源，不是长期协作。星标是发布期曝光，不是生产验证。

sand3d 是 Apache-2.0，LICENSE、pyproject.toml 与徽章三处一致。vork 的 API 是 NOASSERTION，LICENSE 标题叫 vork Preview License。

它开头就写 source-available 和「It is not open source」，还把「代表你行动的 AI agents」写进了「你」的定义——条款连调用方是人是模型都提前划了线。

预览期可商用，但条款禁止出售、分发修改版、对外提供托管渲染，且只覆盖当前版本，后续版本可能改为付费。想把它包成一个按次收费的渲染服务，这一步就走不通；README 里那句 free during the research preview 也预留了变化。

所以「给 agent 用的 3D」不该当一个品类比高低。先问产出物是文件还是像素，再问许可证允不允许你把它做成服务。要造零件，A 那 70 个动词就够；要出片，先验自己那张卡过不过 B 的硬件门槛。真正把两者分开的不是星标，也不是谁更省 token，是你要交付的东西落在流水线的哪一段。
