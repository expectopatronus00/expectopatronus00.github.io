02 核心机制

同一套工具能力被装进三个入口：MCP 服务、命令行客户端、教 agent 怎么用它们的技能包。

入口形态承担什么
MCP servernpx chrome-devtools-mcp@latest把工具暴露给客户端
CLIchrome-devtools终端直接调，也能生成脚本
Skills仓库 skills/ 目录告诉 agent 何时调哪个工具

工具参考文档是自动生成的：13 个分类、63 个工具。最多的是内存类 14 个，输入与调试各 10 个，导航 6 个，扩展 5 个，PWA 4 个，性能 3 个。

但参考文档列的是全集，不是启动即有的集合。配置文档里 13 个分类开关，7 个默认 true，另外 6 个要显式打开。

默认开启（7 类）默认关闭（6 类）
输入、导航、模拟网络模拟、扩展
性能、网络、调试第三方工具、WebMCP
内存PWA、WebAuthn

--slim 是另一层收敛：只留导航和调试两个分类，共 3 个工具——navigate、evaluate、screenshot。给只做页面检查的 agent，这比全量 63 个更合适。

03 关键细节与数据

技能目录有 8 个，README 表格只列 7 个；缺的那一个恰好也是门槛最高的。

README 的技能表列出七项：chrome-devtools、chrome-devtools-cli、a11y-debugging、cookie-debugging、debug-optimize-lcp、memory-leak-debugging 和 troubleshooting。

仓库 skills/ 下实际还有第八个目录 inspect-in-devtools，它的 SKILL.md 有 9,221 字节，却没进 README 的表格。

04 怎么用

最小的接入只要一段 JSON，但真正需要动手的是启动参数，尤其是遥测和文件访问。

MCP 客户端写入 npx -y chrome-devtools-mcp@latest 即可。浏览器不会在连接时启动，而是第一次调用需要浏览器的工具时才起来。想验证，先问一句「检查 https://developers.chrome.com 的性能」。

CLI 要全局装包：npm i chrome-devtools-mcp@latest -g。它连的是后台常驻的 daemon：Linux/Mac 走 Unix socket，Windows 走命名管道；默认 headless、默认隔离，除非你自己给 --userDataDir。

顾虑参数 / 变量说明
遥测--no-usage-statistics默认开启，记录成功率、延迟、环境
真实用户数据--no-performance-crux性能工具默认可能发送 trace URL
工具面太大--slim缩到 3 个工具
CLI 文件访问--workspace默认不限目录，可重复指定
JS 执行--no-javascript-evaluation关掉部分执行入口，不是浏览器沙箱
网络范围--allowed-url-pattern只作用于已附加的 DevTools 目标

关遥测也可以设 CHROME_DEVTOOLS_MCP_NO_USAGE_STATISTICS 或 CI；关更新检查用 CHROME_DEVTOOLS_MCP_NO_UPDATE_CHECKS。注意 Chrome 自己的指标开关与此互不相通。

技能可以用插件装：Claude Code 走 /plugin marketplace add ChromeDevTools/chrome-devtools-mcp，Gemini CLI 走 gemini extensions install --auto-update 并跟随更新。手动复制的技能要在每次升级后重拷。

05 冷思考

这个项目的边界写在文档里，而不是写在默认配置里：它把浏览器内容原样交出去，把校验责任交给调用方。

README 第一句免责就是：MCP 客户端可以检视、调试和修改浏览器里的任何数据，别把不想交出去的隐私放进去。SECURITY.md 补充，网页内容按原样返回文本，结构变化不算漏洞，并建议防提示词注入。

它把启动目录、环境变量、npm 配置、Node 与 Chrome 二进制都列为可信输入；检查不受信任的仓库，建议放进系统沙箱或虚拟机。MCP roots 是可选配置，且临时目录始终可访问。

常被当成沙箱的开关文档原文口径
--allowed-url-pattern不完整的网络沙箱
--no-javascript-evaluation不是 JS 沙箱，无浏览器级边界
--experimentalDevtools会让上面的开关失效
MCP roots可选配置，tmp 目录豁免

支持面也窄：官方只承诺 Google Chrome 与 Chrome for Testing，其他 Chromium 系「可能可用但不保证」。113 个未结里 33 个是 PR，说明仍在活跃收补丁，也意味着 1.14.0 不是终点。

它交付的是 DevTools 的观察与操作能力，不是浏览器里的安全边界。本地调试照默认用没问题；一旦页面带着登录态或来自不可信来源，先把遥测、目录、JS 与 URL 这四项配好，再让 agent 上手。
