01 · AI编程的"瞎写"问题

AI编程的"瞎写"问题

Vibe Coding 让人人都能用 AI 写代码，但一个普遍痛点是：AI 经常"瞎写"——不按规范来、随意命名、忽略错误处理、代码结构混乱。你说一句"帮我写个功能"，它一顿输出，结果能用但写得一塌糊涂。

AI"瞎写"代码的常见表现：
  • 变量函数命名随意，不看上下文已有命名风格
  • 不写错误处理，假装所有调用都会成功
  • 重复造轮子，不使用项目已有的工具函数
  • 代码结构混乱，一个函数干十件事
  • 不写注释，不写测试，改完就走
02 · 解决方案：给AI立规矩

解决方案：给AI立规矩

这个项目的核心思路很简单：与其每次都在 prompt 里重复要求，不如把规则固化为 Skill，让 AI 自动遵守。

什么是 Skill？

Skill 是一份结构化的规则文件（通常是 Markdown），告诉 AI Agent 在特定场景下应该怎么工作。它就像给 AI 一本"员工手册"——遇到什么情况怎么处理，都有明确的规定。

Skill vs 系统提示词的区别
  • 系统提示词 — 每次对话都要重复，容易遗漏
  • Skill — 自动加载，按需触发，不占额外 token
  • Skill — 可以包含触发条件、执行步骤、检查清单
  • Skill — 团队共享，保证所有人用 AI 的标准一致
03 · Skill如何工作

Skill如何工作

步骤1
定义规则 — 把团队的编码规范、最佳实践写成 Skill 文件
步骤2
自动加载 — AI Agent 启动时自动读取 Skill，不需要手动指定
步骤3
按需触发 — 当场景匹配时，AI 自动应用对应规则
步骤4
规范输出 — AI 按照规则写代码，不再"瞎写"
04 · 为什么Skill比Prompt更好

为什么Skill比Prompt更好

Prompt 是每次都要说的"口头叮嘱"，Skill 是写进制度的"工程规范"。口头叮嘱会忘，制度不会。

Skill 的三大优势
  • 一致性 — 团队所有人用 AI 都遵循同一套规范，代码风格统一
  • 可积累 — 踩过的坑写成 Skill，下次自动避免，经验可复用
  • 低成本 — 不需要每次对话都写长 prompt，Skill 自动按需触发
05 · 适用场景

适用场景

适合用 Skill 的场景
  • 团队编码规范 — 命名规则、代码结构、注释要求
  • 框架最佳实践 — React 组件写法、API 设计规范
  • 测试规范 — 测试覆盖率要求、测试用例模板
  • 安全规范 — 输入验证、SQL 注入防护、密钥管理
  • 部署规范 — CI/CD 流程、环境变量管理、日志规范
06 · 总结

总结

核心观点：AI 瞎写代码不是 AI 的问题，是没有给它立规矩。Skill 就是给 AI 立规矩的工具——把团队的编码规范、最佳实践固化为结构化规则，让 AI 自动遵守。从"瞎写"到"规范写"，差的不是更好的模型，而是更好的约束。
