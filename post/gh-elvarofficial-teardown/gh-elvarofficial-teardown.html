02 · 核心机制

一个输入驱动一切，屏幕上的数字不许和运动打架

入口是 SKILL.md，frontmatter 把触发场景列得很宽：有人问 how a machine works，想要 visual explainer / simulator / cutaway / exploded view / interactive 3D lesson，或想看 3D 物件动起来而不是被描述。正文第一句就定形：One machine, one page。产物是一个离线 HTML 页面，同一套代码还能逐帧录成 60 fps 视频并配一条同步的程序化配乐。它不是给 three.js 套模板，是先规定机器只能怎么动。

七条「决定它能不能成」的规则里，前四条是硬约束。第 1 条 Start from a reference, never from imagination：先找照片、手册里的剖视图或实拍片段，逐帧比对；原文写 Machines invented from a sentence come out generic every time。第 2 条 Real numbers, one source：先拿真实尺寸（缸径、行程、齿数、连杆长度），每一块表、每一张图、每一个标签都从摆放零件的同一个函数读，屏幕上不许和运动不一致，还要手算校核一条。第 3 条 One input drives everything：姿态只由曲轴角、行程或风速决定，不许手打关键帧，film、live 页面和配乐才不会漂移。第 4 条 The part doing the work opens up：isolate、cut、x-ray，用作者的话说，能进到内部的相机值十个环绕镜头。

落到文件上是一台机器三个目录、按职责切文件：-shared/ 放机器本身，-live/ 放你能操作的页面，-film/ 放录好的巡览。数学单独一层（kin.js / gear.js / jansen.js），真实单位、单一输入、不含 three.js；几何、影棚、控制台、脚本各自一个文件。最关键的是 render(t) 契约：duration: 20、fps: 60，函数必须纯——禁 Math.random、禁 Date、不许跨帧带状态，因为抓帧会在任意时刻调用它；第 0 帧就是缩略图，且必须已经显示机器；每个节拍写进 timeline.json（单位秒），配乐读同一份文件。画面和声音共享一根时间轴，漂移在结构上就不可能发生。

剩下三条管观感：浅色影棚配单一强调色（暗背景会输掉第一秒）、按机构选机位（平面连杆正看会塌成网格）、穿透用参数块里的数字修而不许用镜头遮。后面还单列了 live 页面的性能规则、three.js 在 Windows 的 ANGLE/D3D 上踩过的五个坑、声音的 48 kHz 与 −14 LUFS，以及一张带数字的品味表。规则密度不像一份 SKILL.md，更像渲染车间的作业指导书。

03 · 关键细节与数据

三张动图 14.4 MB，是全部代码的约 37 倍

先用逐层 /contents 把仓库数一遍。根目录 13 项，10 个文件 3 个目录：文档只有 README.md 2,283 字节与 SKILL.md 11,672 字节，其余是 package.json 520、package-lock.json 16,634、LICENSE 1,099，加四个工具脚本（paths.mjs、run_sfx.py、sheet.mjs、wave.mjs）。sims/ 13 项 = 3 个脚本（build.mjs 5,806、capture.mjs 9,418、beats.py 7,155）+ 10 个目录：kit/ 与 v8、cessna、strandbeest 三台机器各 3 份（shared / live / film）。sfx/ 8 项 = 7 个 Python 文件共 41,476 字节 + samples/。而 docs/ 只有 3 个文件，却占了 bee.gif 6,250,109、octopus.gif 4,691,465、scorpion.gif 3,485,023 字节，合计 14,426,597 字节。对照 languages 接口的 JavaScript 325,287 / Python 55,512 / CSS 6,878，代码合计 387,677 字节——三张首页动图约是全部代码的 37 倍。

这个对比正好解释开头那个「演示换了，示例没换」。sims/ 里没有任何 bee / scorpion / octopus 目录，README 给的三条构建命令仍是 node sims/build.mjs v8-live、cessna-live、strandbeest-live，SKILL.md 的示例表也仍是交叉平面 V8、Cessna 337 主起落架、Theo Jansen 的 20 腿 Strandbeest。10 月 31 日那次提交确实只改了 README 与 docs 里的图。你被首页那三只机器生物吸引，装到手能跑的仍是另外三台。

自述数字大多能对上实物，少数要标口径。Cessna 那条手算校核写得很实：32 齿 × 4 mm 模数 = 128 mm 节圆直径，半周长正好是 201 mm 行程，齿轮转 180°；V8 的点火顺序是 1-8-4-3-6-5-7-2，8 个活塞由 slider-crank 精确驱动；Strandbeest 用 Jansen 的 11 个连杆长度按圆交点解算，作者标「67 行精确连杆解算器」。package.json 是 version 1.0.0、private: true，5 个依赖（three 0.186.1、esbuild 0.28.1、playwright 1.58.2 与两个字体包）、2 个 scripts；README 与 SKILL.md 都写「需要 Node.js 20 或更新」，但 package.json 里没有 engines 字段，这条要求只存在于文档。

阈值密度是这份 SKILL.md 最特别的地方：单页保持在 1 MB 以下（原文理由是 X、Slack 的链接爬虫读分享卡，15 MB 的页面会直接放弃），构建出的 v8-live.html 自述约 800 KB；必须在集显上测，桌面卡能跑 60 fps 的页面到笔记本集显可能掉到 15 fps；--size 1600x900 --dpr 1.2 出 1920×1080；无操作 25 s 把控制权交还自动巡览；review 静帧取每个节拍后 0.3 s；重要元素离边缘至少 60 px、1080 canvas 上标签不小于 34 px、大表面 roughness ≥ 0.45、envMapIntensity ≈ 0.5、emissive 层压在 1.0 以下；声音 48 kHz、母带 −14 LUFS、true peak ≤ −2 dBFS。几乎每一条审美判断都配了一个可核对的数。

04 · 怎么用

一句 npx 装 Skill，后面是一整套渲染工具链

安装分两步，README 写得很轻：npx skills add elvarofficial/teardown -g -a claude-code，然后「once, in the installed folder」跑 npm install && npx playwright install chromium；SKILL.md 里对应的是 cd "$SKILL_DIR" && npm install && npx playwright install chromium。前置条件列在后面：Node.js 20 或更新，出视频还要 ffmpeg 在 PATH 上，出配乐要 Python 3（只用标准库）；SKILL.md 另外允许用 FFMPEG、PYTHON、CHROMIUM 指向别的二进制。这个「once」背后是 npm 依赖、一个 Chromium 和一套能跑 GPU 渲染的环境。

用起来是三句大白话，README 给了原句：Build me a simulator of a 4-stroke motorcycle engine I can take apart.、How does a mechanical watch keep time? Show me as a simulator.、Make a teardown of a hydraulic excavator arm and record a 20-second video of it.。更稳的起点是先跑现成的三台：node sims/build.mjs v8-live 产出 teardown-out/dist/v8-live.html，一个约 800 KB 的离线页；不带参数跑 build.mjs 是 all 6。SKILL.md 建议「从最接近的那台复制」，因为三台已经把数学层、几何层、控制台层、film 脚本与配乐脚本的接口都示范了一遍；想在 SKILL_DIR 之外建机器，则给一个带 main.js 的目录，用 import {runSim} from 'teardown-kit/runtime.js' 引 kit。

要出片就走完整条链：capture.mjs 按 --stills beats 出静帧表或按帧渲染静音 mp4，run_sfx.py 读 timeline.json 合成 wav，ffmpeg 把音视频合成，最后 wave.mjs 再对一遍时间轴。文档反复强调的验收是 review loop 五步：不能看视频，只能看帧；每个节拍后 0.3 秒取一张标了 t= 的图，逐张对清单（该碰的碰上、没有穿透、面板数字与姿态一致、标签不盖住被标注的部件），放大看过渡再修，直到一整轮找不到问题；最后用 sheet.mjs 把成片摊开再读一遍，看编码器实际写了什么。它不给「通过了」的自动判定，给的是一套让人逐帧看的工序。

05 · 冷思考

项目自己写的第一条规则，否定了它的用法

先质疑最大的那个数字。2870 星、440 个 fork，配 2 次提交、0 个 release、10 天没推代码，issue 区开着挂 9 条；而仓库体积的大头是 3 张换过一次的演示 gif。把它读成「一个被持续维护的 3D 模拟器框架」没有依据。更具体的一击是：首页那三只机器生物不在 sims/ 里，作者换的是首屏观感，不是可运行的东西。星标买的是「把任意机器拆开给你看」这句话和那三张动图，不是这套代码被反复验证过。

第二处矛盾更该停下来。README 让你 Ask Claude Code in plain words，示例就是一句「给我做台能拆的四冲程摩托发动机」；SKILL.md 七条规则的第 1 条却写 Start from a reference, never from imagination，并直说 Machines invented from a sentence come out generic every time。两句话出自同一个仓库，指向相反的做法。按 README 那句去用，得到的正好是作者自己判定「每次都很泛」的那类结果；要按规则 1 用，你得先备好剖视图、真实尺寸和逐帧对照的参照物。一句提示词就能出片是入口话术，不是这套规则承诺的效果。

第三处是门槛。它是个 Skill，却不只是一个 SKILL.md：Node 20+、npm 依赖、playwright 装 Chromium、three 与 esbuild，出片再加 ffmpeg 与 Python 3；规则里还默认你有集显可测、能调 shader（预热、质量分档、GTAO 与 bloom 的坑）、能读懂逐帧静图。1 MB 页面上限、集显 60 fps 实测、25 秒交还控制权这些数字都很讲究，但它们把成本放在「生成之后」——生成只是开始，验收要一个人对着静帧表跑完整轮。文档也承认这一点：Never report a machine as done without reading sheets of the current render。整套流程里没有一步是替你判断「这机器对不对」。

所以值不值得看，不看 2870 星。如果你要的是「问一句话就得到能拆的 3D 机器」，README 与 SKILL.md 第 1 条已经互相把话说完了；如果你要研究的是怎么让 agent 产出的可视化不漂——一个输入驱动一切、面板与姿态读同一个函数、render(t) 保持纯、画面与配乐共用一根 timeline、每条审美判断配一个可核对的数——这套约束比任何「3D 模拟器模板」都值钱。先把「屏幕上每个数字从哪来」钉死，再谈让它出图；这句话比那三张 gif 更该被抄走。
