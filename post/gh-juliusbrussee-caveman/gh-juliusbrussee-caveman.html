01 · 这件事

12.1 万星的项目，把「65%」从统计口径里划掉了

caveman 不是新 agent，它插进你已有的 agent，改写回复的措辞，再可选地压缩它读到的内容。 JuliusBrussee/caveman 创建于 2026-04-04，Apache-2.0，主语言 Go，文档站在 docs.caveman.so。

核对日 2026-11-18，仓库 121,188 星、7,083 fork，当天 07:28 仍有推送。未结条目 100 个，搜索接口拆开是 66 个 issue 与 34 个 PR，不能读成 100 个缺陷。

02 · 核心机制

说话和读文件是两块石头，可以只装一块

skill 只改输出；要改输入，得另装本地 proxy 与 engine。product-model.md 把路径分成两层，本地使用都不需要账号，只有托管命令要登录。

  • Skill / hooks / plugins：让回复少寒暄，代码与报错照原样输出。
  • CLI：安装组件、启动 agent、提供本地命令，连接可选的托管功能。
  • Engine：识别载荷形状、套用压缩变换、估算 token、存放可恢复原文。
  • Local proxy：把 provider 请求过一遍 Engine，并在本地 SQLite 记用量。
  • Connected commands：需要账号，才能访问托管项目与网关。

输出规则取自航空维修手册的 ASD-STE100：一句一意、最多 20 词、主动语态。not、never、no、only 与数字单位不许丢，代码、命令、路径、报错逐字保留。

有损压缩走固定四步：先把原文字节存进本地 CCR，再给模型一个短版本，附一个可取回原文的句柄；存储、解析或体积检查失败就原样透传。原文始终留在磁盘上，agent 需要时能自己取回。

它不重写你的提示词。README 引 Adobe 的结论：把用户提问也改成 caveman 风格会让答案变差，所以规则只作用于回复侧。

文档还定义了四种证据标签：inferred 是本地估算，benchmark_counterfactual 是配对基准，verified 只能由托管侧产生，本地工具不能自己发出「已验证」。

INSTALL.md 列了约 30 个 agent 的入口，但 auto-activate 一栏多数写着 No；Codex 用 $caveman 而不是 /caveman，脚本模式默认关闭。

04 · 怎么用

从最小的一块开始，先量自己的账单

六块石头都有独立开关，默认全开不是必须的。caveman status 看当前状态，caveman off browse 只关网页压缩那一块。

目标最小路径
只要回复短一些npx skills add JuliusBrussee/caveman -g，不装 proxy
可恢复的本地压缩caveman <agent>，原文留在本地 CCR 存储
只要原样计量caveman wrap --off <agent>
接到自己的应用改 provider SDK 的 base URL，用 @caveman-ai/sdk

完整安装是 npx @caveman-ai/cli@latest，CLI 要 Node.js 22.13+。npm 12 上直接跑 git 包得加 --allow-git=root，否则会报 EALLOWGIT。

指令按宿主不同：Claude Code 用 /caveman，Codex 用 $caveman；claude -p 与 Agent SDK 默认关闭，要用 CAVEMAN_DEFAULT_MODE 打开。

Blocks 与 browse 是可加可减的小石头。README 的例子里，200 行表格用 Browse 是 121 token，Playwright 快照是 15,704；但小表单反而差 2.3 倍。Blocks 公开的三个用例中两个赢，grep-defs 输给裸 grep。

不要直接采用仓库估算。caveman trial -- claude 做同任务 A/B，再对照供应商账单页；HONEST-NUMBERS.md 给的判据只有一句：同任务更贵，就为这个负载关掉。

  • 只担心遥测：首次交互命令会打印告知，caveman telemetry off 或 DO_NOT_TRACK=1 可长期关闭。
  • 只不想路由：不登录就没有 Auto；已登录用 caveman off routing。
  • 网关模式不想过云：caveman providers cloud off，请求回到自己的 key。
05 · 冷思考

能省输出不等于能省账单，更不等于能放心路由

最硬的质疑是：agent 会话的钱主要花在输入与缓存重读，一句输出风格规则碰不到。LemonCrow 的原始数据里，初始缓存上下文每轮还多了 1,532 token。

  • #145：简短编码问答出现净亏损，固定规则开销超过省下的输出。
  • #506：按请求计费的 Copilot，答案再短也是同一次请求，省不了额度。
  • #550：一次 Cursor A/B 是 430 万对 100 万 token、墙钟时间翻倍；作者写明不可复现。
  • 仓库承认 evals/score_fidelity.py 已存在，但没有提交经过评审的保真快照，所以不发布质量等价结论。

Auto 也要单独算账。0.46 倍主要来自把 Opus xhigh 降到 medium，不是换了便宜模型；85 对任务只差 0.5 个百分点，区间约 ±7，原始轨迹不在仓库。

隐私边界要读 SECURITY.md：选 Auto 会把最近一次提问原文（最多 128 KiB）和上一问发给 Caveman Cloud，免费层可能留存；托管网关模式下整条请求连系统提示与代码都过云。

路由发往云端的还有 11 个 agent 头字段，Codex 的子代理与会话标识最长可到 16 KiB。托管网关会把仓库 owner/name 与分支名放进 x-cave-tags，分支名可能带客户名，可用 CAVEMAN_WORK_TAGS=0 关掉。

CLI 遥测默认开启：命令名、token 增量、随机安装 ID、系统与 IP 都会上传，IP 90 天清除、事件 13 个月删除。项目说不含提示词与代码，但它是「假名」而非匿名。

许可证也有边界：README 写明整个仓库是 Apache-2.0，但「Caveman」名称与石头 logo 属于 Julius Brussee 的商标，不在这份授权里。

结论不是别装。把 skill 当一个可随时关掉的格式开关，用供应商账单验；proxy 只在你真有 60 KB 级工具输出时开；Auto 当独立实验，别和省 token 算成一笔账。
