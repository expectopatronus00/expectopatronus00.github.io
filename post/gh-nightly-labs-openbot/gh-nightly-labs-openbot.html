6,959 星、每天一版：OpenBot 开源止于 0.1.11

6,959 星、10 天 11 版，OpenBot 把 12 个 agent 收进桌面窗口。但 LICENSE 是 PolyForm Noncommercial 1.0.0，商用要另买；GitHub 接口只返回 NOASSERTION。

01 · 这件事

6,959 星，一个让多个 agent 同住一台电脑的桌面应用

OpenBot 把「多个 AI 队友同住一台电脑」做成了桌面应用，但它的两个自我描述都得打折读。仓库 2026-08-12 创建，核对时 6,959 星、699 fork，主语言 TypeScript，最近一次推送就在 2026-11-11。

它给每个 agent 一个独立工作目录与会话，把 FIFO 队列、受管文件传输、内嵌浏览器和 agent 间消息收进同一个窗口。README 第一句写的是「local-first desktop workspace for persistent AI teammates」。

作者对节奏也很自信：同一份文档写着「ready for production use」和「A new release ships almost every day」。最近十个正式版从 11-01 排到 11-10，10 天 11 版，每版 31 个资产。

两个词容易被读错。local-first 不等于 offline-only，source-available 也不等于 open source。

这两句不是我的概括，README 分别写了「local-first, not offline-only」和「OpenBot is not free software」。

下面是仓库身份，全部来自 api.github.com 的仓库接口，罗列成表而不是塞进一句话。

02 · 核心机制

它不造模型，只给已装好的 CLI 派活、排队、传文件

整套设计只有一个支点：agent 是外来的，OpenBot 负责给它们安排工位和交接。README 列了 12 个受支持的 provider，本地的 Codex App Server 与 Claude Code 直接接入，其余 10 个通过 ACP 接入。

所谓「本地优先」指的是数据、会话与工作目录落在本机磁盘，不是不联网。README 逐个点名了各家 CLI 连向谁，这里照搬成表。

provider连接对象接入方式
Codex App ServerOpenAI本地 App Server
Claude CodeAnthropic本地 CLI
Grok CLI / GeminixAI / GoogleCLI
Cursor / Cline / Kimi各自服务CLI 或 ACP
Devin / Copilot / Mistral / Hermes各自服务CLI 或 ACP
自定义端点Ollama、LM StudioOpenAI 兼容 / ACP

工作落点写得很具体，三个目录各有分工，路径与用途罗列成表。

路径用途
~/OpenBot/Agents/<agent-id>每个 agent 一个工作目录与会话
~/OpenBot/Sharedagent 之间显式共享的文件
~/OpenBot/Shared/Transfers受管快照，每份带 .openbot-transfer.json 清单

那份清单记归属、收件人、大小和 SHA-256，文件传输由应用托管，不是直接扔进共享目录。

任务侧是 FIFO 消息队列，带暂停、恢复、取消与崩溃安全持久化；共享频道再叠一层，一个任务只有一个 owner，配 Stop、Resume、Reassign、Archive、Restore 五个控制。

README 的「What works」清单可以归成四层，功能虽多，边界其实清楚。

  • 会话层：独立工作区、可编辑人设、长线程自动压缩上下文
  • 协作层：FIFO 队列、agent 间消息与回复、共享频道与委派
  • 工具层：常驻内嵌浏览器、可选 Computer Use、受管文件传输
  • 账号层：一次性邮件码登录、本地数据导出、隐私安全的诊断导出

内嵌浏览器看着危险，实际用独立的沙箱 Electron 会话，碰不到 window.openbot 和受管附件。Computer Use 靠发行包自带的 cua-driver 二进制，三平台都有，只有 macOS 需要屏幕录制与辅助功能授权。

03 · 关键细节与数据

最硬的反差在许可证，API 说不确定，文件说非商业

这次 GitHub 的 NOASSERTION 不是识别器偷懒，是这个许可本来就不在常见开源清单里。

4,732 字节的 LICENSE 首行写着 PolyForm Noncommercial License 1.0.0，package.json 的 license 字段也写 PolyForm-Noncommercial-1.0.0。

与 11-10 那篇 worktrunk 正好反过来：那份是 MIT OR Apache-2.0 双许可写在同一文件里、机器没读懂；这份是作者明确选了非商业许可，README 直说「OpenBot is not free software」。

04 · 怎么用

装之前先接受一件事：首次同意之后不再逐次请示

最短路径是下载对应平台的发行包、装一个 agent CLI，其余按需再加。发行版不需要 Bun 和 Node.js，这两个只在从源码开发时才成为前置条件。

平台发行包系统要求
macOSarm64 / x64 dmg13 或更新，Apple silicon 或 Intel
Windowsx64 exe10 或更新，x64
LinuxAppImagex64 或 arm64
源码开发git clone 后 bun run devBun 1.4.2 + Node.js 24

Linux 有两处坑：Ubuntu 23.10 起、Debian 13 起受 AppArmor 限制，不装随包附带的 profile 会在启动时直接退出；远程桌面只在 X11 会话下可用，Wayland 不行，arm64 AppImage 也不带它。

真正要读的是 README 顶部那条 [!WARNING]：agent 以 danger-full-access 和 approvalPolicy: never 运行，能读写文件、跑命令、联网、控制内嵌浏览器，首次启动同意后没有逐次确认。

作者把话说得很直白：「Full local access is an explicit current product decision, not a security boundary.」换句话说，工作目录只是组织方式，不是隔离边界。

README 自己给的风险动作，按优先级排成清单更实用。

  • 只运行你信任的 agent 与任务，并保持备份
  • 用前读一遍 SECURITY.md，别把凭据或私密文件放进公开 issue
  • 不要用 --no-sandbox 启动，那会拆掉渲染器与整台机器之间的边界
  • 较旧的 Windows 包没有代码签名，先核对校验和或 GitHub 构建证明

几处硬限制值得先记住，它们都会在实际使用时撞上。

项目限制
单个附件100 MB
单条消息250 MB、最多 10 个文件
一次性邮件码10 分钟过期，只存哈希
账号 API跑在 Cloudflare Workers 与 D1 上

商业使用按 README 去 Settings → Billing 买 Starter 或 Team 授权，或联系 licenses@openbot.run。0.1.11 及之前仍按 Apache-2.0 可用，但那是仓库创建初期的一批老版本，不是当前分支。

05 · 冷思考

该问的不是好不好用，是这 6,959 星里有多少会留下来

星标和订阅差了三个数量级，这个比例比功能清单更值得看。19 个订阅者对 6,959 星约合 1:366，前者是愿意持续收更新的人，后者多为路过点一下；而「每天一版」意味着持续收更新本身就是一份负担。

贡献也高度集中。46 位贡献者合计 3,406 次提交，NorbertBodziony 一人 1,768 次占 51.9%，前三名合计 3,232 次占 94.9%，机器人账号只有 20 次。

commit 接口的末页显示 3,407 次，与贡献者接口合计的 3,406 差 1 次，是分页与合并提交的口径差异，不必当成矛盾。

再看那 1,403 条未结 issue。其中 1,024 条由 openbotgit[bot] 开出，占约 73%，649 条带 from-app 标签。它们来自应用内上报器，不是 1,403 个人在排队等回复。

最新一条 #7543 的正文末尾写着「An agent wrote this text, and the user approved it before it was sent.」——文字由 agent 代写、用户点确认后自动开单。这类积压衡量的是上报门槛，不是维护崩没崩。

还有一处自述值得质疑：README 说「ready for production use」，版本号却是 0.67.1，未到 1.0，而且 10 天里发了 11 版。每天一版的同时，provider CLI 也在启动时与每小时各检查一次更新，装的是上游最新版。

非商业许可、商业授权与 CLA 三件套摆在一起，公司想把它嵌进内部流程，得先过法务；个人拿来管自己的 agent，则要把 danger-full-access 当成「把整台机器交出去」来对待。本地优先说的是数据放哪，不是权限关在哪。

所以我的判断是：个人在一台专用机器或隔离账户上跑信任的 agent，它值得试；要进团队或商业流程，先确认许可、锁死版本，再把全盘权限当部署前提写进文档，别把它当默认设置。也别把 source-available 读成可以随便商用。
