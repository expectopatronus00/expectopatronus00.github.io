3.1万星、737个版本：qwen-code 的开源带着前提

QwenLM/qwen-code 有 30,934 星、737 个 npm 版本，README 写「开源、无厂商锁定」。但起步先要 Plus/Pro 订阅或 API Key，遥测默认开启，daemon 默认无鉴权。开源与默认路径是两件事。

01 这件事

Qwen Code 把多协议编码 agent 全盘开源，但 README 里最醒目的那条路通向订阅账号。

02 核心机制

协议层确实开放：四套认证通道、多家模型接口和六种界面都能换，推荐路径却写得很具体。

README 把「Open-source, inside and out」和「No vendor lock-in」并列，同时列出 OpenAI、Anthropic、Gemini、Qwen 四套 API，以及 Ollama、vLLM 等本地模型，声明可在运行时切换。

认证文档列了四种方式：Qwen 账号订阅、阿里云 Coding Plan、自有 API Key、Vertex AI。旧的免费 Qwen OAuth 额度在 2026-04-15 停止；快速开始直接指向 Plus 或 Pro 订阅，或者自己配置 provider。

这决定了怎么读「无锁定」。换 provider 的动作在配置层，clone 之后默认要做的第一件事仍是选账号或填 Key。可换，不等于默认不挑。

04 怎么用

按文档默认值用之前，先改三处：认证方式、遥测开关和 daemon 的鉴权。

  1. 认证：会话内运行 /auth，选订阅、阿里云 Coding Plan、自有 Key 或 Vertex AI。
  2. 遥测：配置 usageStatisticsEnabled: false，或设 QWEN_USAGE_STATISTICS_ENABLED=false，后者优先。
  3. daemon：默认监听 127.0.0.1:4170 且无 bearer；共享主机要配 QWEN_SERVER_TOKEN 加 --require-auth。
  4. 浏览器：Chrome 扩展可读标签 URL、页面文本、截图、cookie 与历史搜索，结果可能发给会话所选的 provider。

隐私文档写明，用量统计对四种认证方式默认开启，事件发往阿里云 RUM 采集端点，和 provider 自己按隐私政策收集的数据是两条链路。它也明确列出不采集代码内容、prompt、回答与个人信息。

daemon 文档把威胁模型写得更直白：回环端口上的任何本地进程都拿到完整 API 权限，包括以 daemon 用户身份执行代码。文档还标了一条已知限制，某条纯成本路由没有 per-route 限流，本地客户端可以刷 token。

贡献路径要先看分支。main 的 CONTRIBUTING.md 收带 issue 链接的小 PR，超过约 1,200 行建议拆分；v1.0.0-preview 的 README 却写暂停接受社区 PR，预计 2026 年 12 月后开放。

05 冷思考

开源的是代码和协议，默认指向的是订阅、阿里云遥测和一个信任本机的 daemon。

README 的提示说项目用自家 agent 和模型提 issue、交 PR、审代码、跑测试，并署名「Powered by the community, driven by AI」。预览分支却暂停社区 PR 到 12 月后。两句放一起看，社区更像反馈者，而不是合并者。

质疑点能核到的事实判断
无厂商锁定快速开始首选 Plus/Pro；自有 Key 仍默认遥测到阿里云 RUM切换在配置层，默认成本在隐私层
本地即安全回环 4170 无 bearer，本地进程可用完整 API共享开发机先加 token 再启动
基准在进步七版相差 1.40 个百分点，最早一版最高，表格止于 0.22.0更像稳定性证据，不是升级曲线
迭代快等于好用737 个版本、394 个 nightly、9 个实验 dist-tag复现问题必须钉住版本

这些都不否定它开源。Apache-2.0、四种认证、多协议切换和写出来的威胁模型都在仓库里，比只喊口号的项目更可查。口号讲的是能力边界，默认值讲的是产品边界。

只看那张 SWE-bench 表，容易把 1.40 个百分点当进步曲线。最早一版分数最高，末版不是最高，七版共用同一套配置，量的是同一模型下 harness 的波动。拿它当稳定性证据，比当「越新越强」更站得住。

要试就按上一节改完三处默认值：换到自己的 provider，关掉遥测，给 daemon 加 token。这个项目的价值，是把 27 个工作区、110 个脚本和实验分支都摊开给你看；开源给了你改默认值的权利，但在你真的改之前，实际使用的仍是它设定好的那条路径。
