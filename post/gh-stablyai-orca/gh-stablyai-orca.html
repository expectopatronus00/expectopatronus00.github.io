01 这件事

13 万星的开源项目，把「并行跑一群 coding agent」做成了桌面应用。stablyai/orca 在 2026-03-17 建库，MIT 许可，主语言 TypeScript，官网 orca.dev。核对时有 130,475 星、8,304 fork，11 月 20 日仍在推送。

它描述的能力很直接：把大任务交给一个协调 agent，由它拆活，在每个 worker 独立的 worktree 里并行执行，再把结果汇总回你面前。Chat 界面和原生 CLI 之间可以来回切，上下文不丢。

README 自称「100x builders 的 AI 编排器」，列出 12 张功能卡，覆盖聊天与终端、agent 编排、异地运行、移动端、diff 审阅、Git 集成、分屏等。它还准备了 8 种语言的 README 与 star-history 曲线，社区入口挂在 Discord、X 和微信群。

Windows 版的安装包签名由 SignPath.io 提供、证书来自 SignPath Foundation。但仓库描述里藏着一句关键限定：用的是「你自己的订阅」。开源的是调度台，不是模型账单。

02 核心机制

它调度的是 worktree 和进程，不提供模型。Orca 本身是一个 Electron 桌面壳加 CLI：协调 agent 把任务拆开，worker 各自在隔离的 worktree 里跑 Claude Code、Codex 或其他终端 agent，避免互相改同一份文件。

  • Chat 或终端：同一个会话在图形界面和原始 CLI 之间迁移，不丢上下文
  • 编排：协调 agent 拆任务、开 worker、汇总结果
  • 异地运行：本机、SSH 远程主机，或给 worktree 单独开一台云 VM
  • 移动端：手机收通知、回消息，电脑睡眠后 worker 继续跑

README 用功能卡把能力分成几组，下面是其中与「并行」直接相关的几项。

能力它做的事
Orchestrate Agents协调 agent 拆活、起 worker、收结果
Parallel Worktrees任务拆进隔离环境，多个 agent 并排跑
Review AI Output在 diff 的具体行留注，送回 agent
Git Integration从 diff 起草 commit 与 PR，回灌失败检查
Orca CLI命令行建 worktree、起 worker、驱动浏览器

README 写明支持「任何 CLI agent」——只要能在终端跑，就能在 Orca 里跑。它逐一点名 34 个 agent：Claude Code、Codex、Grok、Cursor、Copilot、DeepSeek Harness、Qwen Code、Kimi、Cline 等都在列，末尾还加了「任意 CLI agent」。

审查环节能在 diff 的具体行留批注、送回给 agent；commit 和 PR 文案从 diff 起草，失败的 CI 检查与评审意见也能回灌。这套闭环是它区别于普通终端复用器的地方。

其余功能卡走的是「把 IDE 该有的东西搬进来」路线：Design Mode 在内置浏览器里点中元素就复制 HTML、样式和选择器，粘进 agent 对话；Split Anything 把 agent、终端、浏览器和 diff 拖成分屏。

还有一批配套能力写在 README 的「Also in the box」里：拖文件到 agent 输入框、跨仓库跳转、图片与 PDF 预览、跑 iOS 模拟器和安卓模拟器让 agent 自己验收、语音听写，以及定时执行的 automations。

04 怎么用

桌面端开箱即用，模型账号得自己准备。安装走 orca.dev 下载页，或直接从 Release 拿安装包；macOS 用 Homebrew 时需要写全名，裸写 orca 会装到无关的 Plotly cask。下面是核对到的几条路径。

平台安装方式
macOSbrew install --cask stablyai/orca/orca 或 dmg
macOS RCstablyai/orca/orca@rc，与稳定版冲突需先卸载
Windowswindows-setup.exe，签名由 SignPath 提供
LinuxAppImage，或 AUR 的 stably-orca-bin
CLI / 移动端orca 命令；iOS App Store、Google Play 或 APK

仓库自带的 opencode.json 把绝大多数权限设为 allow，只对 *.env、外部目录和 doom loop 设为 ask，并把标准 TypeScript LSP 关掉、换成本仓的定制 LSP。想让 agent 用上 Orca 的命令行能力，可以装 orca-cli 技能。

GitHub 与 Linear 任务原生接进侧栏，可以为每条 issue 直接开一个工作区；手机端配对后，agent 需要输入时会推送通知，你在手机上回复即可让它继续。定时任务还能做夜间依赖升级、每周 triage 和 flaky-test 清扫。

README 准备了 8 种语言的版本：中文、日语、韩语、西班牙语、法语、葡萄牙语、土耳其语和俄语。官网按平台给出下载入口，Release 里能直接拿到 macOS 双架构 dmg、Windows 安装包和 Linux AppImage。

它是 YC 背景的项目，README 的 topics 里带着 yc-backed 标签；社区支持除 Discord 与 X 外还提供微信群二维码，反馈走 GitHub issue，隐私与遥测说明放在 orca.dev 独立文档里，可选择退出匿名使用数据收集。

真正的前提是订阅：README 的「Usage & Accounts」用来看你自己的 agent 额度用掉多少、何时重置，并支持多账号切换。Orca 收的是编排费，模型账单仍记在你的 Claude、Codex 或其他 CLI 账号上。

05 冷思考

「支持任何 CLI agent」是企业愿景，「能当 bot 用」要一条条接。11 月 20 日新开的 issue 45532 写着：Kiro 的 Chat 支持还没进，bot 因此跑不起来；对应的 PR 45533 仍需补一套 ACP steering 文档机制，且是 draft。

那条 PR 的细节很具体：要让 bot 在 Kiro 里带上常驻指令，得在 session/new 塞一份 _meta.kiro.steering，并依赖 kiro-cli 3.1.0 才有的字段；老版本 2.29.1 没有该字段，只能拒绝启动。作者还在 PR 里写明「用 Claude Opus 5.5 写成」。

这类适配成本不写在 34 个 logo 里。README 把「能在终端跑」等同于「能在 Orca 里跑」，但移动端 bot 需要原生 chat 通道，缺一环就只桌面可用。换一个冷门 CLI，可能要等社区提 PR。

另一笔账是规模。217 条 scripts、132 个开发依赖、一天两个 Release，意味着这个项目自己就是一支高速运转的工程队。普通团队把它当基础设施，就要接受跟版和 breaking change 的成本。

更现实的问题是：未结条目两个口径差了 3,424，连「到底有多少 bug」都读不出唯一答案。星标增长说明关注度高，不说明 5,305 个条目里的处理速度。

还有一个容易被忽略的依赖：项目自带 .mcp.json 只挂了一个本地组件夹具服务，而 opencode.json 默认对外部目录与环境变量读取设为「询问」。这些细节不是缺陷，但说明它默认按开发者工具而非普通消费者产品设计。

所以判断很具体：如果你手上已有多个 CLI agent 订阅、痛点是「同时开几条、谁改了什么」，它值得装；如果你期待一个开箱即用、替你付模型钱的统一入口，README 第一行就写明了不这么做。
