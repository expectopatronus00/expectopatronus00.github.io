01 这件事

26,165 星装得下 85 个技能、16 条命令和 433 条可点开的引用，却装不下一句「它能挖到洞」的证明。

02 核心机制

四层结构把它定义成查阅与流程手册，不是自动扫描器；越界判断交给规则和门禁。

  • Think：方法论与红队心态两个技能，给出非线性流程和判断纪律。
  • Hunt webapps：58 个 hunt-* 技能，按漏洞类给检测模式、载荷与绕过表。
  • Hit the perimeter：企业身份与基础设施链路，覆盖 M365、Okta、vCenter。
  • Ship it：分级验证、报告模板与证据脱敏，提交前过 7-Question Gate。

技能按主题描述自动触发，不必念名字。docs/skills.md 是生成物，把 85 个技能分五类；这是数得清的部分。

README 说收录 5 种 harness，但知识层可以搬过去，斜杠命令和 hunt 引擎只在 Claude Code 里保留。换句话说，跨宿主复用的是文档，不是执行路径。

SECURITY.md 把「scope enforced in code」讲得更具体：验证技能的第 3 问查目标是否在范围内，第 2 问查影响是否列入项目接受清单。越界时默认降级或要求补链，不鼓励继续验证。

03 关键细节与数据

433 条引用可以逐条点开；681 条模式是作者自己维护的口径，仓库里没有可复算的清单。

docs/disclosed-reports/ 下有 36 份按漏洞类命名的模式库，加一份说明共 37 个文件、416,261 字节。逐个提取其中的 HackerOne 链接并去重，得到 433 条，与 README 的「433 now individually cited」一致。

681 的口径还会打架：docs/architecture.md 写「Total disclosed reports curated: 681」，而研究脚本说明与 CHANGELOG 都把它叫 pattern-count。同一页并列两个数字，读者很容易当成同一分母。

CVE 覆盖也要拆开。docs/cve-coverage.md 的快照停在 2026-05-15：1,592 条 KEV 中索引 91 条，180 天回看有 53 条在范围内，已索引 0 条、缺口 53 条。README 说「每周刷新」，但仓库只有一份 yml.template，没有启用的对应 workflow。

04 怎么用

按授权范围装，按安装方式分清哪些能力真的跟着走。

  • 插件安装：先加 marketplace 再装 claude-bughunter@elementalsouls，技能与命令带命名空间，不往 ~/.claude/ 复制文件。
  • 复制安装：clone 后跑 scripts/install.sh 或 install.ps1，写进目标宿主技能目录。
  • 多宿主：加 --all --burp-mcp，把 Burp MCP 一起接进已安装的宿主。
  • 命令行：pipx 安装后用 cbh 跑 recon 与报告流程，不依赖模型做范围判定。

授权是硬前提。SECURITY.md 只覆盖外部攻击面，明确排除内网 AD、C2、后渗透与规避检测。README 还提醒 Anthropic 的实时防护会默认拦下漏洞利用类请求，授权工作应走免费的 CVP 申请。

想验证效果，可以用仓库自带的 eval：先起本地 Juice Shop，再跑 python3 eval/run_eval.py。脚本用开技能与关技能做消融，模型保持不变，目标每次重置到未解题状态。

那套评测不进 CI。BASELINE.md 写明它需要 Docker、Burp 和已登录的 claude CLI，结果文件被 gitignore，只把汇总表提交进仓库。

05 冷思考

仓库唯一一份实测基线是 3 道题打平，技能开启后更慢也更贵；「battle-tested」没有对应的成功率数字。

条件解出中位轮次中位成本
关技能3/32$0.178
开技能3/33$0.254
差值+0+1+$0.076

BASELINE.md 自己解释这是天花板效应：Juice Shop 的解法早就在训练数据里，curl 就能答完。作者也写明 PortSwigger 实验室才可能测出技能差，但需要账号和手工启动实例，目前半阻塞。

更值得盯的是版本边界。最新发布仍是 06-05 的 v2.1，说明写的是 51→71 skills；当前 main 已有 85 个技能，84→85 和命令扩到 16 条都挂在 Unreleased。同期 CHANGELOG 记录了一组范围判定的 fail-open 修复，包括 IPv6 非规范写法绕过拒绝规则、URL 主机被重写后把请求发到范围外。

这些修复都在同一段 Unreleased 里。按发布版安装与直接跟 main，拿到的不是同一套边界保证。

数据核对
  • 仓库：26,165 星 / 2,689 fork；23 未结 = 5 issue + 18 PR；pushed 11-27。
  • 文件树 512 条目 / 387 blob / 4.80 MB；85 份 SKILL.md、16 个命令文件。
  • 36 份模式库去重得 433 条 HackerOne 链接；681 为自述模式数，1,122 为 report_count 合计。
  • 评测 3/3 打平，中位轮次 2→3、成本 $0.178→$0.254（2026-08-25）。
  • KEV 快照 2026-05-15：53 条范围内、0 已索引、53 缺口；刷新仅有模板。
  • v2.1（06-05）写 71 skills；85 技能与范围修复都在 Unreleased。
  • 385 提交 / 21 账号，前三 305 次（79.2%）。
核对时间 2026-11-28。

判断是：把它当成一份可回溯、可引用、能按主题调阅的红队查阅库很合适，尤其适合已确定授权边界、愿意自己跑验收的人。想用星标数替代效果验证，或把 v2.1 当成当前 main 的等价物，都会高估它。
