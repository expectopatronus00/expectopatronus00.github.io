Linux 清除 history 记录的几种方式

history 命令看到的是内存里的会话历史，磁盘上还有一份 ~/.bash_history。想真的清干净， 这两处都得处理。这篇把几种常见做法和它们各自的漏洞列一遍。

原创 2024-02-23 运维与部署
01 · 先分清两个地方

内存里的会话历史，和磁盘上的历史文件

bash 把历史记录同时放在两个位置：一是当前 shell 进程内存里的会话历史，history 命令读的就是它；二是退出时 写入的 ~/.bash_history 文件。只清内存，退出 shell 时又会被写回磁盘；只删文件，当前会话里的记录还在。

所以任何「彻底清除」的操作，本质上都是这两步的组合。

02 · 清空当前会话

只清内存，不碰磁盘

如果只想让当前终端会话里的命令不再被翻到：

history -c export HISTSIZE=0

history -c 清空当前 shell 的历史缓存；export HISTSIZE=0 让之后的命令不再被记入。 注意这两个 都只影响当前这个 shell 进程——新开一个终端，历史还是从文件里读出来的。

容易忽略的一点：HISTSIZE=0 是临时环境变量，关掉这个终端就失效了。想持久化要写进 ~/.bashrc，但那样连你自己也查不到历史，一般不建议。
03 · 删除指定行

只想抹掉其中几条

history -d <行号> 删除内存里的某一行。想批量删，可以先把要保留的写回文件，再重新加载：

# 只保留最上面 3 条，其余全部丢弃 history | head -n 3 > ~/.bash_history history -c # 清空内存 history -r # 从文件重新加载

这个组合的逻辑是：先把想留的写进文件（覆盖掉原来的），再清内存，再从文件读回来。顺序不能反——先 history -c 再重定向的话，history 命令输出已经是空的了。

04 · 彻底删掉文件

删 .bash_history 本身

rm ~/.bash_history # 当前用户 history -c # 同时清内存

文件删掉后，bash 在下次退出时会重新创建一个空的。所以删文件这一步要在清完内存之后做，否则退出时又把内存里的内容写回来了。

Shell 历史文件位置
bash ~/.bash_history
zsh ~/.zsh_history
fish ~/.local/share/fish/fish_history
05 · 清不掉的痕迹

history 之外还有别的记录

这一节比上面几节都重要。清 history 只解决了自己终端里的那一条线，服务器上还有别的日志：

  • 审计日志：/var/log/secure（RHEL 系）或 /var/log/auth.log（Debian 系）记登录
  • 进程记账：开了 psacct / acct 的话，每条命令都单独有记录
  • 其他 shell 的 history：su 到别的用户、tmux / screen 里的会话，各有各的历史
  • 命令本身留下的痕迹：写过的文件、连过的端口、数据库里的操作记录
说句实话：在别人的服务器上，清 history 与其说是抹除痕迹，不如说是给自己心理安慰。真要追溯，审计日志和网络设备那一侧都还在。 所以更实际的做法是——不要在别人的机器上执行不该执行的命令。
