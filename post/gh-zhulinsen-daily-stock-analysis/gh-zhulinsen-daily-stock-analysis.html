7.4 万星股票分析系统：零成本不含模型钱

74,205 星的 daily_stock_analysis 把行情、新闻和 LLM 决策仪表盘打包成工作日 18:00 的定时任务。README 说五分钟零成本部署，但文档写明免费行情源不保证稳定、要配模型 Key，插件不自带运行时。

01 这件事

它把「拉行情、喂模型、推报告」打包成定时任务，卖点是工程省事，不是选股更准。

截至 2026-11-24，ZhuLinsen/daily_stock_analysis 有 74,205 星、58,357 fork，2026-01-10 建库、11-24 仍在推送，MIT 许可。最新发布 v3.35.0 停在 11-16，带 6 个资产；44 个未结条目拆成 31 个 issue 和 13 个 PR。

README 把它定义成 A 股、港股、美股、日股、韩股、台股与 ETF 的自选股分析系统：抓行情、新闻、公告与基本面，输出带评分、买卖点位和风险警报的决策仪表盘，再推到企业微信、飞书、Telegram、Discord、Slack 或邮箱。

今日 09:00 的雷达复核没有把它标成 stale：11-14 入池时 80 分，今天星标仍在 7.4 万级，推送日期就是当天。积压超过 7 天，热度没有衰减，按积压最久照常成稿。

02 核心机制

四层都能换供应商，但「零成本」只覆盖了其中不租服务器这一层。

第一层是行情。data_provider/ 有 24 个 fetcher 文件，默认用 AkShare、Baostock、YFinance 等免费源，也能切到 Tushare、Longbridge、TickPlus。README 明说免费源受上游限流、接口变动和网络波动影响，稳定性不保证。

流水线层仓库里可换的实现要不要自己配
行情24 个 fetcher：AkShare / Tushare / YFinance / Longbridge 等免费源免配，稳定源要 token
新闻舆情SerpAPI / Tavily / Bocha / Brave / MiniMax / SearXNG推荐至少配一个
模型Gemini / OpenAI 兼容 / DeepSeek / 通义千问 / Claude / Ollama至少一个 Key
推送企业微信 / 飞书 / Telegram / Discord / Slack / 邮件至少一个渠道

第二层是新闻与舆情：六种搜索服务可配，Stock Sentiment API 只覆盖美股的 Reddit、X 与 Polymarket。README 把搜索源标成「推荐」，因为它直接决定舆情、公告与催化因素的质量，不配不等于没有新闻，只是原始材料更薄。

第三层是模型，第四层是推送，两边都要求至少配置一个服务商。服务器可以省，模型与新闻的账单省不掉；README 首屏的「零成本」说的是借用 GitHub Actions 的 runner，不是所有调用都免费。

策略层是 15 个 YAML 文件，对应均线金叉、缠论、波浪、龙头、情绪周期等，和 README 的「15 种内置策略」正好对齐。Agent 问股可用 AGENT_MODE=false 关掉，多 Agent 编排仍标着实验性。

技能的 dashboard 输出分成四块：core_conclusion 给一句话结论与仓位建议，data_perspective 给趋势、量能和筹码结构，intelligence 汇总新闻与风险催化，battle_plan 落到狙击点和检查清单。仪表盘是四段有字段的契约，不是一段自由文本。

环境模板从 STOCK_LIST、模型 Key、搜索 Key 一直排到 SQLite 重试、回测窗口、调度与 WebUI 认证。它更像一张功能地图：快速开始只要求少数几项，真正能拧的旋钮远多于此。

主仓还带三个应用入口：dsa-web、dsa-site 和 dsa-desktop，分别对应网页、站点与桌面端。八个工作流除每日分析外，还有 CI、镜像发布、网络冒烟、PR 审查、自动打标与过期 issue 清理，它是按产品而不是按脚本维护的。

定时动作写在 00-daily-analysis.yml：cron: 0 10 * * 1-5，即 UTC 10:00、北京时间工作日 18:00。非交易日默认不跑；强制运行与断点续传另有开关。

插件这一层的口径更硬。README 说插件缓存通常只有 plugin/，不自带 src/ 运行时；技能正文要求先定位 DSA 检出、设置 DSA_REPO_ROOT，再 os.chdir 到根目录，否则数据库路径与大盘复盘锁会指向不同文件。

还有一个版本陷阱：技能文档写明 v3.35.0 尚不支持大盘复盘的 send_notification 参数，而它正是当前最新 release。HTTP 接口里个股默认 notify 为 true、复盘默认 send_notification 为 true，省略字段就会真的推送。

04 怎么用

省事的是 Fork 加 Secrets 那条路，插件路线更适合已经跑过 DSA 的人。

  1. Fork 仓库：把分析流程与定时任务一起复制过去。
  2. 填 Secrets：模型 Key、通知渠道、STOCK_LIST 三项必备，新闻源按质量再补。
  3. 启用 Actions：到 Actions 页确认工作流，手动 Run workflow 先验参数。
  4. 看结果：默认工作日 18:00 自动跑，报告进通知渠道，Web 工作台可回看。

本地运行走另一条路：安装 requirements.txt 的依赖，把 .env.example 复制成 .env，再执行 python main.py。调试、空跑与指定股票各有开关，Web 工作台用 --webui 启动，大盘复盘用 --market-review。

入口适合谁前置条件
GitHub Actions不想管服务器的人Fork 仓库 + 三类 Secrets
本地 / Docker要改代码或接本地模型的人Python 3.10+ 与 .env 配置
Agent 插件已有 DSA 检出的人DSA_REPO_ROOT 指向完整仓库

插件安装只要两行：Codex 用 codex plugin marketplace add ZhuLinsen/daily_stock_analysis 再添加插件，Claude Code 用 /plugin marketplace add 再 install。装完不等于能分析，技能会先找已部署的检出，找不到就停下报错。

05 冷思考

项目把工程门槛压低了，但数据、模型与判断的成本一分没少。

第一处是「零成本」的口径。README 同时写着「5 分钟零成本部署」和「至少配置一个模型服务商 API Key」，首屏还挂着两家带专属注册链接的赞助商。准确读法是：Actions 免服务器，模型调用、新闻搜索与更稳的行情源按用量付费。

第二处是市场覆盖。README 说支持六个市场，docs/market-support.md 把日韩个股写成 suffix-only MVP：要手输 7203.T、005930.KS 这类后缀，裸码未命中股票池就按 A 股语义处理；文档明说不承诺实时行情，自动补全种子各约 30 只头部标的。

第三处是推送默认值。对话里只想看报告时，HTTP 个股接口要显式传 notify false，复盘接口要显式传 send_notification false；插件文档还提醒旧检出别回退成不带参数的调用，因为旧签名默认会推送。错一次，报告就发到群里了。

  • 44 个未结条目里 31 个是 issue，功能面仍在快速扩张。
  • 15 种策略是配置模板，仓库没有统一的收益归因承诺。
  • README 免责声明写明仅供学习研究，不构成投资建议。

如果已经有模型 Key、愿意维护行情源，它是一套省事的定时流水线；如果想找免费又准确的买卖信号，README 自己已经否掉了这个前提。判断点不在星标，而在你能否接受工具只负责把信息摆齐，结论仍由自己承担。
