Claude Code 零基础上手指南

从 0 到 1 手把手教你上手 Claude Code——环境配置、基础指令、项目内对话、文件操作、运行代码，以及最常用的调试和代码优化技巧。不需要任何 AI 基础，照着做就能上手。

01 · 先回答两个问题

Claude Code 到底是什么，为什么值得学

在动手之前，先把两件事说清楚，免得你学了半天和你预期的不是一个东西。

第一件事：Claude Code 不是一个写代码的模型，它是一个「在你的代码仓库里干活的智能同事」。你把它装到 VS Code 或命令行里，它能读你的文件、修改你的代码、跑你的命令、并把结果总结回给你。它不是给你一段代码让你复制粘贴，而是直接在你的项目里操作。

第二件事：它的核心价值不是「帮你写更快的代码」，而是「帮你跳过你本来就不想做的那部分工作」。读陌生项目、写重复的 CRUD、改配置、定位 bug、格式化……这类事情以前最耗你的注意力，现在它们是 Claude Code 的主场。

如果你以前没接触过任何 AI 编程工具，Claude Code 是目前对新手最友好的一个——它默认克制、不乱改文件，并在每次做决定前给你清楚的提示。

02 · 三件你在开始前要准备的东西

账号、API Key 和编辑器

在动手之前，你需要准备三样东西，准备好以后后面就没有卡点了。

1. 一个 Anthropic 账号
去 claude.ai 注册账号，支持邮箱和 Google 登录。

2. 获取一个 API Key（可选，但推荐）
如果你打算在命令行里用 Claude Code，而不是只在网页版的聊天框里用，那你需要一个 API Key。登录 Anthropic 控制台 → API Keys → Create Key。保存好，只出现一次。

3. VS Code 或命令行环境
推荐 VS Code，因为它的 Claude Code 插件界面最直观。打开 VS Code 的 Extensions 面板，搜 Claude Code，由 Anthropic 官方发布的那一个，点安装。

三件事做完大概需要 5~10 分钟。接下来你就可以在你的任意一个项目里启动它了。

03 · 第一次启动

在你的项目里打开它

装好以后，在 VS Code 里打开你自己的项目文件夹。这一步很关键——Claude Code 只认识你当前打开的目录，你打开哪个，它就在哪个里面工作。

启动方式有两种，都可以用：

方式 A：命令面板
按 `Ctrl + Shift + P`（Mac 上是 `Cmd + Shift + P`），输入 Claude Code: Open，回车。侧边栏会多出一个面板，里面是 Claude 的对话区。

方式 B：直接用快捷键
默认是 `Ctrl + L`（Mac 上是 `Cmd + L`），按一下同样能打开侧边栏。

打开以后你会看到两部分：上面是对话区——你和它说自然语言的地方；下面是 MCP 工具区——它读文件、写文件、跑命令的地方。这两部分是联动的：你说一句话，它会在下面自己选工具来回答你。

04 · 最常用的 6 条指令

真正值得你记住的其实就这几条

你可以让它做非常多事情，但新手阶段真正值得你背下来的其实只有 6 条指令，它们覆盖了 80% 的场景：

1. 让它读文件
「帮我看看 src 目录下的 main.py，告诉我它在做什么，3 句话以内。」
价值：你刚接触一个新项目时，它比 grep 和自己读省 10 倍时间。

2. 让它改代码
「在刚才那个文件的第 45 行附近加一个参数校验，校验失败时返回 ValueError。」
价值：你给它明确的修改点，它直接在文件里改，不需要你再复制粘贴。

3. 让它写一段新代码
「在 src/utils 下新建一个 format_date.js，接受 'YYYY-MM-DD' 这种格式字符串，返回一个 Date 对象。要包含错误处理和 2 个测试用例。」
价值：把「实现」+「测试」两件事一次说完，它一次给你完整的文件。

4. 让它跑你的项目并帮你看输出
「跑一下 npm test，如果有失败，帮我定位是哪一个测试和哪一行导致的。」
价值：它自己读错误日志再自己总结，比你盯着滚动的终端省很多注意力。

5. 让它帮你改 bug
「用户反馈登录后偶尔会白屏 3 秒。让它帮我定位 src/login.vue 中可能的问题，并给出 3 个修改建议。」
价值：它比你更耐心地逐行读，而且不会被命名和缩进分心。

6. 让它做项目范围内的重构
「把 src 下所有文件里现在用的 moment.js 改成 date-fns，保持对外 API 不变。一步一步来，每改一个文件就停下来等我确认。」
价值：这是它最强的地方之一——跨文件、有约束条件、需要统一规则的重构。

指令越具体，它的产出越好。不要让它「优化一下代码」，让它「把这个函数的参数校验补齐，并写 3 个测试用例覆盖 null / 空串 / 非法日期的情况」。

05 · 文件操作的规则

它是如何看你的项目的

Claude Code 刚进入一个项目时，它看到的不是项目的全部内容，而是：文件结构 + 它主动读过的文件。这意味着你在对话里如果提到它没读过的文件，它会先去读。

作为新手，只要记住 3 条规则：

规则一：提到文件时用明确的路径
写 `src/components/login.vue`，别写「那个登录页面」。后者会让它花时间去猜，而且可能猜错。

规则二：大文件让它只读关键部分
「这个文件太长，只看第 180 到 260 行」——它会按你给的范围去读，省下不必要的 token。

规则三：让它写新文件时指定路径和文件名
它会按你的路径创建文件，不会擅自乱改已有文件。

它在任何一次写文件或执行命令之前都会让你确认，所以你不会在不知情的情况下被它改动代码。

06 · 命令行版本

你不想打开 VS Code 时的第二种用法

除了 VS Code 插件，Claude Code 也有一个命令行版本。适合你在服务器上、或者只想快速用它做一件事的时候使用。

安装：`npm install -g @anthropic-ai/claude-code` 或者对应平台的包管理方式。

启动后，你在终端里会进入一个对话环境。行为和插件版完全一致：你说一句话，它决定用哪些工具，然后做动作并回报结果。

常用的几个内置命令：

@run — 让它执行你说的 shell 命令。
@edit — 让它修改指定文件的指定位置。
@tool — 查看当前可用的工具列表。
@help — 查看帮助。

对新手来说，优先用 VS Code 插件版本（直观、可视化、有确认按钮）；熟练以后再迁移到命令行版本（更快、更轻、更适合脚本化）。

07 · 新手最容易犯的 5 个错误

希望你一次都不要遇到

下面这 5 个错误是我在身边同事身上反复看到的。提前知道它们，可以帮你省下几十个小时的弯路。

错误 1：不给它上下文就提抽象要求
「帮我优化一下项目」是一个几乎一定会失败的指令。你得把它换成「帮我看 src/api.js 里的这 5 个接口调用，抽一个通用的 request 方法出来，并保持返回值兼容。」

错误 2：一次让它做太多事情
让它同时「重构 + 加新功能 + 写测试 + 更新文档」容易让它的注意力被分散。正确做法：分 4 轮，每一轮让它只专注一件事。

错误 3：从不读它给的 diff，直接 Apply
它的每一次改动都会给你一个 diff 面板。新手最危险的习惯就是从不读 diff 直接点 Accept。请你至少扫一眼它改了什么——这是你从它身上学到东西的最好时机，也是防止 bug 的最后一道防线。

错误 4：让它处理敏感信息
不要让它读数据库密码、API Key、或者任何你不想让它发出去的内容。它是纯本地操作，但日志层面你无法 100% 控制。把敏感信息放在它看不到的地方。

错误 5：只让它写新东西，不让它做脏活累活
新手最喜欢让它写新功能——听起来很刺激，但其实它最强的地方是帮你处理重复的、无聊的代码。重构、格式化、批量改接口、写测试。这些事让它做，你做决策，效率提升最明显。

08 · 一个完整的新手练习路线

照着这条路线，1 天就能上手

如果你不知道从哪儿开始练，我给你准备了一条 4 步的练习路线，每一步大概花 30 分钟。花一个下午，你就能熟练到独立用它做你的真实项目。

Step 1（30 分钟）：读项目
挑你自己最近的一个项目。让它「帮我读一下 README 和 main.ts，然后用中文给我讲 3 件事：这个项目是干什么的、启动流程是怎样的、主要目录结构是什么。」——做完这一步，你就知道它读文件的能力有多强。

Step 2（30 分钟）：写新代码
「在 tests 目录下，给刚才那个 main.ts 写一组单元测试，覆盖 3 个主要函数。如果项目里没有测试框架，先建议我用哪个并写一份配置。」——做完这一步，你就知道它写新代码的流程。

Step 3（30 分钟）：改 bug + 运行项目
「跑一下 npm run build，如果有错误，帮我定位，并给我最小改动的修复方案。」——做完这一步，你就体验过它最经典的闭环：读错误 → 修复 → 再跑。

Step 4（30 分钟）：一次小型重构
「把项目里所有直接写死的 `process.env.XXX` 集中抽到一个 `config/index.ts` 里，保持行为不变。一步一步来。」——做完这一步，你就真正掌握了它的用法。

学习它的最佳方式：用它做你自己的真实项目，而不是跟着别人瞎玩一些 demo。从你最近一次让你头痛的任务开始。

09 · 最后一点提醒

它是工具，不是答案

最后，我想给新手一个冷静的提醒：Claude Code 再智能，它也只是一个工具。它不会替你做产品方向的判断，不会替你设计系统的整体架构，不会替你做上线前的最终质量检查。

它真正擅长的是三件事：

1. 降低你了解新项目的成本——它比 grep 读代码更快、更贴近人话。
2. 吸收掉你重复性的编码工作——写样板代码、写测试、做重构。
3. 作为一个永远不会不耐烦的 Rubber Duck——你把问题描述给它，它会帮你整理思路。

如果你能守住这条边界（你做判断、它做苦力），那么 Claude Code 会是你最近一两年里最重要的效率提升工具。

如果你还没有装，今天就把它装到你自己最近的那个项目里，按上面第 8 节的 4 步练一次。第一次体验它自己跑 `npm run build`、自己读错误、自己修的那种感觉，你会回来感谢它的。
