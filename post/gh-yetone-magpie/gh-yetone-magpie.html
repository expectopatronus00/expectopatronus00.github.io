4 万星、90 个 agent：magpie 开源但不收 PR

40,865 星的 magpie 用本地网关接管九十种编程工具的模型选择，三十二家预设、五种路由。说明文档写明：仓库不收外部投稿，反馈去社区，五千零四十四个问题还开着。它不是新客户端，是把账号与配额切换下沉到网络层。

expectopatronus 2026-11-24 约 6 分钟阅读 原创 · AI 编程

01 这件事

它把「换模型」做成了网络层，而不是再做一个 agent；四万星买的是这一个入口。

截至 2026-11-24，yetone/magpie 有 40,865 星、3,736 fork，2026-09-23 创建，主语言 Go，MIT 许可，最近推送 11-24。两个月出头的项目，已经是本地网关类目里最抢眼的一个。

README 的写作很直接：每个 agent 把模型配置写在自己的文件里，订阅只在一个客户端里生效。magpie 把这些差异收进一个菜单栏应用和一个本地网关，让 Claude Code 用 Kimi、Codex 用 DeepSeek、Gemini CLI 用 GLM。

它给出的切换单位很细：不只是模型，还包括账号与配额。一个供应商的额度用完，先换同供应商的下一个账号，再换路由组里的下一个模型；没有备用账号也没有组，错误才会回到 agent。

今日 09:00 的雷达复核没有把它标成 stale：11-14 入池时 85 分，今天星标仍在涨，推送就在当日。积压虽超过 7 天，热度没有衰减，按积压最久照常成稿。

02 核心机制

配置归 agent，流量归网关；magpie 改的是 agent 自己的配置文件，不是把它们圈进一套新客户端。

网关绑在 127.0.0.1 的 3425 端口，同时说 OpenAI Chat、OpenAI Responses、Anthropic Messages 和 Gemini 四种协议，并在它们之间翻译，流式输出、工具调用和推理内容都在转发范围内。

选模型时，应用按 provider/model 列出所有已添加供应商的模型，原子改写 agent 配置，保留注释、顺序和格式。Profiles 把一组 agent 的选择存成一个名字，一次切回「Budget」或「Focus」。

路由模式README 给出的选择规则
smart在有额度的订阅里挑最先到期的那个，减少重置时浪费
order第一个模型答不了再走下一个
rotate每轮换下一个成员
usage优先用得最少的成员
pace按每小时剩余额度最多的账号走，直到重置

路由组可以套路由组，会话在供应商提示缓存还值时继续留在原账号。意图路由再挂一个小模型读每轮对话，把测试导向强模型、把短问句导向便宜模型，决策过程在 Routing 页里可见。

订阅被当成一种 provider：Claude 走本机真实的 claude 二进制并用 MCP 桥接工具，ChatGPT 计划里的模型给其他 agent 用，Copilot、Gemini、Grok 也在列。多个账号可加入同一订阅做故障转移。

隐私遮罩是另一层：密钥、私钥、令牌、邮箱和校验和正确的卡号命中规则后，在请求离开本机前换成占位符，回复里再换回。它默认关闭，需要在 Settings → Privacy 打开；自定义名称、地址、密码可选本机模型识别，模型包约 1.6 GB。

04 怎么用

安装只要一条命令，真正要想清楚的是订阅账号的读取范围和遮罩开关。

  • 从官网下载安装包，或运行 curl -fsSL https://usemagpie.ai/install.sh | sh
  • 在 Providers → Add provider 里选预设填 key，或登录已有订阅
  • 在 Agents 页为每个 agent 选 provider/model，新开会话生效
  • 需要多账号容错时先建路由组，再让 agent 指向 group/...

终端可以走完整流程：magpie provider add deepseek sk-…、magpie claude deepseek/deepseek-v4-pro、magpie quota 看剩余额度，magpie tui 打开终端界面。

开关默认值实际影响
隐私遮罩关闭打开后密钥等只在本地替换；模型看不到真实值
订阅账号发现开启读取 Claude Code、Codex 登录文件和钥匙串；可关闭
本地网络共享关闭打开后每个客户端单独发 gateway key 和限额
每日使用上报默认开设置里可关，或用 DO_NOT_TRACK=1

不想被改动的 agent 可以直接用环境变量接网关：把 OPENAI_BASE_URL 指到 127.0.0.1 的 3425 端口，key 填 magpie；Anthropic 与 Gemini 的对应变量也在 README 里列出。

遮罩有代价：模型看到的是占位符，拿一个令牌问「为什么被拒绝」这类任务做不了，得放进 Never mask。规则误判的现场在 Insights → Masking 里逐条可查，占位符在流式文本和工具参数里都会还原。

卸载命令会把 agent 配置还原再删除安装内容，~/.config/magpie 里的设置默认保留，加 purge 才清。这套可逆性是它比手工改配置文件更值得试的地方。

05 冷思考

MIT 给的是代码使用权，不是参与权；四千多次发版的速度来自一个人，也依赖一个人。

README 一边开放全部源码，一边把反馈引到 Discord，并写明只有维护者能开 PR。5,044 个开放 issue 和 16 个停在十月的 PR 放在一起看，更像一条单向反馈管道，而不是共同维护的社区。

核对位置口径需要自己确认的事
订阅章节把已登录的订阅供其他 agent 使用各平台条款是否允许这种跨客户端调用，README 未讨论
隐私章节无姓名、URL、账号、提示词合作链接点击计数明确「无论设置如何」都会发生
支持列表README 列 90 种 agent应用只显示本机已安装的那些

每日上报的内容列得很细：随机 id、版本、系统、用了哪些 agent 与模型、装了哪些插件，可以用设置或环境变量关掉。但 partner 链接经过 usemagpie.ai 跳转的点击计数，原文写着不受这些设置影响，属于两套口径。

32 家预设和 90 种 agent 是覆盖面，不是兼容承诺。README 自己也说模型名和推理等级来自 models.dev 补全，兼容任意 OpenAI 或 Anthropic 端点只是协议层说法，工具调用差异仍要实测。

发版放在另一个无许可证字段的仓库，主仓徽章指向那里；想审计签名或固定版本，得同时盯两个仓库。4,561 个 release 的粒度也意味着升级很碎，稳定性需求高的环境应先锁定版本再试。

把它当一台可编排的本地网关用，价值很实在；把它当社区项目参与，门槛不在代码而在规则。订阅共享的条款风险和单维护者的节奏，是上车前该自己核完的两件事。
