2570 星的 DSH Go：手机能跑 Harness，但要交出屏幕

2026 年 10 月 25 日建库，第 6 天 2570 星、106 fork、132 个 open issue——dsh-Go 把 DeepSeek Harness 塞进了安卓手机。手机里跑的是 DSH 本体，不是一个远程壳；代价是约 1 GB 运行环境，和一份无障碍权限。

01 · 这件事

6 天 2570 星，一个非官方的安卓客户端

2026 年 10 月 25 日，GitHub 用户 ccch1mneyyy 建了一个叫 dsh-Go 的仓库。到 10 月 31 日，也就是第 6 天，它的数据是 2570 星、106 个 fork、132 个 open issue，Dart + Flutter 写的，AGPL-3.0 协议，仓库体积 323326 KB。

它要做的事，README 第一句就写完了：「DeepSeek Harness 的 Android 客户端。手机上直接跑，也能遥控你电脑上的 DSH。」作者在同一份文档里把关系交代得很清楚：这是社区开发的非官方客户端，和 DeepSeek 官方没有关系；手机上运行的是 DSH 本身，模型请求发给你自己配置的模型提供方，按你在提供方的账户计费。

「手机上直接跑」和「遥控电脑」是两条完全不同的路。前者意味着把 Ubuntu、Node.js 和整个 DSH 运行环境塞进手机，在本地起进程；后者只是个客户端，真正的活还在电脑上干。dsh-Go 两条都做了，这件事本身比星标数更值得看——它没有假装手机能替代电脑，而是承认两边算力不是一回事，然后让你在同一个 App 里切换。

02 · 核心机制

手机里跑的是 DSH 本体，不是一个远程壳

本机模式的实现方式是不 Root、不装 Termux。App 内自带一套 Linux 环境，首次启动时把 Ubuntu、Node.js 和 DSH 运行环境装进去，README 建议预留约 1 GB 空间。默认走 PRoot 兼容启动——PRoot 是用户态的 chroot 替代品，不需要真实 root 权限，就能让程序以为自己待在一个完整的 Linux 里。开发者选项里另有一个「直接启动」，默认关闭，打开后兼容性会变差，回退办法写在常见问题里。

远程模式走两条协议：SSH，或者作者自己做的 DSH Remote。v1.0.4 这一版把选路改成了自动——先试局域网 / P2P，不行退到 TURN，最后回落到 Relay；同时加了网络详情，点连接卡上的路径标签，能看到实际走了哪条路、连接花了多久、可测的往返延迟、以及为什么回落。这个改动看着小，实际解决的是 Wi-Fi 和蜂窝切换时最容易断的那一段，连接质量从玄学变成了可观测的数字。

第三块是手机操控：开启权限后，本机引擎可以读屏、点按、输入。确认分成三档，付款、密码、验证码和系统设置这四类永远交还给你。这里有个容易漏掉的边界——「不打扰模式」要求 Android 14 及以上，并且需要 Shizuku 或自连 ADB，也就是说低版本系统上这个模式直接不可用。

第四块是插件。仓库里有 packages/dsh_client（DSH Web API 的 Dart 客户端）、packages/dsh_remote（DSH Remote 的 Dart 客户端），以及 sdk/plugin-kit 这套给插件作者的工具包，能做出原生工具卡、表单和面板。工具包没发布到 npm，只能在仓库里用。

03 · 关键细节与数据

132 个 issue 和 106 个 fork，说的是两件事

先看比例。6 天 106 个 fork，132 个 open issue，issue 比 fork 还多。常见的开源项目是 fork 一堆、issue 寥寥，因为多数人只是收藏或者改着玩。这个倒挂说明真正装上手机跑的人不少，而且跑出了问题——权限被系统拦、后台被杀、环境装不上，这些都是要在真机上才会暴露的。

再看安装成本。最新版 v1.0.4 在 10 月 30 日 20:20 发布，arm64 的 APK 是 204959893 字节，约 195 MB，发布一天内下载 2585 次。这只是安装包；要在手机上跑本机引擎，还得再加约 1 GB 的运行环境。仓库没有 32 位 ARM 构建，x86_64 版本放在发布说明末尾的「其他版本下载」里，给模拟器用。

授权这块要拆开看：主仓库是 AGPL-3.0，但 sdk/ 和 examples/ 是 MIT。AGPL 的意思是，你要是拿它改成网络服务给别人用，得把改动也开源。另外 README 明确写了，DSH Go 的名称、标识，以及 Deepy 和鲸娘两个吉祥物，不在开源授权范围内，条款单独放在 ASSETS.md。想拿它做二次分发或者套壳商用，这两条都得先读。

还有几个 README 自己列出来的功能差异，装之前该知道：DSH Remote 当前只支持图片附件；用远程主机时 App 内打不开网页版；插件管理只能开关，不能配置；不支持 DS Bot，也不支持对话日志导出。这些不算 bug，是「两条路功能不对等」的实话。

04 · 怎么用

装之前先决定：只当遥控器，还是让手机自己干活

如果只是想在外面看一眼电脑上跑到哪了，那就不装本机环境。下载 arm64 的 APK 侧载，首次启动选「连接远程主机」，填地址和凭据即可，占用的空间基本就是 APK 本身。这条路的好处是干净——手机只是个终端，出事卸载就完。

如果要在手机上真跑，首次启动选本机安装，等它把 Ubuntu、Node.js 和 DSH 装完，再配置模型和凭据。README 提醒了两件容易踩的事：一是装过签名不同的早期测试包时不能覆盖安装，必须先卸载，而卸载会清空对话、Linux 环境和设置；二是部分国产系统的省电策略会杀后台，App 发现后会提示并直达对应的放行设置，vivo、小米、华为、荣耀、OPPO 都有入口。

想自己编译的话，流程只面向 Linux x86_64，工具链是 JDK 17 + Flutter 3.47.7 + Android SDK/NDK，App 要求 Dart ^3.13.5：

bash tooling/setup-toolchain.sh
source tooling/env.sh
bash runtime/build-runtime.sh arm64-v8a
DSH_BETA_TOKEN_FILE= bash tooling/build-apk.sh -f arm64 --keep-daemon

产物在 app/build/app/outputs/flutter-apk/app-arm64-release.apk。没配 app/android/key.properties 时，本地 release 构建用的是 debug 签名，装不进已经装了官方包的同名设备——这也是上面那条「不能覆盖安装」的来源。当前构建以 APK 侧载为目标，不是 Google Play 的发布配置。

真正决定它值不值的，是你给它安排的位置。它适合「人不在电脑前，但需要知道任务跑到哪、需要批一次工具调用」这个节点；不适合当主力开发环境——手机屏幕小、后台容易被杀、编译大项目更是想都别想。

05 · 冷思考

2570 星买不到六天，六天也买不到成熟

先算一个数：6 天 2570 星，平均每天 428 星。这个速度不太像「产品做得好所以被认可」，更像「需求已经堆在那里很久，终于有人接住了」。DeepSeek Harness 这一轮的热度是真实的，但桌面之外的使用场景，社区一直在自己补。dsh-Go 补的正是这个缺口——它的星标里，有相当一部分是投给「终于有人做了」这件事的，不是投给代码质量的。

第二个质疑更硬：132 个 open issue，作者一个人。README 里那句「大家 Star 点得越多，我适配得越快哦 hhh」是句实话，也是一份坦白——iOS 和鸿蒙的适配没有时间表，进度和星标挂钩。六天里堆起一百多个 issue，说明打磨还没真正开始，现在是「能跑」，不是「好用」。

第三是权限账。手机操控要无障碍权限，意味着它能看屏幕、能点、能输入；开启之后，任务需要的屏幕文字可能发给模型，支持看图的模型还可能收到截图；「发送匿名使用统计」默认是开着的，要在首次引导或者「设置 → 隐私与分享」里关。三件事叠起来，等于你把整台手机交给一个六天大的个人项目。作者在安全说明里写了「付款、密码、验证码一律交还给你」，这是设计上的克制，但克制不等于审计，这个仓库还没经过任何第三方安全审计。

最后是成本。195 MB 的安装包加 1 GB 的运行环境，对「出门应急看一眼」这个场景来说偏重。如果需求只是远程看进度，一个 SSH 客户端就够了，没必要为它腾出 1 GB。

我的判断是：dsh-Go 值得装，但值得装在一台不当主力、不登主账号的安卓备用机上，当「出门时的 DSH 遥控器」用；想在手机上真跑 agent，先等它把 132 个 issue 收到两位数，再谈替代笔记本。它现在的位置很像早期的 Termux 客户端——方向是对的，成熟度还差着一年。
