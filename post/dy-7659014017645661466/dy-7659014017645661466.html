01 · Hermes Agent是什么

Hermes Agent是什么

Hermes Agent 是 Nous Research 推出的开源 AI 智能体项目，上线不到一年，GitHub 星标已经冲破 20 万。这个数字是什么概念？在 AI Agent 领域，这是现象级的增长速度。

它最吸引人的地方在于：越跑越离不开。用得越久，它越懂你——不是靠什么黑科技，而是靠一套扎扎实实的记忆系统和技能系统。你可以把它装在桌面上，也可以接入聊天软件，双端同步使用。

核心定位：一个能自己长技能的 AI 智能体。记忆是护城河，技能是战斗力，Harness Loop 是心脏。
为什么是 Nous Research？

Nous Research 一直专注于开源 AI 模型和智能体研究，Hermes 系列是他们的旗舰产品。这次的 Harness Loop 架构，是对"Agent 应该怎么跑"这个问题的一次系统性回答。

02 · Harness Loop循环

Harness Loop：智能体的心跳

如果说 Hermes Agent 是一个人，那 Harness Loop 就是它的心跳。每一次循环，就是一次完整的思考与行动。

整个循环分为 6 步，环环相扣，少一步都不行：

第 1 步：消息进来

用户输入一条消息，或者系统触发一个事件。这是循环的起点，所有后续动作都从这里开始。消息可以是文字、图片、语音，甚至是一个定时触发的信号。

第 2 步：Agent 运行

智能体接收到消息后，开始"思考"——调用大模型分析意图、理解上下文、制定行动计划。这一步决定了接下来要做什么。

第 3 步：调用工具

如果需要行动，Agent 会调用对应的工具——查资料、写文件、发消息、运行代码。工具是 Agent 伸向世界的手，没有工具，Agent 就只是个聊天机器人。

第 4 步：循环结束

任务完成后，Agent 整理结果，生成回复，返回给用户。一次完整的交互到此结束。但故事还没完……

第 5 步：存记忆

这是最关键的一步——把这次交互存进记忆系统。聊了什么、做了什么、用户喜欢什么、不喜欢什么，全部记下来。下次再聊，它就"记得"你了。

第 6 步：长技能

如果在交互中发现了新的模式、新的方法，Agent 会把它提炼成一个新技能，存进技能库。下次遇到类似问题，直接调用，不用再从头学起。

一句话总结：消息进来 → Agent 运行 → 调用工具 → 循环结束 → 存记忆 → 长技能。六步走完，智能体就变强了一点点。
03 · 最意外的设计选择

最意外的设计选择

研究 Hermes 的时候，有一个设计选择让我特别意外——全程没有 embedding。

现在做 AI Agent，言必称向量数据库、embedding 检索。但 Hermes 偏不，它走了一条完全不同的路：

  • 技能是纯文本文件——不是向量，不是结构化数据，就是明明白白的 .txt 文件
  • 用户信息也是纯文本——你的偏好、习惯、历史，全部存在文本里
  • 聊天历史存本地数据库——就是普通的 SQLite，不上云，不搞花里胡哨的
  • 检索靠关键词 + 上下文——不用向量相似度，直接搜，直接读
为什么这个设计很重要？

第一，可解释——你随时可以打开文件看看，Agent 到底记住了什么，没有黑箱。第二，可迁移——换个机器、换个模型，你的记忆和技能照样能用。第三，成本低——不用 embedding 模型，不用向量数据库，省了一大笔钱。第四，不依赖——不绑死任何一家厂商，真正的开源自由。

04 · 四大核心能力

四大核心能力

Hermes Agent 有四大核心能力，每一个都值得单独说：

记忆系统

这是 Hermes 的护城河。短期记忆 + 长期记忆 + 情景记忆，三层结构。你上周说过什么、上次聊到哪里、你喜欢什么风格，它全都记得。而且记忆是你的，存在本地，随时可以带走。

技能系统

这是 Hermes 的战斗力。技能可以学、可以写、可以分享。用着用着，Agent 自己就长出新技能了。每个技能都是一个纯文本文件，你可以直接编辑，也可以从社区下载别人写好的。

定时任务

这是 Hermes 的自主性。你可以让它每天早上给你读新闻，每周一整理周报，每月底做复盘。到点自动跑，不用你催。配合记忆系统，它会越做越合你心意。

子智能体

这是 Hermes 的扩展性。一个 Agent 忙不过来？那就生几个孩子。主 Agent 负责统筹，子 Agent 负责具体任务。写代码的写代码，查资料的查资料，分工合作，效率翻倍。

05 · 发现的问题

发现的问题

说了这么多好话，也得说说问题。实测下来，有两个 bug 比较明显：

问题一：技能学习不主动

理论上 Agent 应该自己长技能，但实际用下来，它的"学习主动性"有点欠缺。很多时候你得明确告诉它"把这个写成技能"，它才会写。离真正的"自主进化"还有点距离。

问题二：cron 有 bug

定时任务功能偶尔会掉链子——有时候到点不触发，有时候重复触发。这个问题在 GitHub issue 里也有人提，官方应该还在修。日常用没问题，但别把太重要的事全交给它。

客观评价：作为一个开源项目，Hermes 已经做得非常好了。有问题很正常，关键是社区活跃，修复速度也快。真正用起来，这两个问题不至于影响核心体验。
06 · 架构图随用随查

架构图随用随查

为了方便你理解，我把 Hermes 的架构整理成了 5 层，从上到下一目了然：

  • 输入层——桌面端 App、聊天软件接入、API 接口、定时触发器，所有消息从这里进来
  • 核心循环——Harness Loop 六步循环，是整个系统的心脏，负责调度和执行
  • 记忆层——聊天历史、用户画像、情景记忆，存在本地数据库和纯文本文件里
  • 能力层——技能库、工具集、子智能体，是 Agent 伸向世界的手
  • 进化机制——技能学习、记忆提炼、自我优化，让 Agent 越用越强
记住这个结构：输入在上面，循环在中间，记忆和能力在下面，进化是底座。从上到下，从接收消息到自我成长，一气呵成。
07 · 启示与思考

启示与思考

研究完 Hermes，我有 4 个很深的感触，分享给你：

启示一：简单胜过复杂

不用 embedding，不用向量数据库，纯文本 + 本地数据库，反而跑得挺好。有时候我们把问题想复杂了，真正好用的方案，往往反常识、反主流。简单不代表低级，简单是经过深思熟虑后的选择。

启示二：记忆是护城河

模型会越来越便宜，越来越同质化。真正拉开差距的，不是谁的模型更大，而是谁更懂你。记忆是你的，数据是你的，这才是真正的护城河。以后拼的不是模型参数，而是数据沉淀。

启示三：自进化是方向

现在的 Agent 还是"教什么会什么"，但未来一定是"用着用着就会了"。技能系统只是第一步，真正的自进化还很远。但方向是对的——Agent 应该越用越强，而不是越用越腻。

启示四：开源推动创新

20 万星不是白来的。开源让所有人都能看、能改、能贡献，速度比闭源快十倍。Hermes 能这么快成长，靠的不是某一家公司，而是整个社区的力量。开源，是 AI 最好的加速器。

08 · 结语

结语

Hermes Agent 让我看到了 AI 智能体的另一种可能——不追求花哨，不堆砌概念，扎扎实实做好记忆和技能。

Harness Loop 这个架构，简单、清晰、可解释，值得每一个做 Agent 的人研究。它可能不是最终答案，但绝对是目前为止最诚实、最接地气的答案之一。
