01 · 这件事

02 · 核心机制

三个 Hook 盯住对话，六道门把人卡在每一次确认上

机制的核心不是渲染，是把拍片拆成一道道必须被人批准的关卡。SKILL.md 的 frontmatter 注册了三个 hook，全部指向同一段 node 查找器，最终调用 scripts/hook.cjs 拉起 guard.py。

Hook触发点作用
UserPromptSubmit用户发消息提问前先查「用户有没有看过」
Stop一轮结束拦住交付了草稿却不给确认按钮的回合
PreToolUse（matcher *）每次工具调用对话过大、大图入聊、助手超过 25 步等

三个 hook 的 onFailure 都是 continue，即 guard 自己出错也不拦用户。开工先问两件事：模式与用途；模式决定深度，用途决定片种，之后的默认提问、参考、关卡与检查都跟着用途走。

维度Quick 模式Film 模式
产物一个自包含 film.htmlthree.js 分镜 + 分层声音
画面 / 声音Canvas 2D 或 three.js / Web Audio八套预设 / 分层 beds、拟音、旁白
确认次数约 3 次逐步 6–8 次，直出约 3 次
适用时长约 3 分钟以内十分钟以上的纪录片、叙事片

内建规则写得像验收清单，SKILL.md 把它归成五条：

  • 前 2 秒从第 1 帧就要有运动，且经过测量
  • 每一帧都是时间的纯函数，重渲染结果一致
  • 每个外部文件下载时即登记一行许可
  • 长渲染后台运行并写状态文件，含预计剩余时间
  • agent 只看小尺寸拼图，不把整图塞进对话

有意思的是体量：guard.py 有 103,011 字节，是 SKILL.md 的 3.14 倍。执行规则的代码比规则本身大三倍，说明这套 kit 真正押注的是「别让 agent 偷步」。

04 · 怎么用

「不需要付费服务」这句，要连环境要求一起读

工具包是 MIT 免费的，但跑通它要自备一整套本机环境与若干外部账号。README 首屏写 No paid service is required，紧接着的环境要求却列了一整排前置条件。

前置条件README 写的门槛
运行时Node.js 22+、Python 3.9+、ffmpeg
浏览器Google Chrome / Chromium / Edge，需可用 GPU
宿主 agentClaude Code 最佳，Cursor / Codex / Antigravity 亦可
guard 版本Claude Code 2.1.295 及以上才注册 exec 形式 hook
磁盘Quick 几百 MB，Film 每部几 GB

安装是一行 git clone 到 ~/.claude/skills/cinecode，或在 Claude Code 里说「安装这个 skill」。Cursor、Codex、Antigravity 也能跑，但 guard 的三个 hook 只在 Claude Code 生效，其它宿主里工具检查照跑、实时拦截缺席。

联网边界 README 自己讲清了。渲染、混音与检查可离线，Quick 起始模板也可离线；但参考检索、音乐、首次下载字体与风格、以及 three.js 场景取库都要联网。LICENSES.csv 里 three@0.186.1 与 postprocessing@6.39.5 从 jsDelivr 按版本加载，不打包进仓库。

旁白可选，但要你自己的 Gemini key（有免费额度）或 ElevenLabs；图库素材要 Pixabay 的免费 key。「零依赖」指的是脚本只用标准库与系统工具，不是整条链路零外部资源。

商用同样要自己兜底，README 把边界写得很细：

  • 逐项登记字体与素材许可到 LICENSES.csv，成片旁留 credits 文本
  • 仓库按 MIT「原样提供」，发布者对影片许可负责，并注明「这不是法律建议」
  • CI 三作业：Windows、Ubuntu、以及「无 Git 无 bash 的 Windows」，都开真实 Chrome 与 ffmpeg 测试
  • README 自承「还没在 Windows 上完整做过一部片子」，旧版客户端可能标 GUARD OFF
05 · 冷思考

画面不花模型钱，但那段 100–250 步的长对话花

最该打折读的是成本口径：代码出图不消耗模型，陪它走完流程的对话消耗。README 说画面由代码生成、不产生模型费用，同一份 FAQ 又给出 30–60 秒短片通常要 100–250 步，每一步都重读整段对话。

成本项README 自述
单部短片步数30–60 秒 Quick 片通常 100–250 步
每步开销重读整段对话，对话越长每步越贵
缓解办法对话变长就换新会话，靠 STATE.md 续上
额外建议关掉用不到的 skill、插件与连接器，用 usage.py 查 token

这些缓解办法本身就承认了账单在哪。所谓免费，是把成本从 API 挪到了你的 agent 订阅与等待时间；真要拍十分钟的长片，先算的是会话轮次，不是显卡。

工程活动的密度更值得看。9 次提交里 sarpstar 占 7 次，claude 与 cursoragent 各 1 次，后两次都是 11-03 改 README；11-12 那两次也只是加 X 徽章、改一句推荐语。2,462 星对 9 次提交，热度远跑在工程前面。

11 个未结也要拆开，否则容易误读成「11 个待修 bug」：

类型数量内容
真 issue5#12 ffmpeg 7.1 上 apad 无界、音频永不结束，仓库自带测试也挂住
PR6#11、#13、#15 都冲着同一个 master_audio.py 死循环
其它 PR 方向3本地页改用 127.0.0.1、免 Chromium 的 WebView 通道、Android app

#12 从 11-12 开着、0 条评论，报告者连最小复现命令与四种组合的对照表都给了；PR #15 则说安装 Chromium 约 400 MB，在 iSH、Termux 上会直接崩。免费工具包的落地阻力，恰好集中在它不打包的那几样东西上。

所以判断不是「能不能出片」，而是你愿意替它承担哪一段。这套 kit 值得读的，是把审美决策拆成可检查的关卡、把外部素材拆成可回溯的许可记录；不值得信的，是「零成本」三个字。真正被消耗的从来不是 GPU，是你陪 agent 走完 100–250 步的注意力——先看住它，再谈出片。
