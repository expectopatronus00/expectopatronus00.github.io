56k 星对 25k 星：两个专业 skill，两种验收

56,449 星配 206 个订阅者，25,579 星配 172 个。两个 MIT 协议的「专业 skill」，一个把审计结论变成机器可校验的 JSON，一个把 SEO 问题变成按影响排序的方案。前者停更 49 天，后者昨天还在推。

01 · 这件事

两个「专业 skill」，一个停更 49 天，一个昨天还在推

2026 年 6 月 18 日建库，到 11 月 2 日，cloudflare/security-audit-skill 的数据是 56,449 星、3,681 个 fork、110 个未关闭 issue，MIT 协议，JavaScript，仓库体积 143 KB。最后一次 push 停在 9 月 14 日——49 天没有一行代码提交。

另一个是 AgriciDaniel/claude-seo：2 月 7 日建库，25,579 星、3,358 个 fork、78 个未关闭 issue，同样是 MIT，Python 写的，仓库 6,934 KB。最后一次 push 是 11 月 1 日，昨天。

这两个项目在选题池里躺了四天。10 月 29 日入池，评分 97 和 88，属于同一族：把某个专业领域的判断标准，写成 agent 能读、能执行的技能文件。Cloudflare 那份管安全审计，个人开发者那份管 SEO。星标差一倍多，但真正的差别不在星标——在于「凭什么相信 agent 给出的结论」，两个人给了完全不同的答案。

02 · 核心机制

一个把结论变成可校验的记录，一个把结论变成能执行的方案

Cloudflare 那套是六阶段：侦察、按覆盖清单分配猎手、候选验证、结构化输出、独立记录核验、目标无关的报告。名字很绕，实质只有一句：先画清楚要查哪些面，再派人查，再派人推翻，最后按查过的面出报告，而不是按查出来的东西出报告。

六阶段里最硬的一条是角色分离。README 的原话是 The agent that checks a finding is never the agent that found it. 检查漏洞的 agent，永远不是发现它的那一个。每条候选线索交给一个全新的验证 agent，任务不是「确认它成立」，而是「试着推翻它」。

结论只有三档：confirmed 要有完整源码追踪和有界的实测结果，needs_validation 必须写明那个没解决的具体事实、且不给严重级别，rejected 记录被证伪的候选。三档一起写进 findings.json，用 report-schema.json 校验格式；覆盖情况记在 coverage-ledger.json，由 validate-coverage-ledger.cjs 在阶段一之后、以及之后每次更新后校验。它不靠 agent 说自己审完了，靠两个零依赖脚本说格式对不对。

claude-seo 走的是反方向。最多 17 个 agent 并行，先判断站点类型——SaaS、本地商家、电商、出版、代理——再按类型调整检查项，最后交一份按影响排序的行动方案。README 的说法是 You get a plan, not a pile of warnings：给你一份方案，不是一堆告警。每条建议要写清三件事，基于什么、依赖什么、怎么知道它生效了。

所以两者的「验收」根本不是一回事。Cloudflare 的验收是机器做的：schema 校验、独立 agent 证伪、覆盖清单对账。claude-seo 的验收是写给人看的：排序、归因、可验证的成功判据。前者适合交付给别人复核，后者适合今天下午就动手改。

03 · 关键细节与数据

「26 个子技能」这句话，自己数一遍是 25 个

先对 claude-seo 的自述数字。skills/ 目录下是 25 个子目录，从 seo、seo-audit、seo-technical 一路到 seo-sxo、seo-flow；仓库 description 和 README 都写 26。19 个子 agent 倒是完全对得上——agents/ 下正好 19 个 .md 文件。差一个不算大事，但和上次 OpenMontage 的「12 条管线」一样，自述数量值得自己数一遍。

Cloudflare 那边的体量更值得看。skills/security-audit 下 20 个文件，合计 312,670 字节。其中 15 个 Markdown 共 192,981 字节，4 个 .cjs 共 117,195 字节，1 个 JSON schema 14,494 字节。也就是说，这个技能 37.5% 的体积不是提示词，是校验代码；两个校验器的测试文件加起来 54,867 字节，单是测试就占了整体的 17.5%。

提示词部分按攻击面切分，不按流程切分。最厚的是 HUNTING.md 22,446 字节和 SKILL.md 22,026 字节，然后是 VALIDATION-AND-REPORTING.md 17,843、RECONNAISSANCE.md 15,902、ATTACK-CLASSES.md 15,695。目标类型单独成篇：AI-AND-LLM.md 管提示注入与工具调用，WEB-PROTOCOL-AND-AUTH.md 管请求走私与认证协议，CLIENT-SIDE.md 管 DOM 注入与原型链污染，再往下是内存安全与内核、供应链与发布、云与部署、RPC 与消息队列、资源耗尽、数据隔离、桌面与本地 IPC。

claude-seo 的 19 个 agent 里，5 个跑 Opus——content、geo、cluster、sxo、drift，其余 14 个跑 Sonnet。README 的说明是「需要更多判断的五个用 Opus」。另外两个数字：一次完整审计 10 到 15 分钟，测试徽章写着 1077 个测试通过。而 CHANGELOG.md 有 113,780 字节，占顶层文件总体积的 47%——更新非常勤。

04 · 怎么用

怎么装，以及什么时候该选哪个

Cloudflare 一行：npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit，装到用户级加 --global。然后在代码库里直接说 security audit this codebase，触发词匹配就进全量审计模式。默认输出目录是 ~/security-audit-skill/<repo-name>/run-<N>；同一个仓库多次跑是叠加的，它会拿上一次的覆盖清单去找缺口。

硬门槛是沙箱。README 要求 OS 级强制隔离：断外网、白名单环境变量、资源上限、只能写指定临时目录。没有这套控制，遇到需要执行目标代码的线索，它会把结论停在 needs_validation 而不是真跑一遍。这一条把大部分个人开发者挡在门外——你需要的不只是一台笔记本，是一个能安全跑陌生代码的隔离环境。

claude-seo 三条命令：/plugin marketplace add AgriciDaniel/claude-seo、/plugin install claude-seo@agricidaniel-claude-seo、/seo setup。前置是 Claude Code 1.0.33 以上、Python 3.11 到 3.14。/seo setup 自己建 Python 环境和无头浏览器，/seo doctor 体检。不接任何 key 也能跑，但 Core Web Vitals 只能是实验室估算值，索引状态靠页面推断——这是它自己写在 FAQ 里的限制。

怎么选，我给三条：

  • 要交付、要别人复核结论：选 Cloudflare 那套。三档结论加 schema 校验，报告可以被第三方抽查。前提是你有隔离环境。
  • 要今天就把站点改一遍：选 claude-seo。/seo audit https://your.site 十几分钟出方案，不用配 key。
  • 只想要方法论：两个都别装，去读 Cloudflare 的 VALIDATION-AND-REPORTING.md 和 claude-seo 的 agents/seo-technical.md。前者 17,843 字节，讲清了「什么算确认」；后者讲清了技术 SEO 该看哪几项。
05 · 冷思考

56,449 星，206 个人订阅

星标和 watch 一起看更清楚。Cloudflare 56,449 星配 206 个订阅者，0.36%；claude-seo 25,579 星配 172 个订阅者，0.67%。fork 比差得更明显：3,681 除以 56,449 是 6.5%，3,358 除以 25,579 是 13.1%。claude-seo 的 fork 比例高一倍，更像是真有人拿它去改，而 Cloudflare 那 5.6 万星，更像「官方出品，先收藏」。

第二个质疑是停更的代价。49 天没提交、110 个 issue 挂着，但 README 里那句自述恰恰说明它最该继续做下去：In our test runs, a single run found roughly half of the vulnerabilities that repeated runs found in total. 单次运行大约只能找到重复运行总量的一半。这句话是它最有价值的一句，也是最危险的一句——攻击面在变，11 份攻击面文档不会自己更新，停更的专业 skill 会慢慢变成一份过时的检查表。

第三个质疑是口径。claude-seo 的定价对比表把「数据留在本地」标成「是（本机运行）」，FAQ 又说分析的页面和数据会发给 Claude；两句话不算直接矛盾，文件确实留在本机，但宣传语容易被读成「数据不出门」。更要紧的是 homepage 直接指向 skool.com 上的付费社群，README 明说付费会员还有一个私有版，能提前拿到新功能。开源版是漏斗的顶端，这不算错，但读者该知道自己在漏斗的哪一层。

第四个是成本被藏起来了。17 个 agent 并行、5 个跑 Opus、一次审计 10 到 15 分钟——token 账单不在「免费」两个字里，而在你的 Claude Code 套餐里。Cloudflare 那边反过来：它省 token，但要沙箱，还要一台敢跑陌生代码的机器。两种成本都不显示在星标数上。

我的判断是，这两个项目回答的其实是同一个问题的两半。Cloudflare 回答「AI 找出的漏洞凭什么信」，答案是让另一个 agent 去证伪、让脚本去校验格式；claude-seo 回答「AI 找出的问题先改哪个」，答案是按影响排序、每条建议写清依据和验证方法。前者是审计的语法，后者是执行的语法。两个都装也不冲突，安装通道都不一样——一个走 skills CLI，一个走 Claude Code 插件市场。但真正该抄的是 Cloudflare 那条角色分离原则：谁发现，谁就不能验。这条规则跟安全无关，跟所有让 agent 自评的场合都有关。
