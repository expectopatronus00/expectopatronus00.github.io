01 · 这件事

30.6 万星、327 个技能：先读仓库，别先装插件

ECC 的星标已经到 306,038，但最新 Release 停在 10 月 1 日，仓库本身在 11 月 17 日仍有推送。affaan-m/ECC 创建于 2026-01-18，MIT，主语言 JavaScript，自述是 agent harness 的性能优化系统。

核对日 2026-11-18，它有 45,042 个 fork、163 个未结条目。未结不等于全是 bug：拆开看是 93 个 issue 与 70 个 PR，PR 数接近 issue 的四分之三。

根目录还摊开了一排以点开头的适配目录：.claude、.codex、.cursor、.gemini、.qwen，以及 .claude-plugin、.codex-plugin、.grok-plugin 等插件清单。它不是一份编辑器配置，而是一张分发矩阵。

README 首页还列了 17 种语言入口，中文版单独占一个 38,234 字节的文件。它同时声明根是唯一事实源，平台适配器只是打包或映射这套工作流，不另存副本。

更值得写下来的是仓库体量。根目录 87 个条目，skills/ 327 个子目录，agents/ 72 个文件，commands/ 98 个文件。这三个数与 README 首页的 327 / 72 / 98 逐项对得上。

02 · 核心机制

技能是主界面，命令只是迁移期的壳

ECC 把能力分成四层：skills 承载流程，agents 负责委派，hooks 在工具事件上执行约束，rules 常驻上下文。README 明说新工作流先落在 skills，commands 只作兼容入口。

  • Skills：327 个按需加载的工作流目录，覆盖 TDD、调研、安全、文档与前端。
  • Agents：72 个限定作用域的子代理，按规划、评审、修构建等角色切分。
  • Hooks：绑定工具事件，可在编辑后跑脚本，是运行时约束的执行点。
  • Rules：common 与语言目录两类，选装后常驻，不占技能调用。

README 给的 TDD 技能示例是五步：先定接口，再写失败测试，接着做最小实现，然后重构，最后验 80% 以上覆盖率。流程被写成可调用的步骤，而不是一句「记得写测试」。

Agent 的定义写在 YAML frontmatter 里。README 举例的 code-reviewer 只拿 Read、Grep、Glob、Bash 四个工具，模型指定 opus。权限写在角色文件里，比在提示词里说一句「只审查」更硬。

Hooks 能跑 shell，MCP 能持凭据，项目指令会进上下文。README 把三者并列为必须按可执行配置审阅的对象，而不是普通文本配置。

持续学习会把会话摘要和学到的 instinct 写进 agent data home，默认落在 ~/.claude。会话开始时可注入的 instinct 默认最多 6 条，置信度阈值 0.7，两者都能用环境变量改。

04 · 怎么用

先选安装路径，再把 hook 的决策显式做完

安装 ECC 的第一步不是敲命令，是选 profile 和 target；全量 manual 安装不要叠在 native plugin 上。README 写得很直接：两条路选一条。

  • npx ecc-universal@2.2.3 setup：引导式安装，覆盖 Claude、Codex 与 Kimi。
  • npx ecc-universal@2.2.3 install --profile minimal --target claude：低上下文路径，不装 hook runtime。
  • ./install.sh --profile core --no-hooks --target claude：核心配置，关掉钩子。
  • ./install.sh --target claude --modules hooks-runtime --enable-hooks：之后再补运行时。

MCP 不是越多越好。README 写默认连接器只有一个 chrome-devtools，其余是包着 CLI / REST API 的技能，或需要主动勾选的目录项；2026 年 6 月的审计还下线了原先六个默认连接器。

hook 必须显式决定。没有 --enable-hooks 或 --no-hooks，安装器会先打印钩子能做什么，然后停在写入前；引导安装则会交互询问。

环境门槛不高但很硬：Node.js 18 以上，Claude Code 插件要 v2.1.0 以上。Claude Code v2.1+ 会自动加载 hooks/hooks.json，再往 plugin.json 写 hooks 字段会触发重复检测错误。

跨工具混用先隔离数据目录：ECC_AGENT_DATA_HOME="$HOME/.cursor/ecc"。会话摘要、学到的技能、别名和成本指标都落在这个根下，不隔离就会互相覆盖。

省 token 的调整照 README 自己的表来，别当成实测结论：它建议 opus 换 sonnet、自动压缩阈值从 95 调到 50，同时保持 MCP 少于 10 个、活跃工具少于 80 个。

05 · 冷思考

30 万星里能直接拿走的是流程，不是全平台等价

先别把 163 个未结条目读成 163 个 bug：其中 70 个是 PR，维护压力正写在 issue 里。#3997 记录了一次 PR 洪水，20 分钟内 23 个 PR 触发了「超过 5 个关闭、超过 10 个封禁」的策略。

那条 issue 同时写明封禁令牌未配置，所以只关不封。另一条 #4017 是会话摘要含冒号，写出的 YAML frontmatter 解析失败。这些不是功能列表，是日常维护成本。

版本节奏也值得问一句：README 说一个人每周跨 7 个 harness 发版，最新 Release 却是 10 月 1 日的 v2.2.3，没有资产，pushed 停在 11 月 17 日。发布通道与开发节奏不是一条线。

平台差异是硬边界，下面几条都写在 README 或 SECURITY.md 里：

  • Copilot Chat 只有指令层，不接 ECC hooks。
  • Codex 原生 hook 要显式信任，且不沿用 Claude 的 hook profile。
  • macOS 自带 Bash 3.2 跑不了 GAN shell 路径；Windows 原生模式的 observer 与 memory vault 仍有未结缺陷。
  • 免费承诺限定 MIT 仓库；私有仓库的托管 GitHub App 从 19 美元 / 席位 / 月起。

成本建议也要留个问号。「换 sonnet 省约 60%、覆盖八成以上任务」是 README 的推荐表，不是仓库里跑出来的基准；正文没有给出评测链接。

它同时提醒：Bedrock、Google Cloud 的 Agent Platform 与 Foundry 上的 sonnet 别名指向 Sonnet 4.5，不支持 effort 控制；要么换一个支持该控制的模型，要么把这个变量整个删掉。

安全报告路径也要看清：SECURITY.md 说 security@ecc.tools 别名无人监控，要发到 affaan@ecc.tools；承诺 48 小时确认、7 天初评、14 天出关键修复目标，但旧版本回补补丁写明 best-effort。

结论不是别装。ECC 值得抄走的是 plan → test → review → remember 这条闭环；如果你的 harness 在支持表里写着 Partial，就按 selective 装，把 hook 当代码审，别把 327 当成开箱即用的承诺。
