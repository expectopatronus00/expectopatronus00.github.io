269个特性对255份指南：Chrome官方技能的源仓不发货

源仓 10,966 星只写不发，发货仓 26,098 星负责装。Chrome 官方 Web 技能列 269 个特性，文件树只有 255 份指南、196 份 demo；评测 +41pp 有前提，内置插件目录停在 v0.0.194。

01 这件事

Chrome 团队把 Web 最佳实践做成一套可检索的 agent 技能，但写代码的和给你装的，是两个仓库。

截至 2026-11-25，GoogleChrome/modern-web-guidance-src 有 10,966 星、831 fork，2026-01-27 建库，11-24 仍有推送，TypeScript，Apache-2.0，未结条目 398 个。这个仓库没有 Release：它只负责编写、校准与评测内容。

真正被安装的是另一个仓库 GoogleChrome/modern-web-guidance，26,098 星、1,115 fork，3 月 23 日建库，最新 v1.0.2 于 11-23 发布。README 的每个安装命令都指向这个发货仓，源仓只收 issue 和 PR。

这套技能叫 Modern Web Guidance，由 Chrome、Microsoft Edge、Mozilla Firefox 和 MDN 团队共同维护，目标是让编码 agent 少写旧模式，多用浏览器原生能力。它入池 11-16，是 pending 里最早一批；入池第 9 天复核，源仓仍在推送，星标未见衰减，按 88 分成稿。

02 核心机制

coding agent 不是把整本规范背下来，而是在写 Web 代码时按需检索一条指南，再把它塞进上下文。

README 把流程写成三步：agent 识别到 Web 平台任务后激活技能，运行 modern-web-guidance search "<query>" 在本地匹配指南，再用 modern-web-guidance retrieve <guide-id> 取回代码模式与坑点。检索用离线 embedding 加 BM25，不调搜索 API，不需要 key。

步骤命令 / 动作产出
激活agent 判断任务相关技能被载入
本地检索search "<query>"候选指南 ID
取回retrieve <guide-id>代码模式、gotcha、fallback
扫描存量legacy-scan .仓库里的旧模式清单

覆盖清单分三类，README 列出的 269 个特性是这三行的合计：144 个 CSS 与布局、38 个 HTML 与 DOM、87 个 JavaScript 与 API。特性清单不是指南数，后面会看到两者对不齐。

覆盖门类README 特性数举例
CSS & Layout144锚点定位、容器查询、视图过渡
HTML & DOM38popover、dialog、自定义 select

指南按“token 效率”设计：评测会剪掉模型本来就会的低区分度内容。安装时可选技能包，主包 modern-web-guidance 的入口约 205 tokens，chrome-extensions 包约 175 tokens，两者可用 --choose 挑选。

仓库里真正面向用户取用的技能只有一份：skills-src/chrome-extensions/SKILL.md。另外 13 份 SKILL.md 全在 .agents/skills/ 下，从名字到内容都是给维护者用的——写用例、审稿、跑评测、查回归，不随安装包发给用户。

发货是自动化的。RELEASING.md 写明每周一 14:50 UTC 触发工作流：收集评测摘要、解析版本号、编译指南、跑安装测试、推到发货仓 main、打 tag，再用 Gemini 生成发布说明并建 Release。对 Claude Code 而言，发货仓是单一 bundle，不是一个插件市场。

03 关键细节与数据

README 的 269 是特性清单，文件树里的 255 才是指南数，连三件套都没凑齐。

用 curl 拉下完整 git 树（3,243 条记录、未截断）后本地统计：guides 下 255 份 guide.md、196 份 demo.html、217 份 expectations.md、224 份 task.md、224 份 grader.ts。贡献规范要求每个用例同时写指南、演示和期望清单，实际文件数并不相等。

实验性特性不是搜不到，而是取不回：Origin Trial 和 volatile 特性（单引擎、近三个月内上线或仍在稳定中）在 search 里可见，retrieve 会被门控。要放开得在项目根的 .mwgrc 里写 allowOriginTrials 或 allowVolatileFeatures。

README 的评测快照给出 11-20 三行：codex_cli（gpt-6.1-sol）229 项任务、1,961 次检查，49% 到 85%；claude_code（opus-5-5）54% 到 94%；antigravity_cli（gemini-4-argon）56% 到 97%。提升幅度按 guided 减 unguided 计算，标成 +36pp 到 +41pp。

04 怎么用

先按你用的 agent 选安装入口，再决定是否放开实验特性；离线可用，但默认会发遥测。

最快的一条是 npx modern-web-guidance@latest install，交互向导装完整包，要求 Node.js 22 以上（package.json 写的是 ≥22.18.0）。CLI 本身零依赖，缓存后可加 npx --offline 跑，不需要联网取指南。

动作命令前提
安装npx modern-web-guidance@latest installNode ≥22.18.0
检索npx ... search "animate a dialog"无需 key
取回npx ... retrieve <guide-id>非门控指南
放开实验特性set-allow-volatile-features写 .mwgrc
关闭遥测DISABLE_TELEMETRY=1环境变量

README 另列了九种插件式安装：Vercel Skills CLI、GitHub CLI、Antigravity、Copilot CLI、Claude Code 插件、Grok Build、Kimi Code、Pi 和 Codex，全部指向发货仓。Claude Code 用户要注意 marketplace 的名字，后面会讲坑。

场景选什么理由
给现有 agent 补 Web 知识npx 安装主包检索与取回都离线
只做 Chrome 扩展--choose 选 chrome-extensionsMV3 与后台 worker 专包
排查老代码库legacy-scan .先扫旧模式再改
内网 / 无外网缓存后 npx --offline包自含、无搜索 API

遥测默认开启，收集安装次数、调用它的 agent 名、retrieve 的指南 ID 和 agent 生成的搜索词；README 明说不收原始 prompt，可在 shell 里设 DISABLE_TELEMETRY=1 关掉。代码是 Apache-2.0，guides 下的文档内容另用 CC-BY 4.0。

05 冷思考

它承诺的是少写旧代码，不是让 agent 从此写对；更新路径和覆盖口径各有缺口。

最实在的坑在安装环节。issue #3533 记录：Claude Code 内置插件目录钉在 v0.0.194（10-12 发布），升级到 v0.0.195 的 PR 过了检查却一直待审，bot 因有在审 PR 跳过后续版本，v1.0.0 也就没被捡起来。该 issue 11-12 提出，截至核对仍开着，README 的解决法是改用 googlechrome marketplace。

覆盖口径也要拆开读：269 是 web-features 清单里的特性数，255 是实际写出来的 guide.md。三件套规范写得很硬，demo 却只有 196 份、expectations 217 份，说明仍有指南没配齐演示或验收项。把一个特性算成一条现成指导，会高估它开箱即用的程度。

评测数字同样有条件。README 自己说提升靠 opportunity（100% 减无引导通过率）和 uplift 定义，模型本来就会的内容会被剪掉，评分器还要先拿 golden solution 过 100%、拿未改动的基线应用过 0% 才校准完成。+41pp 是在挑出来的难题上量的，不是全站代码的平均提升。

评测的入口也不是谁都能跑。EVALS.md 里 Claude Code 走 Vertex AI，Codex CLI 要内部申请例外，另两个命令行工具需各自登录；结果上传到 GCS 后才能真正发布。所谓“持续校准”由有云权限的团队维护，个人拿到的是校准后的产物。

外部贡献的门槛也不低：AGENTS.md 要求先确认签了 Google CLA、有分配给本人或标 pr-welcome 的 issue、无竞争 PR，若本人零合并 PR 则不能有其他在开 PR，内容改动最多碰一个指南目录。对想补一条指南的人来说，这比点个 star 重得多。

398 个未结条目里 84 个是 PR，而内置市场那条升级 PR 已经排了队。把星标当成“社区在共同维护”的证据会失真：真正能合并内容的是 Peers 与领域负责人，指南还必须先由他们署名或背书。星标说明话题被看见，不说明贡献通道是敞开的。
