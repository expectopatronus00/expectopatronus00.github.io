01 · Skills是什么

Skills是什么

如果你是 Claude Code 或 Codex 的用户，你可能已经接触过 Skills——它们是 Markdown 文件，告诉 AI Agent 在特定场景下应该怎么工作。比如：

  • python-testing skill — 告诉 Agent 使用 pytest 框架写测试
  • react-patterns skill — 告诉 Agent 遵循特定的 React 编码规范
  • database-migration skill — 指导 Agent 安全地执行数据库变更

Skills 的好处是：你把好的工作模式固化为 skill，Agent 下次遇到类似场景就自动按最佳实践执行。

核心问题：当你装了 20 个 skills，哪些真的在用？哪些只是白白消耗 token？
02 · 三大核心项目

三大核心项目

deadskills — 技能死代码检测

⭐ 25 · TypeScript · 本地优先分析工具

每个安装的 skill 都会在每次 prompt 中注入名称和描述，无论它是否被使用。这意味着冗余技能在持续浪费 token 和上下文窗口。deadskills 帮你找出哪些 skills 只是占着位置。

Claude-Skills-collection — 137个生产级技能库

⭐ 15 · Python · MIT 协议

这不是一个工具，而是一个内容库——137 个经过验证的、生产级别的 Agent Skills，覆盖代码生成与重构、测试编写与覆盖率、API 设计与文档、数据库操作与迁移、部署与 CI/CD、安全审计。

  • 统一结构 — 所有 skill 遵循同一套 Markdown 模板
  • 统一语气 — Agent 加载后的行为一致
  • 即装即用 — 每个 skill 都能直接改变 Agent 的行为

这个项目的意义在于——它把 Skills 从「个人经验」变成了「社区资产」。

AI-Project-Workflow — 跨工具统一工作流

⭐ 11 · JavaScript · MIT 协议

不同的 AI 编程工具（Cursor、Claude Code、Codex、TRAE、Qoder 等）有各自的工作方式，但项目应该是工具无关的。它提供了一套统一的、AI 原生的软件交付工作流：

  • SDD（Specification-Driven Development）流程定义
  • 跨工具的 skill 和规则共享
  • CI/CD 集成
03 · 生态为什么现在成形

生态为什么现在成形

前提1
用户量足够大 — Claude Code 和 Codex 的用户增长迅速，Skills 的用户足够多了。任何技术领域的生态化，第一个前提就是用户量。
前提2
痛点足够痛 — 装了 20 个 skills 但只用了 3 个？每次对话都在消耗额外 token？这些问题在「只有 3 个 skills」的阶段不明显，但在「管理 20+ 个 skills」的阶段变得无法忽视。
前提3
基础设施栈成形 — 最早的 skills 是个人随手写的。现在出现了管理工具、内容库、标准工作流，三个层次构成了一个完整的基础设施栈。
04 · 三层基础设施栈

三层基础设施栈

三大层次：
  • 治理层 — deadskills：帮你治理想法，哪些 skills 真的在用？
  • 内容层 — Claude-Skills-collection：帮你发现好用的 skills
  • 流程层 — AI-Project-Workflow：帮你统一使用方式，skills 怎么嵌入工作流？

这三件事加在一起，勾勒出了 AI 编程的下一个基础设施层。现在入场的开发者，将有机会塑造这个生态的早期形态。

05 · 未来展望

未来展望

即将出现的生态形态
  • Skills 市场/注册中心 — 一个可以搜索、评分、安装 skills 的中心化平台
  • Skills 分析仪表盘 — 可视化展示哪些 skills 最常用、哪些拖慢性能
  • Skills 自动推荐 — 根据项目类型自动推荐合适的 skills
  • Skills 版本管理 — 像 npm 一样管理 skills 的版本和依赖
  • Skills 互操作性标准 — 跨 Claude Code、Codex、Cursor 等工具的通用 skill 格式
  • Skills 自动生成 — 从你的编码习惯中自动学习并生成 skills
更远的变化
  • Skills = 开发团队的知识资产 — 团队的编码规范、架构决策、最佳实践全部固化为 skills
  • Skills 经济 — 高质量的 skills 可以付费分发
06 · 开发者行动指南

开发者行动指南

入门
从少量开始 — 先装 3-5 个与你日常工作最相关的 skills
观察效果 — 注意 Agent 的行为是否真的改善了
自己写一个 — 把你团队的一条编码规范写成 skill
进阶
用 deadskills 做一次审计 — 找出哪些 skills 只是占着位置
整理你的 skill 库 — 确保每个 skill 都有清晰的触发条件
参考 Claude-Skills-collection — 看看别人的 skill 怎么写，优化自己的
团队级
建立团队的 skill 仓库 — 把团队规范固化为 skills
新成员入职即配备 skills — 让 AI Agent 自动遵循团队规范
定期审计和更新 — Skills 也需要维护
07 · 总结

总结

核心观点：Agent Skills 生态的成形是一个重要信号——它说明 AI 编程不再是「写 prompt 的玄学」，而是正在建立可复用、可治理、可共享的知识体系。三个核心项目抓住的是三个不同的层次：治理、内容、流程。这三件事加在一起，勾勒出了 AI 编程的下一个基础设施层。
