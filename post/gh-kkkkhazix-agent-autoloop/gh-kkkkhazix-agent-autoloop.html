02 · 核心机制

把「等人拍板」做成不占进程的状态

一件事的流转是五步：新事件（定时规则、GitHub Issue、业务报错）进内核 → 按 rules.json 派给某个 Agent 和某个目录 → Agent 把结果写在最后一条回复里、进程退出 → 碰到删数据、重启服务、花钱、对外发消息这类事，内核推一张卡片给你 → 你选完，它接上原会话把剩下的活干完。能自己定的直接办完，或者约半小时后醒来复查，全程不打扰。中台对 Agent 的约定只有一条：最后一条回复交代结果；要请示，就在末尾附一段 agent-autoloop 代码块，用 ask、notice、resolve、later 或 events 说明意图。接新 Agent 不需要 SDK，也不需要改 Agent 源码。

最值得拆的是「挂起零消耗」。等你回复期间，Agent 进程直接退出，等待状态写进事件日志和数据库，只有很轻的中台在后台；README 举的例子是你三天没回，这三天就没有 Agent 进程、也不花 Token，一回答就接回原来的对话继续干。它把 human-in-the-loop 从「一个挂着的进程」改成了「一条可重放的记录」，比把上下文和进程一起留在内存里等输入的循环要克制。代价是会话续接必须可靠——README 为此专门写了：会话接不上才开新的，接上了却干到一半断了就算没跑成，过几分钟回原会话重试，不重做业务。

内核自称没有运行时依赖，并搬了四个计算机领域的成熟做法：事件溯源（状态全从只追加日志算出，日志与索引同一事务落盘，写完才应答）、指令数据分离（外部文字只作资料放进文件，不拼进提示词；事件里带 cwd、agent、access 字段直接拒收）、跳数熔断（像 IP 包的 TTL，Agent 交回的事件再派给 Agent 时层数累加，超过 8 层只记录、不再派活并通知你，经过人工提问和定时复查也不清零），以及确定性内核（不读系统时钟、不用随机数、不向外发请求，插件主动连进来，凭据留在各自插件里）。文件级反查能对上：kernel/ 是 11 个 TypeScript 文件，最大的 decide.ts 40087 字节，另有 evolve.ts、cron.ts、http.ts；根 package.json 里没有 dependencies 字段，只有 3 个 devDependencies（@types/node 26.6.4、prettier 3.9.10、typescript 7.0.2），engines.node 要求 >=24。「零运行时依赖」在清单层面站得住。

性能数字 README 也给了，条件是 Apple M5 Pro、24 GB、Node 24.21.0，写入逐条提交、事务落盘后才应答，复现命令是 npm run benchmark：冷启动 88.78 ms、空闲内存 59.94 MB RSS、1000 个同时等待的长轮询 170.49 MB RSS、持久化写入 2394 条/秒、派活 p99 1.82 ms、110 万条事实时启动 99.8 ms、运行时依赖 0。同一节紧跟着写了代价：历史变大后状态汇总变慢、日志和索引继续占磁盘，格式变化后的首次启动要从日志全量重建，110 万条用时 43.1 秒。这些是作者自报的基准，本文没有安装运行，也没有重跑 benchmark。

最该抄下来的是 README 自己那段「实测情况」。跑通的是 Claude Code、Codex、ACP 的多轮问答与跨进程会话续接，以及飞书的发送、按钮回调和卡片更新；四种 Webhook 模板只在本地模拟服务上验证过，GitLab Webhook 按官方文档格式测试、没连过真实 GitLab；Gemini CLI 0.67.0 与 OpenCode 1.1.2 只跑通了 ACP 握手，多轮问答和会话续接还没跑过；另外 6 个 Agent 的接入命令被明确标注「整理自各家官方文档，我们还没有逐个跑过」。场景模板那段更直白：样例数据都是虚构的，脚本和回执只用本地 HTTP 与假飞书 CLI 验证过，没有在真实账号上跑过完整业务；SECURITY.md 结尾也补了「本仓库测试只使用假 CLI」。把「没验过」写到和功能表一样细的 README，比一份全是绿灯的清单更可信，也更该先读。

04 · 怎么用

先验一遍，再接真实通道

安装门槛写得很直白：Node 24 或更新、Git、一个已经登录好的命令行 Agent，macOS / Linux 还需要 curl，不需要 GitHub 账号。Windows PowerShell 用 irm .../install.ps1 | iex，macOS / Linux 用 curl -fsSL .../install.sh | sh，安装和 agent-autoloop update 都取通过全部检查的最新 Release。装完先跑 agent-autoloop try，用本机 Agent 走一遍「提问 → 退出等回复 → 拍板 → 接着干完」；交互终端直接输数字回车，非交互终端用 agent-autoloop answer 1 2，再 agent-autoloop status 看它接回会话，以及今天和最近 7 天的轮数、Token 和费用。这一步不连任何外部服务，是成本最低的一次验真。

日常配置只有一份 ~/.agent-autoloop/rules.json：写清「什么事、交给谁、在哪个目录干」，比如 "when": {"cron": "0 9 * * *"} 配 to、cwd、prompt 就是每天 9 点写早报；外部事件换成 "source": "github" 加 "types": ["issues.opened"]、"parallel": 3。几个不碰中台就能用的校验值得记住：agent-autoloop check 查当前规则、check <文件> 查草稿、rules explain [文件] 看生效规则和下次定时、emit <类型> --dry-run 预演一条事件会派给谁；pause / resume / run 管控单条规则且只记日志、不改 rules.json；why 1 查某一轮从触发到回执的来龙去脉。规则改错、文件被删或读不到，系统继续按旧规则跑并发卡片提醒。把「先验再放行」做成默认路径，是这套设计里最实用的一处。

接真实通道之前有两条必须先看。默认只开桌面通知；飞书 / 钉钉 / 企微 / Slack / Discord 要自己配，文字通道靠回答链接拍板，得把 hub.publicUrl 配成手机或电脑能打开的地址——而 SECURITY.md 写明卡片链接「持有即授权」、从创建起 7 天内有效，只发给配了 "links": true 的通道，不能发到公开位置。另一个坑是超时：OpenClaw 的 agent exec 每次默认最多跑 600 秒，到点就算失败，长任务要在命令里加 --timeout <秒>。

05 · 冷思考

省下的是等待，不是账

先质疑那个最显眼的数字。4337 星配 8 个订阅者、5 个未关闭 issue，比例低得反常；7 天 15 版里相当一部分不是新功能，而是在把地基打对——v1.7.1 修的是 macOS 从图形界面拉起的终端 umask 为 0 时 LaunchAgent plist 变成所有人可写、launchd 只报 Bootstrap failed: 5 且重装修不好；Codex 中途 Reconnecting... 后换传输跑完，原来被判失败、整轮重做；收件箱模板被 skipSenders 跳过的邮件占掉读取名额，没读到时间窗尽头却报「没有需要看的邮件」。星标衡量的是「Agent 自己上班」这件事的想象空间，不是它已经替谁干完了一个月。

再质疑「零消耗」的口径。挂起零消耗省的是等你拍板那段时间的进程和 Token，这个机制成立；但模型调用走的是你本机已安装并登录的订阅制命令行工具，中台不读取也不转存凭据。README 的「用量与合规说明」自己写得很清楚：高频自动化场景下各家厂商通常更建议使用 API Key，因为个人订阅额度主要是为日常人工交互设计的；如果用它对外提供服务，请使用 API Key；本项目是独立开源项目，与上述厂商无隶属或背书关系。把「等待时不烧 Token」读成「自动化不花钱」，中间隔着一份服务条款。

第三处是「到底拦得住什么」。SECURITY.md 不绕弯子：askFirst 只是写进提示词的要求，Agent 不照做，中台也拦不住，真正挡得住的是 access 和 Agent 自己的沙箱；默认权限是 edit，给 full 之前要想清楚这个 Agent 能碰到什么；普通 Agent 的 read 不等于读不到这台电脑上的密钥；中台不隔离同一系统账号下的进程，Codex 的 Windows 沙箱还会给数据目录加读权限，直到中台启动才收回。指令数据分离能挡住把 Issue 标题拼进提示词，作者却也承认「这挡不住所有提示注入：Agent 还是会读到别人写的话」。日志与恢复那节同样留了边界：模拟和 SIGKILL 覆盖的是进程崩溃与有限场景，不等同于断电恢复证明或完整安全审计。四个内核机制约束的是调度，不是 Agent 本身的行为。

所以判断不落在 4337 星上。如果你要的是「等人拍板时别让 Agent 一直挂着」，事件溯源、挂起零消耗、跳数熔断这三条可以直接抄进自己的调度器，kernel/ 那 11 个文件和 package.json 里那个不存在的 dependencies 字段就是可核对的证据；如果你要的是接上真实飞书、真实 Webhook 就能跑生产，那 8 套模板、4 种 Webhook 和 6 条「整理自官方文档」的接入命令，目前都还停在作者自己标注的「没逐个跑过」。这个项目最稀有的不是自主度，是把「哪些还没验」写到了和功能表一样细——在一个所有人都在晒 Agent 替自己干活的窗口里，这种克制比星标更值得当样本留着。
