10.5 万星的本地语音工作台：646 种语言，570 种不足百小时

105071 星、11678 个 fork、106 个未关闭 issue——VoiceStudio 把语音克隆、视频配音、听写转写收进一台机器，README 写着 646 种语言。逐行数完仓库里那张语言表，646 条一条不少，581k 小时也对得上，但中位数只有 10.18 小时。

01 · 这件事

十万星的语音工作台，把六件事收进一台机器

debpalash/VoiceStudio 2026 年 4 月 9 日建库，到 11 月 9 日核对时是 105,071 星、11,678 个 fork、106 个未关闭 issue，订阅者 355；Python，AGPL-3.0，仓库 203,146 KB，主页 voicestudio.sh。最后一次 push 是 11 月 8 日 23:20 UTC，还在动。README 第一屏写着「AI voice studio. On your device.」，紧跟着一句「Clone, design, dub, dictate, transcribe and narrate in 646 languages.」——把语音克隆、声音设计、视频配音、听写、转写、有声书六件事，全放进一个跑在本机的应用里，还标了 646 种语言。README 里那句「100,000 GitHub stars — thank you!」已经落后于实测值，说明它刚跨过十万星不久。

这类项目最容易被写成「ElevenLabs 的免费开源平替」，但那只是 description 里的定位。真正决定它能不能替代的，是「646 种语言」这个数字到底覆盖到什么程度——是六百多种语言都能正常出声，还是六百多个条目都挂在同一个模型目录里。这次不数管线也不数 skill，只把仓库里那张语言表逐行数一遍，顺带看看一个十万星项目的工程体量和授权边界撑不撑得起「本地免费」四个字。

02 · 核心机制

模型在本机，646 只属于默认引擎

它不是一个调云 API 的客户端。默认引擎是 k2-fsa/OmniVoice，模型由 Model Manager 按需下载，README 明确写「The app asks before it downloads any model」——下任何模型前会先问。推理走四条硬件路径：Windows / Linux 上的 NVIDIA CUDA、AMD ROCm（Windows 为 opt-in）、GGUF 引擎的 Vulkan、Apple Silicon 的 Metal (MPS)；No GPU? The app is fully usable on the CPU, just slower.「本地」在这里是字面意思：没有 GPU 也能跑，只是慢。

应用形态是 Electron 桌面端，加移动预览。稳定档覆盖 macOS 13.3+（Apple Silicon）、Windows 10/11 x64、Linux x64 与 Docker 镜像；Android 10+ 和 iOS / iPadOS 17+ 标的是 Preview，描述为「On-device, offline after model download」；Intel Mac 只能跑 UI，要连另一台机器上的 backend，Windows on ARM 是 experimental。对外接口给了 Local API、MCP、可复用 recipes 和 watch folders，还能用 npx skills add debpalash/VoiceStudio 装两个 agent skill 给编码助手用。换句话说，它同时是一个桌面应用和一套可被 agent 调用的本机语音服务。

关键的一句在 docs/languages.md 里：「This catalog describes the OmniVoice model. Other engines have their own language sets.」——646 这个目录描述的是默认引擎 OmniVoice，不是整个应用的通用能力。文档还写明，现在选到某个引擎不支持的语言会直接停止合成，并报出引擎名和可选语言，而不是偷偷用别的语言顶上。先把归属搞清楚，再看数字才有意义。

03 · 关键细节与数据

646 条一条不少，中位数却只有 10.18 小时

仓库里 docs/lang_id_name_map.tsv 15,672 字节，四列：language_id、language_name、iso_639_3_id、train_data_duration。逐行统计是 647 行——1 行表头加 646 条语言，和 README 的「646 languages」严丝合缝。docs/languages.md 写「VoiceStudio supports 646 languages with a total of 581k hours of training data」，把 TSV 第四列求和得 581,489.36 小时，同样对得上。这是少见的、自述数字两个都经得起反查的项目——之前几篇里，README 说的插件数、管线数、子技能数都和目录对不齐。

但分母长什么样，第一屏没讲。646 条按时长排序，中位数是 10.18 小时；不足 100 小时的有 570 种，占 88.2%；不足 10 小时的 265 种，不足 1 小时的 11 种；反过来，能上 10,000 小时的只有 10 种。头部是 English 206,061.1、Chinese 111,343.3、Japanese 36,914.4、Spanish 27,559.74、French 23,675.32、German 21,927.13；尾部是 Macedo-Romanian 0.02、Haitian 0.04、Ayacucho Quechua 与一种 Nahuatl 各 0.05。0.02 小时是 1.2 分钟语料，它和英语的二十万小时共享同一个「支持」标签。

把前两名加起来：English + Chinese = 317,404.4 小时，占总时长 54.6%；英语一门就占 35.4%。docs/languages.md 没有给出 WER、MOS 或任何质量分层，也没有 Tier 1 / 2 这类档位，只逐行列出时长；它还写明葡萄牙语巴西 / 欧洲两个变体共用同一个 pt 模型，Uyghur 的支持是条件式的（Whisper 不能转录它，因此不作为配音源语言），RTL 文字靠 dir="auto" 处理。「646」是目录条目数，不是 646 份等质的能力。

另外两处顺手核了。README 说 Model Manager 里有「dozens of other engines」，docs/engines/ 下确有 32 个 .md；但其中 README.md、disk-usage.md 不是引擎，cosyvoice / cosyvoice-gguf、omnivoice 的三份文档、以及 faster-whisper、whisper-cpp、whisperx、pytorch-whisper、mlx-whisper 等属同族变体——按文档数说「几十」成立，按独立引擎数要打折。最新版是 v0.5.7，2026 年 10 月 26 日发布，31 个发布资产：桌面包从 2.1 亿到 2.9 亿字节不等（win-x64.exe 222,263,756 字节、mac-arm64.dmg 280,523,075 字节），Android APK 135,770,866 字节，另含 5 份 Electron 更新清单。根目录 55 项、docs 106 项、CHANGELOG.md 589,613 字节、uv.lock 1,779,232 字节，这是个工程化仓库而不是演示原型。

04 · 怎么用

先查那门语言的时长，再决定下不下模型

安装路径按平台分得很细：macOS 用 brew tap debpalash/tap → brew trust --cask debpalash/tap/voicestudio → brew install --cask debpalash/tap/voicestudio；macOS / Linux 一键脚本 curl -fsSL https://voicestudio.sh/install | sh；Windows 是 irm https://voicestudio.sh/install.ps1 | iex；Linux 另有 yay -S voicestudio-bin、sudo apt install ./VoiceStudio-*-linux-x64.deb、sudo snap install voicestudio（记得 sudo snap connect voicestudio:audio-record）、AppImage 与 Nix；源码是 git clone 后 bun run dev。脚本还支持 --version X.Y.Z、--main、--uninstall 三个开关。README 特别注明 0.5.3 及更旧的 Tauri 版要单独装新应用，属于迁移而非覆盖升级。

第一次打开，README 给的最短路径是：进 Voice cloning，挑一个声音或给一段干净参考录音，输入文字，生成；下载任何模型前应用会先询问。要自动化就走 Local API 或 MCP，也可以用 npx skills add debpalash/VoiceStudio 把 voicestudio / voicestudio-maintainer 两个 skill 交给编码助手。Docker 路线要额外设一个本机密钥：export OMNIVOICE_API_KEY="$(openssl rand -hex 32)"，然后 docker run -d --name omnivoice -p 127.0.0.1:3900:3900 ghcr.io/debpalash/voicestudio:stable，浏览器开 http://localhost:3900。这个 API key 是自己签给本机服务用的，不是云账户凭据，别和「needs no account」混为一谈。

授权要单独算账。AGPL-3.0 覆盖应用本身且允许商用，但 README 写明「Model weights, voices and generated output have their own licences」，Model Manager 会逐个显示；Pro 是闭源构建、需要账户、单用户最多 3 台设备、7 天退款，卖的是商业许可；Cloud 是托管 API，标注 coming soon，尚未上线。声音克隆那句 Clone a voice only with its owner's permission. 把合规责任明确留给了使用者。「免费、无需账户、无需付费云」在桌面单机这条路径上成立，不等于整个产品没有商业层。

所以装之前有一件比选安装方式更该做的事：打开 docs/lang_id_name_map.tsv，搜你要的语言，看 train_data_duration 那一列。做中英，111,343.3 与 206,061.1 小时摆在那儿，值得把模型下下来；做一门排在表尾、只有几小时语料的语言，先把期望调到「能出声」而不是「能商用」，或者换一个专做该语种的引擎——文档说得很清楚，选到不支持的语言会直接停，不会降级。这一步花两分钟，比装完 200 多 MB 再发现不对便宜。

05 · 冷思考

数字没撒谎，口径替它说了话

先质疑那个最响的数字。646 条、581k 小时，逐行都对得上，仓库没虚报；但 README 把它放在第一屏和 description，docs/languages.md 才补上「这份目录只描述 OmniVoice 模型，其他引擎各有自己的语言集」，而且全文没有 WER、MOS 或质量分层。把 1.2 分钟语料的语言和二十万小时的英语并成一个「支持」，是市场口径，不是工程口径。十万星里有多少是被「646」吸引来的，仓库不会告诉你，但把中位数 10.18 小时写进第一屏显然不利于传播。

再质疑热度与完成度的错位。105,071 星配 355 个订阅者、106 个未关闭 issue，版本还是 0.5.7；Android / iOS 是 Preview，Intel Mac 是 Limited（UI 跑本机、后端要外挂），Windows on ARM 是 experimental，Cloud 还没上线。同时根目录 55 项、docs 106 项、CHANGELOG 589,613 字节、uv.lock 1.78 MB、31 个发布资产覆盖五套桌面架构加两端移动包——维护面已经铺得比版本号快，星标涨得越猛，这条缝越容易被人忽略。

第三处是硬件与合规这两笔隐性成本。CPU 能跑但 README 自己写「just slower」，CUDA / ROCm / Vulkan / Metal 四条加速路径分别卡在不同平台上；桌面包 200 MB 起步，模型还要另下。AGPL 只覆盖应用，模型权重、声音与生成输出各有许可证，做商业配音得逐个核；声音克隆的授权责任文档一句话推给了用户。「本地」省掉的是调用费和上传，没省掉显存、磁盘和合规判断。

所以判断不该落在 10 万星上，也不该落在 646 上。如果你只做中英，或者就是不想把音频交给第三方，它给了一条能完全离线、无账户、AGPL 授权的完整路径，桌面端成熟度也够试；如果冲着小语种去，先读那张 TSV 的第四列，再决定要不要下载模型——真正决定结果的是你要用的那一两门语言有多少小时，不是目录有多少行。一个把数字写得这么经得起查的仓库，值得用同样的方式去读它。
