4.7万星、74版：12G跑125B，仓库里查不到

47,392 星的 Strata 让消费显卡本地跑 Qwen3.8-Flash-Next。抖音推到「12G 跑 125B、96t/s」，但 README、模型文档与社区基准里，这两个数字一次都没出现。挪动的门槛是从显存到内存。

01 这件事

它是一个把 MoE 大模型摊到整台电脑上的本地推理引擎；4.7 万星属于「消费显卡跑大模型」这个承诺，不属于短视频里那个速度数字。

11-14 入池时是 43,916 星，11-16 复核 44,762 星，今天 47,392 星。它来自 60 天新库探测，从未上周榜、月榜，也没有可核对的本周增速。

抖音口播把它讲成「12G 显卡畅跑 125B 体量 Qwen3.8 Flash Next、速度 96t/s」。我按这三个数字回查仓库：12G 只在特定条件下成立，另两个在 README、模型文档与社区基准表里一次都没出现。

02 核心机制

省显存不是靠压缩权重，是把一个模型拆到显卡、内存、SSD 三层，让 CPU 和 GPU 同时干活。

HOW_IT_WORKS.md 写得很直白：Qwen3.8-Flash-Next 有 24,576 个专家，每写一个词只用到其中 10 个。既然大多数专家这一轮用不上，就不必全压在显卡里。

  • 显卡：注意力层、路由、共享专家与最热的数千个专家；每多 1 GB 显存约多放 700 个专家
  • 内存：固定放全部 24,576 个专家，CPU 用 AVX-512/AVX2 就地算显卡没缓存的那部分
  • SSD：放 28.8 GB 的 n-gram 查找表，每个词只读几行

另一层加速叫「先猜再验」：模型自带的 MTP 层一次起草最多 3 个词，再一遍扫过 48 层全部校验，平均每遍收下 2.4–3.2 个词，文档给的提速是 1.6–1.8 倍。重复上下文的代码改动另走 prompt lookup，最多起草 5 个词。

README 底部留了 #how-fast-is-it 和 #how-does-it-work 两个锚点，正文却只把读者引向社区基准与协议文档。仓库把速度问题留给用户自己填，短视频替它填了。

03 关键细节与数据

真正的门槛写在内存一栏：完整模型要 37.6–54.8 GB，64 GB 内存才覆盖全部档位。

MODELS.md 的「Pick by memory」给的是权重占用（RAM 与 VRAM 合计），不是显存下限。八档四个尺寸，随精度递增：

档位权重占用档位权重占用
Q2_037.6 GBIQ3_XXS47.0 GB
IQ2_XS39.2 GBIQ3_S54.8 GB

文档另给一条判据：加载时 shard 1 的专家进内存，Q2_0 是 34 GB、IQ3_S 是 50 GB；模型要装得下，内存至少得是专家数再加约 10 GB。64 GB 内存全档能跑，48 GB 只能跑 Q2_0 和 IQ2_XS。

这里有个反直觉的约束：文档原话是「更大的显卡更快，但除了低内存模式，不会降低所需内存」。32 GB 内存配 24 GB 显卡能跑 Q2_0、IQ2_XS 和 Coder；同样 32 GB 内存配 12–16 GB 显卡就只剩 Coder。内存不够时 setup 会改从 SSD 读专家，文档直说「能用，但慢得多」。

12G 显卡能启动，但启动的是裁剪版 Coder，不是完整 Flash-Next。模型文档只给了一个 12–16 GB GPU 的例子：32 GB 内存配 12–16 GB 显卡跑 Coder；它保留了每层 512 个专家中的 256 个，约 32 GB 内存。显卡再大只会更快，不会降低所需内存，低内存模式除外。

社区基准表里没有统一跑分，只有用户自测。解码速度从 Radeon 780M 的 13.1 tok/s 到双 TITAN RTX 的 77.3 tok/s；文档明确写着协议还是草稿，早期报告「不是标准结果」。

04 怎么用

装起来很快，慢的是配内存和等模型下载：一条命令装终端，桌面端一键装，模型按显存分档选。

仓库给三条路：桌面端下 Windows 安装包、Linux AppImage 或 Mac dmg；终端一行脚本；或从源码编译。装完运行 strata launch 选模型，strata connect 看主流工具怎么接。

路径入口要点
桌面端v0.2.20 安装包三系统各一个安装包，首次启动按显卡拉引擎
终端install.sh / install.ps1装完运行 strata launch
源码SOURCE_INSTALL.md可强制 --low-ram on|off

支持面列了七类：NVIDIA RTX 20/30/40/50 系、AMD RX 7000/9000 与 AI PRO、RX 6800/6900（实验）、Intel Arc（Linux）、Apple Silicon M1 起、Strix Halo、DGX Spark。README 同时列出 Tencent Hy4-Flash、Qwen3.6-35B-A3B、Inkling 2 Mini 三组可选模型。

它对外提供 OpenAI 与 Anthropic 兼容的本地 API，接 Claude Code、Codex CLI、OpenCode 等工具。SAFETY.md 承诺无遥测、无账号、服务只听 127.0.0.1，模型文件带固定 SHA-256；API key 以明文保存在仅本用户可读的文件里。

更新走另一套信任链：release 发布经 Ed25519 签名的 feed，客户端验签、查过期、防重放，再逐项校验 SHA-256。这套机制覆盖了升级，但首次 curl | sh 仍只靠 HTTPS 与仓库本身的可信度，文档把这条单列出来提醒。

05 冷思考

短视频卖的是那个 96t/s，仓库交付的是一台要 64 GB 内存的机器，两者之间隔着三层口径。

第一层是协议。BENCHMARK_PROTOCOL.md 自己标着 draft、pilot 未跑；首批实测里 36 个 4K/16K 请求有 35 个在还在推理时撞上 512 词上限，文档因此要求报告带上 Capped 列，并禁止把不同 track 合并成一个 headline 数字。

  • README 的 headline 性能表述不随社区报告更新，文档写明「加一份报告不需要改 README 的性能宣称」
  • 74 个版本里贡献者高度集中：前 100 名合计 8,080 次提交，作者本人占 7,242 次（89.6%）
  • Windows 安装包尚未代码签名；首次 curl | sh 的信任链只有 HTTPS 与发布页本身

第二层是权限。coding agent 默认 Manual，改动前逐条确认；Plan 模式只读，Bypass 则完全放行。文档提醒 Manual 并不把 agent 关在聊天目录里——你批准的那一步，能碰到你账号能碰到的一切。

第三层是成本转移。它确实把 125B 级 MoE 塞进了消费显卡，代价是 24,576 个专家常驻内存、28.8 GB 表放 SSD，以及显卡每多 1 GB 才多缓存约 700 个专家。省下的显存变成内存条和电费。

所以我的判断是：按「本地、无账号、离线可用」买它，承诺基本兑现；按「12G 畅跑满血、96t/s」买它，第一台机器就会卡在内存那一栏。它降低的是入场显卡，不是整机门槛。
