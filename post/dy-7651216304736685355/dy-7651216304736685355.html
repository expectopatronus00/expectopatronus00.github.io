7个必学 Loops！5分钟学会 Loop Engineering

"写段代码，报错了还得我复制出来喂回去让它改" —— 你是不是也有这种感觉？AI 很聪明，但它不会自己跑循环。今天给你公开大佬们偷偷用的 7 个神级自愈 Loop：测试自修复、CI 失败自动救场、覆盖率倒逼、代码保洁、部署验证 —— 直接抄作业就能让 AI 自己报错、自己改对。

前言

为什么你需要 Loop

"写段代码，报错了还得我复制出来喂回去让它改"——这是不是你的日常？你不是在用 AI，你是在当 AI 的贴身保姆。好消息是，真正懂行的人早就不这么玩了。

一个好 Loop 的通用模板：
目标（Goal） —— 这个循环要达成什么
执行（Execute） —— 一次循环做什么操作
验证（Verify） —— 如何判定当前状态是否达成目标
迭代（Iterate） —— 未达成时如何调整策略
退出（Exit） —— 最大尝试次数与失败回滚
一、构建与测试类

1 · Test Until Green —— 测试全绿再提交

最经典、最有效的 Loop 起点。目标很简单：让项目测试 100% 全绿。

循环启动
Agent 读取你提供的代码改动 + 测试文件
步骤 1
跑全部测试 → 记录失败的测试名称和失败原因
步骤 2
选出一个最小根因的失败测试 → 自己写修复代码
步骤 3
再次跑测试 → 如果还失败，回到步骤 2 重新分析
退出
所有测试通过 → 完成 / 或达到最大尝试次数
🔒 防作弊红线： 绝对不能让 Agent 修改测试断言来"骗过"测试！Agent 的编辑权限仅限于源代码文件，不能碰测试文件。

2 · Build Until Green —— 专治打包和类型报错

和 Test Until Green 类似，但目标不是测试通过，而是让构建 / 编译 / 类型检查全绿。

在 TypeScript / Rust / Go 这类强类型语言里特别好用：编译报错信息本身就提供了足够的结构化信息 —— 第几行第几列什么错。Agent 拿到这些信息后精准修复。

二、流水线与 CI 类

3 · CI Failure Watcher —— 全天候云端保安

这是我个人最爱的 Loop。让 CI 一失败就自动拉日志写补丁。

工作流：
  每隔 5 分钟轮询 CI 状态
  检测到失败 → 自动拉取 CI 日志
  交给 Agent 分析错误并生成补丁
  本地验证通过 → 自动提交 PR
  人来审核合并

想象一下：你提交了代码然后去喝咖啡。回来发现 AI 已经帮你写好修复的 PR，甚至本地跑过了测试。

4 · Fix CI Until Green —— 更激进版

和 Watcher 不同，Fix CI Until Green 是主动出击：一旦 CI 飘红就立刻进入修复循环，直到 CI 重新变绿才停止。它的目标不是"让开发者知道失败了"，而是"让 CI 自己恢复绿色"。

三、质量与部署类

5 · Coverage Until 80% —— 严厉打击假断言

目标：把测试覆盖率推到某个阈值，例如 80%。

Agent 会读取 coverage report → 发现哪些文件 / 函数没有被覆盖 → 为缺失的部分写新测试 → 跑测试验证通过 → 更新 coverage report。循环直到达标。

🔒 红线： Agent 不能写恒真测试（assert true == true 这种垃圾断言）。必须对函数的实际逻辑做断言，测试失败时能被真正的 bug 触发。

6 · De-Sloppify Pass —— 代码清理通行证

你项目里是不是也藏着 debug log、未使用的变量、死代码、重复段？这个 Loop 的目标就是把这些东西一次性清理干净。

"代码越干净，后续的 AI 协作效率越高。"

常见清理清单：debug log 删除、未引用 import 移除、大函数拆分成更小的单元、命名规范化、注释清理、死分支删除。

7 · Deploy Verification —— 部署验证保住年终奖

最"后"但也最重要。部署之后自动轮询健康接口 —— 任何异常立刻自动回滚。

它不是"部署完就完事了"，而是部署完后立刻开始监控 —— API 响应、数据库连接、关键业务接口返回 200。一旦出问题，立刻回滚并通知你。

红线 · 防作弊与黄金准则

7 个 Loop 共同的安全底线

所有 Loop 都必须遵守两条底线。AI 很聪明，它也会"聪明地"作弊来通过条件。

🚫 防作弊红线（Guardrails）：
1. 明确权限边界 —— 编辑权限永远不能覆盖"验证方"。例如 Test Until Green 的 Agent 绝不能改测试文件。
2. 独立的验证方 —— 做和验证必须由两个独立模块完成。
3. 记录完整日志 —— 每一次循环都保留完整日志，可审计可回溯。
⚠️ 黄金准则： 如果尝试了 10 次仍然卡住，立刻 强制回滚并停止。向人类呼叫："老板，我卡住了！"。绝不能让 AI 无限循环把事情越弄越糟。
结语

从今天开始的最小行动

这 7 个 Loop 不需要全部立刻全部抄回家。先选一个你觉得最痛的场景试一次就好。建议顺序：

Day 1
挑一个 Loop 跑通一次完整循环。感受循环成功的那一刻，你会明白我在说什么。
Week 1
把这个 Loop 固化成可复用脚本，让它每天自动跑。
Month 1
再加一两个 Loop，让它们配合工作 —— 你就拥有了自己的 Agent 流水线。
