# 偏好画像 · source-radar 评分基准

> 由博客现有内容分布（121 篇）与本会话的收录取舍蒸馏而成。
> 评分闸门的一切判断以本文件为准；口味变了直接改这里。

## 一、主题优先级（从高到低）

| 优先级 | 主题 | 依据 |
| --- | --- | --- |
| ★★★ | 开源 AI 项目 / GitHub 新星（agent、harness、skill、MCP 生态） | ai-code 45 篇 + 开源榜 Top 100 的持续投入 |
| ★★★ | AI 编程工作流（Claude Code / Codex / Cursor 实战） | 博客主线 |
| ★★☆ | 看盘工具与量化基建（热力图、数据接口、框架） | 「宝藏网站」专题 + quant 类目新建 |
| ★★☆ | 大厂官方动作（Anthropic / DeepSeek / Google / 腾讯云的新品与开放） | Harness²、Grok Bot、Octop 三篇的共性 |
| ★☆☆ | 效率与成长、AI 与职业 | growth 桶 6 篇 |
| ☆ | 健康生活、纯资讯日榜、社会评论 | 不是博客主线，除非极出彩 |

## 二、收录硬条件（不满足直接丢弃，不打分）

1. **有可验证实体**：能找到原始网站 / 开源仓库 / 论文 / 原视频链接，并核对过存在性
2. **来源标注完整**：作者、平台、发布时间至少有两项
3. **非重复**：与 articles.js 现有 121 篇标题相似度不撞车（含已删的「超级工程师」教训：同内容多平台搬运只留一份）

## 三、加分项

- 热度信号：抖音 10 万赞+ / GitHub 周 +3 千星+ / 创作者历史命中率（学霸妈妈讲AI、小乐数字纪元两个号已被验证）
- 「我能不能用它干成一件事」的实操空间——能跑通命令的优先于纯观点
- 官方出品或知名团队背书

## 四、减分项（命中两条以上降一档）

- 标题夸张化（「疯狂」「炸裂」「彻底变天」）——收录可以，标题必须重写
- 纯口嗨无实体（只谈趋势不给工具/仓库/方法）
- 内容与 AI / 效率 / 量化三主线无关的生活流量话题
- 营销号搬运痕迹（文案与已有文章雷同）

## 五、口吻基准

- 标题：去夸张化、点名实体（参考「一眼看清板块情绪：开源 A 股热力图 dapan.app」）
- 结构：事件是什么 → 怎么用 → 边界与冷思考
- 转载三件套：原文链接、作者、发布时间
